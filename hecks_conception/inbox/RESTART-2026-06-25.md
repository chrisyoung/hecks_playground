### THE GAP (the next task) — unified-runtime serve
Under `serve`, dispatching Capture EMITS FrameCaptured but the DiskBuffer handler never
fires. Root cause, precisely : `Runtime::record_effect_outbound` (rust/src/runtime/mod.rs
~L1431) returns EARLY unless the served runtime's domain contains the **`OutboundEvent`**
transactional-outbox aggregate (`aggregates/framework/hexagon/outbound_event.bluebook`).
The MULTI-domain serve (`src/server/multi.rs`) builds a SEPARATE runtime PER bluebook, so
the Screenshot runtime has no OutboundEvent -> nothing recorded -> the drain delivers
nothing. Co-locating the family/adapter AND OutboundEvent in the served dir did NOT help —
serve just makes them distinct domain-runtimes ("2 domains").

domains include the framework outbox (OutboundEvent) — the MCP/CLI dispatch path already
loads the full corpus into one runtime, which is why effects work there. Either make serve
merge framework aggregates into the domain runtime, or add a single-unified-runtime serve
