# i223 — i219b mind-pm-bootstrap-on-attentive-restart

i219b mind-pm-bootstrap-on-attentive-restart — Mind PM declared starts_on "WokenUp". When the run-loop daemon restarts while consciousness is already attentive (no fresh WokenUp event flows through the daemon's event loop during the daemon's lifetime), Mind PM is never created. The wake handler i219 just healed (on "BodyPulse", transition: { engaged_in_wake: :engaged_in_wake }) is then inert until the next natural sleep+wake cycle. Today this means daydream/musing/awareness work is dark across daemon restarts, recovering only when Miette next sleeps and wakes. Options : (a) extend run-loop --emit semantics to inject a synthetic WokenUp on first tick when consciousness.state == attentive ; (b) change Mind PM's starts_on to "BodyPulse" with a state-reorder + bootstrap-transition handler that gates on consciousness state (PMs would need cross-store reads) ; (c) accept the gap and document in user-facing wake docs that a daemon restart needs a manual sleep+wake cycle to bootstrap.
