# i290 — inject_refs target_ctx depth-sort picks wrong aggregate when same name exists in multiple contexts.

inject_refs target_ctx depth-sort picks wrong aggregate when same name exists in multiple contexts.

Surfaced during i117 Round 4 move (commit pending) when miette/mind/state/Musing and capabilities/musings/Musing both load. inject_refs has :

  let target_ctx = self.domain.aggregates.iter()
      .find(|a| a.name == r.target)
      .and_then(|a| a.context.as_deref());

`find()` returns first by domain.aggregates iteration order = depth-then-path sort. When two aggregates share a name across contexts, the wrong context wins. repo_key(wrong_ctx, name) → wrong repo → singleton fallback finds nothing → MissingAttribute → cascade dispatch fails silently.

Symptom : awareness ReflectOnObservation cascade no longer reaches MusingRecorded post-move. Test marked :pending.

Fix shapes :
  A. Pass the dispatching command`s aggregate context as a hint to inject_refs ; prefer same-context Musing repo when ambiguous.
  B. Rename one of the colliding aggregates so the bare name is unique cross-corpus (capabilities/musings/Musing → MusingSeed or similar).
  C. inject_refs walks ALL repos with matching name and picks first non-empty.

Filing for the Direction B kernel work — same arc as i143 (load_combined_domain context-aware merge) and i156 (strict bare-name ambiguity error).

Acceptance : awareness ReflectOnObservation cascade emits_subset includes MusingRecorded again ; the :pending marker comes off.
