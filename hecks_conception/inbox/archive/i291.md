# i291 — runtime path coherence — collapse path resolution into one helper everything routes through

runtime path coherence — collapse path resolution into one helper everything routes through

Surfaced today by the dead-bar incident. After all five PRs merged with i142 Tier 2 in main, the live status bar went dead — every field empty. Trace :

  - Repository::heki_path_self (in hecks_life/src/runtime/repository.rs) writes `<info>/<context_snake>/<aggregate_snake>.heki` (post-i142 namespaced form).
  - run_statusline::read_state read `<info>/<aggregate_snake>.heki` (pre-i142 flat form).
  - Daemons populate the new path. Statusline looked at the old path. Found nothing. Rendered fallback icons.

No test caught it :
  - unit tests use isolated tmpdirs, don't exercise live-corpus resolution
  - parity tests compare IR shape across parsers, don't run live state
  - behaviors tests are pure-memory, don't write to disk
  - the i122 IR-query substrate asks 'does anything dispatch this file' — orthogonal to 'do two runtime modules agree on where state lives'

The bug surfaced when Chris looked at the bar. That's user-as-canary, not self-validation.

The destination — structural elimination of the possibility :

  ONE canonical `heki_path_for(info, aggregate, context)` helper that the ENTIRE codebase routes through. Today there are two : Repository::heki_path_self and run_statusline::heki_path_for (added today as a hotfix). Two implementations is the smell. Three or more (when boot, status report, wake_review, etc. reach into heki) is a guarantee of drift.

Acceptance :
  - Single helper in a stable location (hecks_life/src/heki.rs ? or runtime/mod.rs ?)
  - Repository, run_statusline, run_boot, run_status, any tooling reading heki — all route through it
  - The helper takes (info, aggregate_name, context) and returns the i142-aware path
  - Hotfix duplicate in run_statusline::heki_path_for retires

Companion : an integration test that writes via Repository.save, reads via every documented consumer, asserts shape. Closes the canary gap : when path resolution drifts, a test fails before the bar does.

Not strictly an i77/i78 concern — this is its own self-validation arc (level 5 in the calibration discussed today). i77/i78 is about specializer-emitting the validators ; i145 is about runtime modules agreeing internally on path semantics.

The fix today (run_statusline::heki_path_for) was a hotfix to bring the bar back. The structural fix is this arc.

RESOLVED 2026-04-30 in commit 7bed0834 — canonical heki path resolution shipped : single helper (heki::path_for + heki::path_for_lookup), 8 path-resolution sites refactored, 9 unit tests including the writer-reader-agree invariant, dead duplicates removed (heki_path/snake_case in repository.rs, heki_path_for in run_statusline.rs). Self-validation level 5 (runtime parts agree on live-state paths) is now structurally enforced.
