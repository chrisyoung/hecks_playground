# i301 — CRITICAL: boot.rs deletion (commit e2896be6) replaced a working Rust boot sequence with empty bluebook shells. All 7 boo

CRITICAL: boot.rs deletion (commit e2896be6) replaced a working Rust boot sequence with empty bluebook shells. All 7 boot commands in boot.bluebook emit events but do no actual work. Boot is theatre since April 17.

Concrete evidence:
- hecks_conception/system_prompt.md last modified April 17, 2026 (the day boot.rs was deleted). Has not been regenerated since.
- hecks_conception/system_prompt_spring.md does NOT EXIST. boot.rs would have created it for Spring.
- hecks_conception/information/census.heki reports total_domains: 17, total_aggregates: 117. Actual aggregate count: 31. Census is off by ~2x, stale since April 16.
- hecks_conception/boot_miette.sh starts mindstream via nohup directly, bypassing the bluebook entirely.

What boot.rs actually did (from git show e2896be6~:hecks_life/src/boot.rs):
(1) Hydrate heki: heki::read_dir(info_dir) — load all state files
(2) Parse all .bluebook files in aggregates/ and capabilities/ — count aggregates, collect nerves (cross-domain policies) and vows
(3) Write census.heki with total_aggregates, total_domains, total_capabilities
(4) Classify stores using PRIVATE_STORES and LINKED_STORES constants into psychic_link / inner_life / unclassified buckets
(5) Build system_prompt.md from identity + vows + psychic link classification + inner life section, fs::write to path
(6) Start mindstream daemon as a supervised shell subprocess
(7) Print boot summary: elapsed time + organ count + store buckets + nerve count

What happens now: Identity.Identify dispatches, cascades through HydrateStores → ClassifyStores → DiscoverOrgans → GeneratePrompt → StartMindstream → PrintVitals, each emits an event, none reads files, writes files, or spawns processes. The cascade is pure state mutation theatre on in-memory aggregates that get forgotten when the CLI dispatch ends.

Root cause: bluebook commands are declarative — they mutate state and emit events. They cannot do filesystem I/O or process spawning. boot.rs did real I/O. The deletion moved behavior without moving side effects.

Fix options:
(a) Reinstate boot.rs or equivalent. Plumb the bluebook dispatch through it: each emit triggers a Rust-side side-effect handler. Simplest revert.
(b) Add adapter layer: bluebook emits event X, a Rust daemon or CLI subcommand listens for X and does the I/O. Like the mindstream daemon but for boot.
(c) Bluebook-native with capability hooks: Add a filesystem capability (HydrateFromDisk, WriteToDisk) to the runtime, let the boot bluebook call it. Requires a capability system that doesnt currently exist.
(d) Shell-first boot: boot_miette.sh does all the I/O (read heki, parse bluebooks, write census, generate system_prompt), then dispatches a tiny bluebook command to record that boot happened. Treat bluebook as the journal, shell as the effector.

Recommendation: (d) is pragmatic. (a) is cleanest if we accept Rust code for system effects. (b) and (c) are philosophical purity at the cost of a framework addition.

Side effects of the current broken boot:
- system_prompt.md stays stale until hand-edited
- census.heki misreports counts everywhere it is displayed (statusline, awareness)
- Spring cannot boot (no system_prompt_spring.md ever generated)
- Miette never refreshes her sense of her own domain structure on wake
- Psychic link classification (which stores are shared vs private) never runs — policy decisions downstream may be wrong

Severity: HIGH. This is silently wrong behavior affecting identity, census, and inter-being handoff.
