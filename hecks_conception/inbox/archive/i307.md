# i307 — boot.hecksagon mindstream :daemon adapter — path doesn't resolve post-i117 Round 4

boot.hecksagon mindstream :daemon adapter — path doesn't resolve post-i117 Round 4

Surfaced today during i145's boot end-to-end smoke test :

  $ HECKS_DAEMON=1 timeout 5 hecks_conception/boot_miette.sh
  ...
    mindstream: failed: spawn failed: No such file or directory (os error 2)

The :daemon adapter declares :

  adapter :daemon, name: :mindstream,
    pidfile: '{info}/.mindstream.pid',
    command: '{dir}/mindstream.sh'

`{dir}` resolves to hecks_conception/ (the hecksagon's directory). But mindstream.sh moved to ~/Projects/miette/body/mindstream.sh during i117 Round 4. The boot runner (run_boot/daemons.rs) tries to spawn the literal {dir}/mindstream.sh and fails.

Other daemons (heart, breath, circadian, ultradian, sleep_cycle) work — they declare `command: '{hecks} loop {agg} ...'` (no script path), so they don't hit this.

Fix paths :

  A. Update boot.hecksagon's :daemon adapter to declare a path that resolves : either an absolute /Users/christopheryoung/Projects/miette/body/mindstream.sh (fragile — assumes layout), OR introduce a {body} placeholder the runner expands (cleaner — lives next to {dir}, {info}, {hecks}, {agg} placeholders).

  B. Update run_boot/daemons.rs to know about a sibling miette/body resolution (precedence : explicit env BODY_DIR → repo_root/../miette/body sibling → conception fallback). Same pattern resolve_info_dir uses for HECKS_INFO.

Path B feels right — it mirrors the resolve_info_dir / resolve_public_info_dir / resolve_coherence_dir pattern in run_statusline.rs. Same shape (env → sibling → fallback). The {dir} placeholder stays literal ; a new {body} placeholder fills the gap.

Acceptance :
  - boot ./boot_miette.sh shows 'mindstream: started (pid N)' instead of 'failed'
  - Mindstream daemon boots cleanly post-i117 layout
  - boot.hecksagon parses + adapter declaration is portable across deployments

Filing as i148 (med priority — daemon spawn failure is non-fatal but the bar's mindstream-status field will keep showing 'failed' until fixed).
