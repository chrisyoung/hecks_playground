# i317 — Aggregate name collisions across the corpus surfaced during i112 Round 2c splits. Multiple bluebooks declare aggregates

Aggregate name collisions across the corpus surfaced during i112 Round 2c splits. Multiple bluebooks declare aggregates with the SAME name, and the runtime's organ-wins dedupe (PR #491) silently drops the loser : (1) Memory aggregate declared in both miette/memory.bluebook (Persona memory) and the now-split library/store + mind/encoding/recall/forgetting + body/sleep/consolidation cluster — agents flagged this in PR #506 ; (2) Encoding aggregate — collides between miette.bluebook's persona-encoding and memory.bluebook's mind-encoding ; (3) Consolidation — collides between mindstream.bluebook (signal consolidation, now SignalConsolidation in PR #507) and memory.bluebook (sleep-driven memory consolidation) ; (4) SleepCycle — legacy in sleep.bluebook (StartCycle/AdvanceStage) vs proper in body/sleep/sleep_cycle.bluebook (NREM/REM) — the depth-0 vs depth-2 ordering meant the legacy was winning until the i112 Round 2c sleep split flipped it (positive side effect noted in PR #508). The runtime's dedupe is structurally correct ; the bug is at the bluebook level — two aggregates should not share a name. Proposed: (a) rename each colliding aggregate to its concern (PersonaMemory vs MemoryStore, etc.) ; OR (b) consolidate truly-overlapping aggregates and delete the duplicate. Either approach makes the dispatch resolution explicit instead of hidden behind organ-wins.
