# i332 — Bug: fixture-parser string-escape divergence between Ruby and Rust.

Bug: fixture-parser string-escape divergence between Ruby and Rust.

Reproduced on PR #249 (antibody DSL drafts). When a .fixtures file contains double-quoted strings with backslash escapes, Ruby's DSL parser consumes them as Ruby escape sequences while the Rust fixture parser preserves them literally.

Concrete divergence:
  fixture "Canonical", pattern: "^\\s*\\[antibody-exempt:\\s*([^\\]]+)\\]", flags: "i"
  # Ruby output: pattern = '^ *[antibody-exempt: *([^]]+)]'        (\s → space, \[ → [, \] → ])
  # Rust output: pattern = '^\\s*\\[antibody-exempt:\\s*([^\\]]+)\\]'  (preserved)

Same pattern for \n inside strings: Ruby expands to a newline character; Rust keeps the two-char literal \n.

Impact: any fixture that needs a regex with backslash escapes, or a message with literal newlines, drifts silently between runtimes. Caught by the parity suite; currently tracked via known_drift.txt entry on antibody.fixtures.

Root cause is in the fixture parsers' string-literal tokenization:
  - Ruby loads via Kernel.load, so the fixture body IS Ruby source; "..." follows Ruby semantics.
  - Rust (hecks_life/src/fixtures_parser.rs) treats "..." as opaque bytes between quotes.

Fix options:
  (a) Rust parser grows a Ruby-compatible escape expander for \n \t \\ \" \s \[ \] etc. Likely 20-50 lines.
  (b) Ruby side intercepts via a DSL method that receives raw source and stores it without re-interpretation. Harder — Ruby already ate the escapes by the time the DSL runs.
  (c) Document as semantic gap and forbid backslashes in fixture string values. Ugly but simple.

Recommend (a). Test path: extend spec/parity/fixtures_parity_test.rb with a new synthetic fixture containing each escape sequence; Rust+Ruby outputs must match byte-for-byte.

When fixed: remove the antibody.fixtures entry from spec/parity/known_drift.txt.
