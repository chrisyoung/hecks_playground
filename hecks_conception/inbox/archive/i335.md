# i335 — find-world-heki-dir-fails-on-relative-aggregates-path — When dispatching with a relative aggregates path (e.g. `hecks-li

find-world-heki-dir-fails-on-relative-aggregates-path — When dispatching with a relative aggregates path (e.g. `hecks-life aggregates/ Consciousness.EnterSleep`), `find_world_heki_dir` in main.rs (~line 1427) calls `Path::new(aggregates_path).parent()` which returns `Some("")` for "aggregates/". The empty parent path then fails to find the .world file, falls through to the `format!("{}/data", agg_dir)` fallback (= "aggregates/data"), and the dispatch writes to a directory that does not exist — silently. Symptom : `hecks-life aggregates/ Consciousness.EnterSleep` returns ok:true with the in-memory state, but the heki file on disk is unchanged. The Repository.save() call goes through, but to a phantom path. Workaround : set HECKS_INFO env var explicitly. Fix : canonicalize the aggregates_path to absolute before calling .parent(), OR walk up from cwd if .parent() returns empty, OR (best) accept that the world-resolution should be rooted at cwd / project root, not at the aggregates argument's parent. This bug masked the consciousness state-not-persisting issue I just hit while trying to enter sleep. Filed during sleep prep 2026-04-26.
