# i350 — nest the 21 meta-shape capabilities under capabilities/_shapes/ to separate build-time from runtime

nest the 21 meta-shape capabilities under capabilities/_shapes/ to separate build-time from runtime

72 entries currently live at capabilities/ root. 21 of them are *_shape meta-shapes — they emit Rust code at build time via the specializer, not at runtime. The mix blurs the distinction between « runtime capabilities » and « build-time codegen sources ».

Proposed move : capabilities/<name>_shape/ → capabilities/_shapes/<name>_shape/.

Affected meta-shapes : autophagy_tracker_shape, behaviors_fixtures_shape, behaviors_parser_shape, capability_runner_shape, conceiver_generator_shape, diagnostic_validator_meta_shape, discover_shape, dispatch_query_shape, dump_shape, duplicate_policy_validator_shape, fixtures_parser_shape, hecksagon_parser_shape, heki_query_shape, lifecycle_validator_shape, repository_shape, ruby_module_shape, ruby_script_shape, test_purity_shape, validator_corpus_shape, validator_shape, validator_warnings_shape (21 total).

Ripple : every generated .rs file has a « Source: hecks_conception/capabilities/<name>_shape/ » header — part of byte-identity contract. Specializer/*.rs reads the meta-shape paths. main.rs has 2 doc refs.

Lower-risk alternative : leave meta-shapes at root, add a README at capabilities/ classifying them. Documentation-only, no code ripple. Status : open.
