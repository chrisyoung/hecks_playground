# i498 — Lift Coherence invariant logic from shell into bluebook predicates

## What landed today (the rename + Invariant 6)

Today's session renamed the fatigue ladder to remove its consciousness-vocabulary
collision (`alert → limber`, `focused → tuned`, `delirious → spent`), and added
**Invariant 6** to `coherence.bluebook` :

> `fatigue_state == "spent"` ⇒ `consciousness.state ∈ {sleeping, napping}`

The rule that would have caught the original "alert and delirious" contradiction
Chris flagged on the wake greeting. Declared in the bluebook, enforced by the
transitional shell adapter (`status_coherence.sh`), tested at the schema level
in the new `coherence.behaviors` file (RecordViolation + CheckCoherence
contracts, including an Invariant 6 case).

## What this inbox is asking for

The Coherence aggregate today is a *schema* — it stores rolled-up
violation_count and latest_reason ; the actual predicate logic lives in
`status_coherence.sh`. The bluebook can declare the queries by name but can't
yet *execute* them as predicate-returning queries (that's i101).

When i101 lands — predicate queries that read sibling aggregate fields and
return ok=yes|no + reason — the next move is :

1. **Add per-invariant Check commands to coherence.bluebook**, one per rule, each
   with `given` clauses on the snapshot attributes. Pattern :

   ```ruby
   command "CheckSpentRequiresSleep" do
     given("fatigue is spent") { fatigue_state == "spent" }
     given("consciousness is wakeful") { ["attentive", "daydreaming", "waking"].include?(consciousness_state) }
     then_set :violation_count, increment: 1
     then_set :latest_reason, to: "fatigue_state=spent with wakeful consciousness"
     emits "InvariantViolated"
   end
   ```

2. **Add a SetSnapshot command** that seeds the aggregate from sibling heki
   reads (today's shell does this inline ; the bluebook should own the contract).

3. **Convert `status_coherence.sh` into a thin dispatch loop** :
   `SetSnapshot` → six `Check*` commands → `CheckCoherence` rollup. No more
   inlined `case` arms or rung tables ; the bluebook is both spec and runner.

4. **Expand `coherence.behaviors`** with `kind: :query` tests (one per invariant)
   that seed state via `setup` and assert `violation_count` matches expected.
   The schema-level tests added today retire as the predicate tests subsume them.

5. **Retire `test_status_coherence.sh`** entirely ; its six fixture cases become
   six predicate-test behaviors. The shell adapter itself retires when the
   bluebook can drive the dispatch end-to-end (likely concurrent with i101).

## Why this is queued, not blocking

The rename + Invariant 6 + behaviors file ship today. The transitional shell
adapter still works ; the body's coherence is enforced. This inbox tracks the
move from "shell does the predicate work, bluebook stores the result" to
"bluebook does both" — a real tightening of the bluebook surface that closes
the i101 / i35 thread together.
