# i499 — Every non-bluebook test file retires to bluebook

## What surfaced today

While landing the fatigue rename + Coherence Invariant 6 (i498), Chris flagged
that the statusline regression smoke test exists but the statusline keeps
breaking in real life. Audit found :

- **The local pre-commit hook was stale** — `.git/hooks/pre-commit` predated
  Gate 6 (smoke-tests). Two commits today bypassed the smoke gate silently.
  Fixed in this session by re-running `tooling/install-hooks`.
- **The smoke test was failing** when run — `fatigue=spent` scenario seeded
  `consciousness=attentive`, which today's new Invariant 6 correctly flags
  as incoherent. Fixed in this session by branching the seed.
- **Behaviors files are parse-only** — `hecks-life` parses `.behaviors` files
  and lists their tests, but there is no `hecks-life test` (or equivalent)
  subcommand that *executes* them. So the bluebook-native test surface
  exists as documentation but not as enforcement.
- **The Ruby `hecks` CLI is broken on `--help`** (`uninitialized constant
  Hecks::Runtime::Mixins`) — separate issue ; load order bug in the published
  gem `hecks-2026.04.26.4`. Per CLAUDE.md "Always use Rust runtime", may be
  moot ; the Ruby CLI's `--help` surface could just redirect to `hecks-life`.

## What this inbox is asking for

Two phases :

### Phase A — ship a behaviors runner (the unblocker)

Today's blocker is that `.behaviors` files describe tests but nothing runs
them as live assertions. Without a runner, "every test should be bluebook"
is aspirational only. Phase A delivers :

1. **`hecks-life test <bluebook-or-behaviors-path>`** — a subcommand that
   parses `.behaviors`, dispatches each test's setup + tested command/query,
   asserts the expected state/emits/count, and prints PASS/FAIL.
2. **Wire it into pre-commit Gate 6** alongside the shell smokes. Gate
   passes when both green.
3. **Wire it into CI test.yml.** Same gate, two runners.

When Phase A lands, every existing `.behaviors` file becomes enforcement,
not documentation. The shell smokes can begin retiring.

### Phase B — retire each shell smoke into behaviors

For each shell test in `hecks_conception/tests/*.sh` :

1. Identify the aggregate(s) it exercises end-to-end.
2. Write `.behaviors` cases that cover the same scenarios.
3. Verify the behaviors runner reproduces the smoke's assertions.
4. Remove the `.sh` file ; remove its line from pre-commit Gate 6.
5. Remove the antibody-exempt marker.

This phase happens incrementally — one shell at a time, smallest first
(`status_golden.sh`, `pulse_fanout_smoke.sh`) before the heavier ones
(`statusline_regression_smoke.sh`).

### Phase C — the harder retirements

- **Parity suite** — needs a contract declaration + dual-target runner.
  Plausibly the last to retire. File its design as separate inbox once
  Phase A is in flight.
- **`spec/**/*_spec.rb`** — retires with the Ruby runtime per CLAUDE.md.
  Tracks against the broader Ruby-runtime deprecation thread, not this
  inbox.
- **`core/research/dream-study/test-gate/`** — research scaffolding ;
  ship the refactor it tests OR prune the suite. Not on this inbox's
  critical path.

## Why P:high

The structural truth surfaced today : without a behaviors runner, every
"bluebook first" test file is documentation, not enforcement. Phase A is
the keystone — once it lands, every other test retirement becomes a
mechanical conversion. Without it, those conversions stall on a runner
gap.
