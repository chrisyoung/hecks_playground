# i521 — heki.bluebook : conceive the HEKI file format

**Filed:** 2026-05-09
**In service of:** dream-work — close the bluebook-first gap exposed by the warning sweep on `rust/src/heki.rs` (957 LoC).

## Gap

`rust/src/heki.rs` is kernel-floor : the on-disk persistence format
(JSON-array-of-records with optional companion `.heki.meta` mtime
sidecar). It implements `read`, `write`, `upsert`, `latest`,
`latest_field`, `count`, `list`, plus the namespacing rules for
nested directory layouts (`information/<context>/<aggregate>.heki`).

Today this is described in :

  - `runtime/storage/storage.bluebook` — covers `Repository`
    (in-memory aggregate-state cache) and `RefreshIfStale`
    (the i517 mtime-aware refresh policy).
  - **Nothing else.** The on-disk file format itself, the upsert
    semantics, the namespacing rules, the meta-sidecar contract —
    none of it has a bluebook.

This means : if a junior reads `storage.bluebook`, they learn about
the in-memory layer but not the file the layer reads from.

## Proposal

Conceive `runtime/storage/heki.bluebook` (or extend storage.bluebook
with a Heki aggregate ; choose by Trikaya). The bluebook should name :

  - **HekiFile** (aggregate, lifecycle: read|written|empty)
    - path : String
    - record_count : Integer
    - last_write_at : Time
  - **HekiRecord** (value object inside HekiFile)
    - id : String (string, not UUID — singletons use semantic ids
      like "dream", "consciousness")
    - payload : Map (the attribute hash)
    - updated_at : Time
  - Commands :
    - **Read**(path) — load all records
    - **Upsert**(path, id, attrs, reason) — insert-or-update by id
    - **Latest**(path) — most recent by updated_at
    - **LatestField**(path, field) — convenience accessor
    - **Count**(path)
    - **List**(path)

The CLI surface (`hecks-life heki ...`) is already a projection of
this — the bluebook makes the projection explicit.

## Out of scope

Refactoring `rust/src/heki.rs` itself. The bluebook is the
**specification** ; the kernel-floor Rust stays as the
implementation. Future work can specializer-regenerate it from the
bluebook (i147 wave). For now : just close the bluebook-first gap.

## Acceptance

  - `runtime/storage/heki.bluebook` exists (or storage.bluebook
    is extended with a HekiFile aggregate).
  - Parity stays 330/330 (or grows by however many additional
    aggregates the new bluebook introduces).
  - The antibody marker on `heki.rs` is updated to reference this
    bluebook as its specification.
