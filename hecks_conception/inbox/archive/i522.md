# i522 — discovery.bluebook : conceive boot discovery

**Filed:** 2026-05-09
**In service of:** dream-work — close the bluebook-first gap exposed by the warning sweep on `rust/src/run_boot/discover.rs` (152 LoC).

## Gap

`rust/src/run_boot/discover.rs` is kernel-floor : it walks the
filesystem under `aggregates/` to find `.bluebook`, `.hecksagon`,
`.fixtures`, `.behaviors`, and `.world` files, then groups them
by aggregate path so the boot pipeline can hand each cluster to
the parser.

Today this is **partially** described in :

  - `runtime/boot/boot.hecksagon` — declares the boot phases,
    including a `discover` phase that the Rust runner implements.

But the discovery rules themselves — what extensions are recognized,
what naming patterns trigger which parser, how `<dir>.bluebook` and
`<dir>/<dir>.bluebook` co-exist (the i118 R5 nested layout) — are
encoded in code, not in a bluebook.

## Proposal

Conceive `runtime/boot/discovery.bluebook`. The bluebook should
name :

  - **Discovery** (aggregate, lifecycle: idle|scanning|complete)
    - root : String (the aggregates root)
    - found_count : Integer
  - **DiscoveredFile** (value object)
    - path : String
    - extension : String (one of bluebook, hecksagon, fixtures,
      behaviors, world)
    - aggregate_path : String (the parent directory grouping)
  - Commands :
    - **Scan**(root) → emits FileDiscovered per match
    - **Group**(root) → emits AggregateClusterFound per parent dir
  - **Recognized extensions** : explicit list (bluebook,
    hecksagon, fixtures, behaviors, world). The closed vocabulary
    that the antibody hook also enforces.

## Why this matters

The vocabulary of "what is a Hecks source file" lives in three
places today : the antibody hook, this discover.rs, and the
parser dispatch. A bluebook makes them all projections of one
truth. Adding a new source extension (e.g. a hypothetical
`.recipe`) becomes a single bluebook edit, not a hunt.

## Acceptance

  - `runtime/boot/discovery.bluebook` exists.
  - Parity stays 330+ (no regressions).
  - The recognized-extensions list is the same as the antibody
    hook's vocabulary (cross-referenced).
