# i531 — Rename `enforcer` → `macrophage`

> **i553 extends this card** with the three-gate role + CI parity.
> i531 names *what to call the cell* ; i553 names *where it runs.*
> The rename + the expanded role ship together.

## Why

`discipline/` carries two complementary gates that both enforce
"bluebook first," but their names don't reflect that they're parts
of one system :

- **Antibody** — slow gate, fires at commit time, checks the staged
  files against bluebook-source rules, demands `[antibody-exempt:
  …]` markers for non-bluebook additions.
- **Enforcer** — fast gate, fires at write time (Claude Code's
  PostToolUse:Bash / PostToolUse:Write hook), surfaces a complaint
  the moment a non-bluebook file is touched.

Two enforcement concepts, two different timings, but only one of
them has an immune-system metaphor. The names overlap unhelpfully
("enforcer" sounds like "antibody enforces too").

## The rename — what + why

`enforcer` → `macrophage`.

Macrophage in immunology : the *"big eater"* — the patrol cell that
recognizes foreign patterns at first contact, engulfs them, then
presents the antigen fragments to the rest of the immune system.
Macrophages are the **innate** sentinels ; antibodies are the
**adaptive** response.

Mapped onto the codebase :

| Concept | Cell | Trigger | Layer |
|---|---|---|---|
| `discipline/macrophage/` (new name) | Macrophage | PostToolUse hook on file write | Innate — fast, pattern-based |
| `discipline/antibody/` (unchanged) | Antibody | Pre-commit gate | Adaptive — slow, specific |

The narrative arc reads cleanly :

> Macrophage detects the non-bluebook write → presents the gap →
> Antibody binds at commit time.

## Scope of the rename

This is a normal sweep, not an architectural shift. Files that
mention `enforcer` need to flip to `macrophage` :

- `discipline/enforcer/` directory → `discipline/macrophage/`
- `enforcer.bluebook` / `enforcer.behaviors` / `enforcer.hecksagon` →
  same with macrophage stem
- The aggregate name `Enforcer` → `Macrophage`
- Commands like `Enforcer.RecordRustEdit`, `Enforcer.Complain` →
  `Macrophage.RecordRustEdit`, `Macrophage.Complain`
- Rust runtime invocations (`storehouse enforce-edit` subcommand,
  `run_enforce_edit` function in main.rs) → name follow-on
  question : do we rename the subcommand to `macrophage` (verb
  form) or keep `enforce-edit` ?
- The Claude Code hook in `~/.claude/settings.json` —
  `PostToolUse:Bash` and `PostToolUse:Write` commands invoke the
  binary with `enforce-edit` ; update accordingly.
- Doc text in `CLAUDE.md`, hook scripts, memory files.
- Inbox cards referencing `enforcer` — historical, leave alone.

## Decisions to confirm

1. **Subcommand name** — `storehouse macrophage` is the natural
   verb form once we re-cast "enforce" as "engulf bad writes."
   Keep `enforce-edit` only as a transitional alias.

2. **Event-payload names** — `Macrophage.RecordRustEdit` is the
   aggregate-method form ; the emitted event probably stays
   `RustEditRecorded` (event-name follows the past-tense pattern
   from existing aggregates).

3. **Sibling cells** — Macrophage is one of several immune-system
   cells we could conceive (B cell, T helper, NK, dendritic). Are
   any of them on the immediate roadmap, or is Macrophage the only
   new immune-system aggregate we need ? Filed as later question.

## Sequencing

commit-time, CI) ship together — they're two halves of the same
move. i553 carries the CI parity story ; this card carries the
