# i543 — Scope lifecycle-rules list per-aggregate

## Why this card exists

Before the aggregate grid renders, the walking-skeleton page emits a
single `<ul>` titled "Rules" containing every lifecycle invariant
from every aggregate, in load order, unscoped :

> Complete requires active
> Complete requires one_time
> Cancel requires active
> Request Background Check requires submitted
> Approve requires background_check_pending
> Mark Active requires approved
> Reprice requires active
> Retire requires active
> Publish requires draft
> Start requires published
> …(20+ more)

It reads as nonsense. Which "Complete" belongs to which aggregate?
Which lifecycle does "Mark Grace Elapsed" belong to?

## What changes

Move each rule into the aggregate card it belongs to. The card's
existing layout already has space for a "Rules" subsection (the
walking-skeleton template just doesn't fill it). The IR already
attributes each rule to its parent aggregate via the command's
lifecycle declaration ; the renderer just isn't grouping.

Optional follow-up : hide the whole rules block behind a "Show
invariants" toggle so the default render is just the dispatch form.
