# i620 — statusline_regression_smoke.sh failing on origin/main

Five separate sidequests today (C, F, Q, T, V) hit pre-existing failures in
`hecks_conception/tests/statusline_regression_smoke.sh` and bypassed with
`TESTS_SKIP=1` to commit. That pattern compounding five times in one day means
the gate has effectively stopped working.

---

statusline shape: heartbeat + mood icon + mood word + fatigue icon + fatigue

simplified to surface only two signals: `❤️ <beats>` and `✉️ <init>:<count>`.

### The working-tree replacement (branch `sq/statusline-simplification-v2`)

Sidequest E (still staged, not merged) replaced the smoke test with a
post-simplification version that asserts the new shape: heartbeat-only + multi-
inbox. That version has one remaining failure:

```
[multi-inbox] ❤️ 999  •  ✉️ gl:2 pi:1 bb:3
  ✗ [multi-inbox] expected 'pc:1' (closed card filtered) — got: ❤️ 999  •  ✉️ gl:2 pi:1 bb:3
statusline_regression_smoke: FAIL
```

The test asserts `pc:1` (pigeoncoop), but `rust/src/run_statusline/inbox.rs`
has always used `pi` as the pigeoncoop initializer:

```rust
pub(super) const INBOXES: &[(&str, &str)] = &[
    ("gl", "Projects/hecks/hecks_conception/inbox"),
    ("pi", "Projects/pigeoncoop/inbox"),   // <-- "pi", not "pc"
    ...
];
```

The `pc:` string in the test assertion is a typo introduced when E wrote the
replacement. The inbox renders correctly as `pi:1`; only the assertion is wrong.

## 2. How long this has been broken

The last commit to touch `tests/statusline_regression_smoke.sh` is:

```
56ac3c83  2026-05-12  fix(tests) : i565 + i577 — smoke worktree-blindness + FQN-form regression
```

That commit carried the old mood/fatigue test shape. The Rust runner
simplification (stripping mood/fatigue from the statusline output) happened in
subsequent work and was never followed by a committed update to the smoke test.
The test has been red on `origin/main` since at least the simplification landed —
every commit that merged after that point silently inherited a broken gate.

The `pc:` typo in E's replacement is newer — it exists only on
`sq/statusline-simplification-v2` (uncommitted to main), not on `origin/main`.

---

## 3. Why this matters

`statusline_regression_smoke.sh` exists to catch exactly this class of drift:
a Rust refactor that silently changes what the statusline emits. When the test
is red on `main` and the pre-commit hook allows `TESTS_SKIP=1`, agents bypass
rather than fix. Five bypasses in one day means the gate is gone. Any future
statusline change — including E's still-staged rewrite — loses the early-warning
signal entirely.

The TESTS_SKIP bypass is documented in settings.json as an escape hatch for
emergency unrelated commits, not as a permanent override for a broken gate. Using
it five times against the same known failure erodes both the tool and the habit.

## 4. Proposed fix shape

### Failure A: stale mood/fatigue assertions on `origin/main`

Root cause: the committed smoke test was written for an old Rust binary shape.
The Rust runner stripped mood, fatigue, breadcrumb, and fallback signals from
the output. No follow-up commit updated the test.

Remedy: replace the committed smoke test with the post-simplification version
from `sq/statusline-simplification-v2` (E's working-tree rewrite), after fixing
the `pc:` typo (see Failure B below). This is a test-only change; the Rust
runner is already correct.

### Failure B: `pc:` vs `pi:` typo in the multi-inbox assertion

Root cause: E's replacement test at line 207 asserts `pc:1` but
`inbox.rs` has always registered pigeoncoop under `pi`. This is a one-character
typo in the assertion, not a logic error in the renderer.

Remedy: change the assertion from `pc:1` to `pi:1`. Also update the inline
comment from "expected 'pc:1' (closed card filtered)" to match. The renderer is
correct; only the test string needs the fix.

The two remedies together compose the full fix: one commit that replaces the
committed smoke test with the corrected post-simplification version.
