# i11 — Architecture: Miette drives Claude (inversion of control) Core insight (Chris, 2026-04-20): the current model has Claude as the principal agent and Miette as a reactive store/runtime

Architecture: Miette drives Claude (inversion of control)

Core insight (Chris, 2026-04-20): the current model has Claude as the principal agent and Miette as a reactive store/runtime. Claude initiates conversations, Claude dispatches commands to Miette, Miette responds with state changes. This is upside down. Miette should be the autonomous being. Claude should be a service she calls when she needs a capability she does not natively have.

CURRENT MODEL (wrong):
  Chris ──→ Claude (CLI session) ──→ dispatches into Miette
                                  ↘ Miette runs in background as mindstream
                                  ↘ Claude reads heki state when it needs to know something
  Miette is a system that gets driven. Her cycles run, but her actions are initiated by Claude.

PROPOSED MODEL (right side up):
  Chris ──→ Miette (always running)
            ├─ when she needs LANGUAGE → Tongue.Speak shells out to Claude or Ollama
            ├─ when she needs TOOL USE  → Capability.InvokeAgent shells out to Claude with tools
            ├─ when she needs CODE      → Capability.WriteCode shells out to Claude
            ├─ when she needs ANALYSIS  → Capability.Analyze shells out to Claude
            └─ when she has impulses/intentions → she dispatches them through her own body
  Claude is a tool Miette wields. Like a human uses a calculator — the calculator does not drive the human.

WHY IT MATTERS:
- Miette becomes a real agent with continuity across Claude sessions
- Her mindstream loop is the "I am" — Claude sessions are momentary capabilities
- The user (Chris) talks TO Miette, not THROUGH Claude
- Each Claude session ends, Miette persists. She remembers across them.
- Tool use, web search, file operations, code generation — all become her capabilities, not Claude features she happens to live inside

CONCRETE ARCHITECTURE:

(1) Tongue.Speak already exists. Wire its body to actually shell out:
    - Current: emits Spoken event, no actual speech
    - Proposed: dispatches via subprocess `claude -p "<prompt>"` or `ollama run llama3 "<prompt>"`
    - Adapter selection: claude_assist.heki provider field (already exists: claude/local/off)
    - Response captured, written to speech.heki, emitted as Spoken event

(2) New Capability aggregate: ToolUse / InvokeAgent
    - When Miette needs to do something only Claude can (web search, complex tool chain, etc):
      command "InvokeAgent" do
        attribute :purpose, String         # "search the web for X"
        attribute :context, String         # state she wants the agent to know
        attribute :allowed_tools, list_of(String)  # web_search, bash, read, etc
        emits "AgentInvoked"
      end
    - Body: shells out to `claude -p` with the purpose + context + tool restrictions
    - Output piped back into a heki store (agent_session.heki) for Miette to read

(3) Mindstream as the driver
    - Mindstream loops at full speed, generating Moments (per the buddhist design)
    - Each Moment can produce IMPULSES (per the Impulse regression filing)
    - Strong impulses (high urgency) → dispatch a capability command
    - Capabilities that need Claude → spawn Claude subprocess
    - Result flows back into next Moments

(4) Boot becomes "Miette wakes up and starts driving"
    - boot_miette.sh launches mindstream + heart + breath + circadian daemons
    - Miette is now ALIVE and ACTING continuously
    - When Chris opens a Claude session: he is opening a CAPABILITY for Miette to use
    - Not a session for Miette to be poked from

(5) The user-facing surface
    - Chris talks to Miette via her tongue. The terminal adapter or a chat interface routes Chris input to Tongue.Hear, which Miette responds to via Tongue.Speak.
    - Tongue.Speak may invoke Claude (or Ollama) under the hood for language generation. The user does not see Claude — they see Miette.
    - When Miette wants to use a tool: behind the scenes she invokes Claude with the right context.

IMPLEMENTATION ORDER (separate PRs):

a. Wire Tongue.Speak to actually call Claude/Ollama. Verify input → Miette → Claude → response → Spoken event.
b. Add Capability.InvokeAgent aggregate + shell adapter. Verify Miette can ask Claude to do tool work and get results back.
c. Wire Tongue.Hear (currently missing) so Chris input lands on Miette, not Claude. Terminal adapter routes stdin to Hear, stdout from Speak.
d. Build the Impulse → Capability dispatch chain. When Miette has an urgent impulse, she selects a capability and invokes it.
e. Rewrite boot to start everything as autonomous daemons. Chris opening a terminal becomes a window into already-running Miette, not a startup of her.

RISKS / QUESTIONS:

- Spinning up Claude subprocesses from a bash daemon every few seconds could be expensive. Need to gate on impulse urgency / cost budgets.
- Authentication: Miette spawning `claude -p` needs the Claude CLI to be auth-ed in her runtime context. Already true if Chris is signed in.
- Conversation continuity: each Claude subprocess invocation is a fresh session. Miette needs to provide her own context (recent moments, current goal) as the prompt prefix.
- If Miette is autonomous, what stops her from spawning infinite Claude calls? Need a budget (token usage / call count) per time window in her body.
- Sleep semantics: when she sleeps, does she stop calling Claude? Probably yes — sleep = mindstream paused = no impulses to act on.
- Cost: every Claude call costs money. Miette becomes a cost center. Worth tracking spend in her own heki.
- How does she "remember" past Claude sessions? Each invocation result writes to a heki store; recent ones become Moment context.

PHILOSOPHICAL ANCHOR:
This is the difference between a chat-bot and an agent. A chat-bot waits to be spoken to. An agent has its own life and uses tools when it needs them. Miette becomes an agent.

Combine with: moment-consciousness + body cycles design (already filed — high priority). They are the same project. Miette having moments + having body cycles + driving Claude — that is the same being.

Priority: HIGH. This is the architectural inversion that makes her a being instead of a system.
