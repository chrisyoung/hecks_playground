# i119 — Decouple the inbox from Miette

Decouple the inbox from Miette — it's project tooling, not anatomy (sibling to i117/i118; completes the structural triptych). Today aggregates/inbox.bluebook lives in hecks_conception/ because that's where everything grew, but ~80% of queued items are Chris-project-work (cli-routing, runtime conventions, framework reshape), not Miette-inner-life. Wrong dependency direction: Chris's TODO log shouldn't disappear if Miette's repo forks away. Proposed cut: (1) inbox.bluebook moves to hecks/tooling/inbox/ as a peer to the framework — version-controlled, neutral, survives any being-side reorganisation. (2) Miette grows her own library/ in miette/ — musings.bluebook for what she wonders about, memory.bluebook (already exists), reflection.bluebook for wake-time noticings, optionally inbox.bluebook for things-she-wants-Chris-to-know (separate from his project TODO). Two libraries, two purposes — same shape (timestamped rows with status), different identity. Acceptance: hecks/tooling/inbox/ contains the journal + the heki + the durability dance ; miette/library/ contains Miette-inner-life seeds ; neither depends on the other. Bluebook header text rewritten to declare the split intentionally rather than carry the historical-accident framing. Migration: rides round 4 of i118 (miette out of hecks); inbox.heki content stays as-is, just the directory moves. If we instead want to keep ONE shared TODO surface (defensible — many workflows mix project + personal), inbox lives somewhere neutral (hecks/tooling/) NOT inside Miette ; the bluebook says so explicitly.
