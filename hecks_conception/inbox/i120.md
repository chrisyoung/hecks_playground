# i120 — Archive completed records out of live stores — generalise the pattern across heki. Today inbox.heki holds 113 records: 7

Archive completed records out of live stores — generalise the pattern across heki. Today inbox.heki holds 113 records: 75 queued + 38 done + 0 dropped. Reporting '113 inbox items' conflates active work with history; the live count should be 75. Same shape applies to other stores: memory.heki holds forgotten + active memories, dream_wish.heki holds filed + unfiled wishes, subcommand.heki may grow deprecated entries, exempt_registry.heki may grow retired exemptions. Proposed pattern: bluebook lifecycle declares which states are TERMINAL (done, dropped, archived, retired, forgotten — semantics per aggregate). Runtime moves terminal rows to a sibling archive store on transition: inbox.heki (queued only) + inbox_archive.heki (done+dropped). Or convention: information/archive/inbox.heki holds the historical tail. Two paths: (a) automatic migration on terminal-state transition (Close → row leaves inbox.heki, lands in inbox_archive.heki, preserves all attrs + adds archived_at); (b) manual sweep via Archive.Sweep command run periodically. (a) is cleaner — the lifecycle keyword already names terminal states; the runtime just needs to honor archive: true (or terminal: archive) on the lifecycle declaration. Reads: queries default to live store; explicit Inbox.ListArchive or --include-archive flag for historical. Counts: 'inbox count' returns live count (75); 'inbox count --total' includes archive. Acceptance: live stores stay small + fast; historical data preserved; counts are honest by default; pattern generalises to memory/dream_wish/subcommand/exempt_registry as their lifecycles add terminal states. Sibling to i114 (antibody self-introspect): both reduce 'this store has data that's no longer interesting' as a manual concern.
