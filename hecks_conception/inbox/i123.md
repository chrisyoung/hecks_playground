# i123 — Ruby DSL parser doesn't recognise then_set X, from: Y kwarg form. Four real bluebooks added in commit 3c15dec7 (disposit

Ruby DSL parser doesn't recognise then_set X, from: Y kwarg form. Four real bluebooks added in commit 3c15dec7 (disposition, psychic_link, section_template, wake_ritual) use 'then_set :name, from: :name' syntax — Ruby parser fails with 'unknown keyword: :from', breaking parity_test for those files. Rust parser handles it correctly. Result: parity_test exits 1 on main and on every PR. CI may have been silently passing pre-PR #482 because the workflow trigger or the test didn't fire ; the parity lift in PR #489 surfaced this. Two fixes: (a) teach the Ruby DSL parser to accept 'then_set X, from: Y' as equivalent to 'then_set X, to: :Y' (the from: form may be wrong syntax — verify what the canonical IR says it should be) ; (b) until (a) lands, either fix the four bluebooks to use the supported form, or add them to known_drift.txt so the parity test reports them as drift rather than hard failure. Note: these four bluebooks are part of the system_prompt-as-fixture arc (i89) and the disposition/psychic_link/wake_ritual cluster from this morning's session — they need to land properly before Round 4 of the structural reorg moves them to miette/.
