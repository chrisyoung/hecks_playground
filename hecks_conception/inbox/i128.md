# i128 — DDD: Specifications as first-class. Evans treats specifications

DDD: Specifications as first-class. Evans treats specifications — named predicates that describe domain rules ('is this customer overdue?', 'is this order shippable?') — as a reusable pattern, often as their own value objects. We have `given` clauses on commands today, but no standalone `specification` keyword. The same predicate gets re-typed in queries, validations, and command guards. Proposed shape: `specification "OverdueCustomer" do; matches { last_paid_at < 30.days.ago }; end` — declarable once, citable from command `given`, query `where`, and validator hooks. Closes the duplicate-predicate gap. First instance to retire by name : the `status == 'queued'` guard repeated across Inbox.Close / Inbox.Reopen / Inbox.Drop becomes `given specification: 'QueuedItem'`.
