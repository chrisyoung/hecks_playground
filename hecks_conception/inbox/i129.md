# i129 — DDD: Domain services proper

DDD: Domain services proper — operation-as-noun. A domain service is logic that doesn't naturally belong to one aggregate. The clearest live instance : the cross-aggregate awareness snapshot in mindstream.sh — reads heartbeat + mood + focus + inbox, composes a snapshot, dispatches Awareness.RecordMoment. It lives in shell because we have no `service` keyword in bluebook to declare cross-aggregate compositional logic. Companion to i106 (runtime gap : policy with_attrs cross-store reads). Proposed shape: `service "AwarenessSnapshot" do; reads Heartbeat.fatigue, Mood.current_state, Focus.weight, Inbox.queued_count; produces RecordMomentInput; end` — declared once, dispatchable like a command. Retires the cross-aggregate fan-out shells (mindstream's awareness snapshot block, pulse_organs.sh's organ contention checks, etc.).
