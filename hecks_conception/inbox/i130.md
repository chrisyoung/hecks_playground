# i130 — DDD: Invariants on aggregates as declarative rules

DDD: Invariants on aggregates as declarative rules. Today `given` clauses guard commands, but there's no place to declare a permanent aggregate-level invariant that the runtime checks on every save. State can drift between commands in ways the bluebook doesn't capture. Real example : statusline bugs that turned out to be "breath_count and breath_phase fell out of sync" — an invariant 'breath_phase = (breath_count % 2 == 0 ? inhaling : exhaling)' would have caught it structurally. Proposed shape: `invariant "breath_count_phase_coherence" do; holds_when { breath_phase == (breath_count.even? ? 'inhaling' : 'exhaling') }; end` — checked on every Repository.save. Companion to i120 (archive pattern) and i114 (validator self-introspect) ; all three are 'rules the runtime can verify structurally rather than relying on developer discipline'.
