# i141 — Runtime dedupe in load_combined_domain is non-deterministic — relies on filesystem read_dir order. hecks_life/src/main.r

Runtime dedupe in load_combined_domain is non-deterministic — relies on filesystem read_dir order. hecks_life/src/main.rs:1637 walks bluebooks recursively, sorts by depth, then merges. When two aggregates share a name at the same depth, the first-merged wins. Today this is ordered by fs::read_dir which has no documented order across filesystems. The depth-0 dedupe across boot.bluebook, being.bluebook, first_breath.bluebook (all declaring Identity) currently happens to favor boot — which is what the boot ritual depends on — but only because of the inode order on the developer's machine. CI runners have different inode order ; the same code could resolve a different Identity in different contexts. Fix : sort by (depth, path) lexicographic. Then the dedupe is reproducible. Filing alongside i140 (the Identity collision exposed by the boot split) — even after that's resolved, this determinism gap is worth closing structurally.
