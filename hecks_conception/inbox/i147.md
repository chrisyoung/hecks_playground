# i147 — runtime kernel disappears as authored code

runtime kernel disappears as authored code — the deep self-hosting claim

The end state of the autophagy arc : the runtime IS the bluebook. Every .rs file under hecks_life/src/ regenerates from a corresponding meta-shape, and the meta-shapes themselves regenerate from a meta-meta-shape that bottoms out in a small fixed-point kernel — Futamura projection complete.

Today the kernel surface is approximately :

  - hecks_life/src/main.rs (~3000 LoC) — CLI dispatch, subcommand routing
  - hecks_life/src/parser.rs / parse_blocks.rs / parser_helpers.rs — bluebook DSL parser
  - hecks_life/src/ir.rs — Aggregate / Command / Policy / etc. structs
  - hecks_life/src/runtime/ — Repository, command_dispatch, policy cascade, adapter registry
  - hecks_life/src/heki.rs — the binary record format itself
  - hecks_life/src/behaviors_runner.rs — pure-memory test runner
  - hecks_life/src/conceiver/ — bluebook generators
  - hecks_life/src/run_*/ — the capability runners (caught by i146)

22 .rs files in exempt_registry as kernel-surface. Each entry is a confession that the file lives outside the IR's reach.

Acceptance :
  - Every kernel module has a meta-shape under capabilities/ that emits its .rs file byte-identically
  - hecks_life/ becomes a thin Cargo workspace whose lib + binary are SPECIALIZED — no authored Rust except a tiny entrypoint
  - The bluebook → bluebook self-compile loop closes (i26 sibling)
  - exempt_registry.heki retires entirely

This is the multi-month / multi-quarter arc. i26 (close the bluebook → bluebook self-compile loop) is the philosophical statement of intent. i66 (runtime-kernel-minimization-via-futamura) is the practical thread. i70 (bluebook-as-executable-endpoint) is the architectural fixed point. i147 names the whole.

Each step retires registry entries structurally — when capability_runner_shape's specializer emits run_status, the run_status entries retire. When repository_shape's emits Repository, those retire. And so on until the registry is empty and the runtime is generated.

The discipline ratchets we shipped this session (smoke gate, behaviors gate, companion ratchet, process isolation) and the i122 substrate are transitional — they protect a kernel that the destination structurally cannot have. They retire alongside the kernel they protect.

When this lands : the runtime is the bluebook, the bluebook is the runtime, the corpus is the source code, and 'are we self-validating' answers itself in the source.
