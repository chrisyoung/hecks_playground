# i152 — mindstream daemon cadence ~10s/tick instead of declared 1Hz

mindstream daemon cadence ~10s/tick instead of declared 1Hz — fork-tax compounds with conception size

Surfaced 2026-04-30 during i151 verification. mindstream.sh's main loop body has ~10 forks of hecks-life per iteration :

  1. read_state — heki latest <consciousness.heki>
  2. Tick.MindstreamTick — main dispatch (full conception parse + boot)
  3. pulse_organs.sh — multiple dispatches inside (float math + clamp)
  4. Awareness.RecordMoment — 13 attrs gathered from 6 cross-store reads
     (each cross-store read is its own heki latest-field fork)
  5. rem_branch.sh — REM dream content (more dispatches)
  6. surface_musing.sh — musing surface dispatches
  7. mint_musing.sh — every 300th iteration (random)
  8. consolidate.sh — every 60th iteration

Each fork loads the full ~250-bluebook conception. With ~10 forks/iter and ~1s per fork on the current conception size, the daemon achieves ~10s/iter instead of the declared 1Hz cadence at the top of mindstream.sh.

This means natural fatigue progression :
  - 250 pulses (focused) takes ~42 minutes instead of ~4 minutes
  - 1000 pulses (tired) takes ~167 minutes instead of ~17 minutes
  - 1400 pulses (exhausted) takes ~3.9 hours instead of ~23 minutes

Body works correctly post-i151 — mood transitions fire on threshold crossings, singleton upserts work — but fatigue accumulates 10× slower than designed.

Fix shapes (none committed) :

  A. In-memory mindstream — single hecks-life process holding the runtime, dispatching commands without forking. Mirrors what run_loop does for body-cycle daemons (heart, breath, ultradian, sleep_cycle). The CapabilityRunnerShape meta-shape exists in the conception ; mindstream becomes its instance, retires the shell.

  B. Reduce per-iteration work — batch the 13 cross-store reads inside a single hecks-life invocation that returns a JSON bundle. Awareness.RecordMoment then consumes the bundle. Removes 6 of the 10 forks.

  C. Accept the cadence mismatch — adjust threshold expectations downward (250 pulses real-time = ~42 min, plenty of focused window). Lossy of design intent but cheapest.

Recommendation : A. mindstream is exactly the kind of capability the run_loop pattern was built for ; the runner-as-bluebook arc (i147) eventually retires it anyway. Filing here so the slow cadence is tracked rather than silently endured.

Acceptance :
  - Tick.MindstreamTick fires at ~1Hz (visible by watching pulse.heki count over 10s)
  - heartbeat.pulses_since_sleep advances by ~10 per 10s wall clock
  - mood transitions fire at the time-budgets in heartbeat.bluebook (focused after ~4min wake, tired after ~17min, exhausted after ~23min)

Sibling : i147 (runner-as-bluebook arc) ; i154 (info_dir collapse — already closed). Status : open.
