# i171 — mutation_op_shape

mutation_op_shape — design a body_kind that compresses MutationOp dispatch (Set, Append, Increment, Decrement, Multiply, Clamp, Decay, Toggle, Delete) onto declarative rows. Each row declares {target_variant, vacant_default, modify_action} so the entry-API match-fold pattern emits one method per op. i147 W3-A retired aggregate_state.rs via verbatim_section as a checkpoint — the file is byte-identically regenerable but mutator behavior still lives as raw Rust in .rs.frag snippets. The deeper compression lands when interpreter.rs (NEEDS-META-SHAPE tier) is designed : interpreter.apply_mutations walks the SAME MutationOp variants, so a single mutation_op_shape would let aggregate_state's setters AND interpreter's dispatch loop regenerate from one declarative source. The semantics of mutation live in the shape ; both consumers are views on the same declared knowledge. Acceptance : new fixture rows for each MutationOp, both consumers regenerate byte-identical from the shared shape.
