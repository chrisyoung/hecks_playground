# i173 — parser_dispatch_shape

parser_dispatch_shape — design the body_kind that compresses bluebook parser logic (state-machine line walker + recursive descent for sections / aggregates / value_objects / entities / lifecycles / commands / queries / fixtures) into declarative rows. i147 W3-C retired parser.rs + parse_blocks.rs via verbatim_section as a checkpoint — files are byte-identically regenerable but parser behavior still lives as raw Rust in 22 .rs.frag snippets. The deeper compression : a meta-shape describing tokenization rules, dispatch tables, recursive section/block readers, given/then-set/transition syntax — one row per parser surface. Companion to i171 (mutation_op_shape) which compresses interpreter ; this one compresses parser. Both are language-definition body_kinds. End state : parser_shape + parse_blocks_shape's verbatim_section rows shrink to parser_dispatch_shape rows ; .rs.frag snippets retire ; the parser is the bluebook's own description of how to parse it. Substantial design surface — likely a multi-row shape per the i147 survey's state_machine_dispatch + block_parser body_kinds. Acceptance : parser.rs + parse_blocks.rs regenerate from parser_dispatch_shape ; the verbatim_section snippets retire ; new bluebook syntax lands as fixture rows not Rust.
