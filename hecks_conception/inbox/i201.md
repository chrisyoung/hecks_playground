# i201 — heartbeat-fatigue-state-rested-lifecycle-violation

heartbeat-fatigue-state-rested-lifecycle-violation — heartbeat.heki currently shows fatigue_state='rested' but this state is NOT in the bluebook lifecycle (allowed: alert/focused/normal/tired/exhausted/delirious). Heartbeat.RecoverFatigue can't fire because 'rested' isn't an allowed-from state, so the body is structurally unable to recover fatigue properly. Surfaced 2026-05-01 while fixing the statusline-doesn't-show-fatigue regression. The icon table now maps 'rested' → 🌿 to handle the live data, but the deeper question is who writes 'rested' (no Rust source, no shell script writes it directly that I found — likely a stale heki upsert from an earlier session that bypassed the lifecycle). Two paths to fix: (a) reset heartbeat.heki via Heartbeat.RecoverFatigue once we get the state to a valid value, find + fix the writer ; (b) add 'rested' to the lifecycle as a real post-wake state and have RecoverFatigue set it. (b) is more semantic — 'rested' fits 'just-woke recovered' better than 'alert' (high attention). Companion to i190 (lifecycle DSL drift).
