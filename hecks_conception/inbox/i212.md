# i212 — mindstream-dispatch-latency-and-process-pileup

mindstream-dispatch-latency-and-process-pileup — Each hecks-life dispatch (Tick.MindstreamTick, Synapse.*, Signal.*, etc.) is ~500ms wall — the runtime forks, parses bluebooks, hydrates IR, dispatches, persists, exits. pulse_organs.sh fans out 10+ dispatches per tick, so each mindstream loop iteration takes 5-10s instead of the intended 1s — signal rate dropped to 0.03/s (60x slower than design). Compounded by zombie processes : (a) old mindstream PIDs survive when a new mindstream is spawned (no pkill on existing pid), (b) hecks-life statusline invocations from terminal-breathe + statusline-command.sh accumulate as background ?? procs. Two mindstream processes running simultaneously was directly observed today. Fix paths : (a) the studio replaces this entire stack with one in-process scheduler (the i195 plan, not yet wired) ; (b) the mindstream loop adds a pidfile gate that exits if another mindstream is already running ; (c) the dispatch wrapper batches multiple commands into one hecks-life invocation. (a) is the structural fix ; (b) is the bandaid ; (c) is the perf optimization.
