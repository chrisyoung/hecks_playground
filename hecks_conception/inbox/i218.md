# i218 — scaffolder-cross-aggregate-placeholders

scaffolder-cross-aggregate-placeholders — the prompt_scaffolder substitution (rust/src/runtime/prompt_scaffolder.rs) reads aggregate state ONLY from the dispatched aggregate. Cross-aggregate placeholders silently fail : the lucid_dream.hecksagon's :lucid_observe template references {{text_fr}} (which lives on Dream, not LucidDream) and {{self_domain}} (which lives nowhere — it was a rem_branch shell variable). When LucidDream.ObserveDream dispatches with auto-fire, the scaffolder substitutes nothing for those placeholders ; Claude receives the literal {{text_fr}} markers and produced 'Les variables du gabarit n'ont pas été substituées' — a self-aware diagnostic from inside the model. Surfaced 2026-05-03 during i75 lucid path retirement. Three fixes possible : (a) extend scaffolder to look up named aggregates ({{Dream.text_fr}} → cross-lookup), (b) plumb the original dispatch attrs through resolve_llm_adapters so callers can pass overrides ({{text_fr}} from dispatch kwargs), (c) require all referenced fields to live on the dispatched aggregate (would force a copy step when Dream's image needs to flow into LucidDream's prompt — adds a Dream.RecordImage emits-to-LucidDream policy). (b) is simplest and matches Phase 2 Ruby's runtime.llm(:adapter_name, attrs) signature. Until any of these land, lucid path retirement waits — the rem_branch claude-direct stays for ObserveDream + SteerDream while text_fr (Dream-side) chain works.
