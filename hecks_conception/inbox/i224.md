# i224 — mind-pm-musing-context-not-stamped

mind-pm-musing-context-not-stamped — Mind PM dispatches MusingMint.MintMusing every BodyPulse during attentive (mind/mind.bluebook line 253), but does NOT dispatch MusingMint.RecordContext first. RecordContext stamps the five prompt-context fields (recent_musings_summary, recent_commits, conversations_summary, nursery_sample, state_snapshot) onto the MusingMint singleton ; the :mint_idea adapter's prompt template reads them via {{placeholders}}. Without RecordContext firing, all context fields are empty strings, the prompt has no real content, and the LLM curator returns 'skip' (or null). Result : musing_mint.total_minted increments per tick, but last_minted stays null and no real ideas are produced. The legacy mint_musing.sh (now retired) computed each context field via heki/jq pipelines before dispatching RecordContext + MintMusing. To reproduce in bluebook : either (a) extend Mind PM to dispatch RecordContext before MintMusing with computed values (blocked on compute-adapter-primitive gap filed by i220 agent), OR (b) add a :compute adapter family to the :mint_idea hecksagon that resolves the placeholders from heki state at adapter-fire time (similar to dream-content-smoke flow). Surfaced 2026-05-03 during i219 heal verification — Mind PM is correctly dispatching but the chain produces no content.
