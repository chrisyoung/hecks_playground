# i226 — i221-C parse-where-comparator-hash-form

i221-C parse-where-comparator-hash-form — i101 first-class query IR carries Lt/Lte/Gt/Gte/Ne WhereOp variants but the bluebook DSL parser (rust/src/parse_blocks.rs::parse_where_line, ~line 321) only recognizes the Eq form: where(field: value). The hash-form: where(field: { lt: 0.1 }) / { ne: "archived" } / { gte: 5 } isn't wired. This blocks expressing Synapse.cold (where last_fired_at lt now_minus_X), Signal.cold (similar), Signal.live (where status ne archived). Without these queries, the i225 sweep primitive (for_each: { from: "Synapse.cold" }) can't be used safely on body cycles — sweeping over Synapse.alive composts the entire working set, strictly worse than the existing consolidate.sh shell. Closes the BLUEBOOK half of i221 once shipped : (1) extend parse_where_line to recognize hash-form values + map ops to WhereOp variants ; (2) Ruby DSL builder symmetric extension for where(field: { lt: ... }) parity ; (3) round-trip parity fixture in parity/bluebooks/ ; (4) add Synapse.cold + Signal.cold + Signal.live queries on miette aggregates ; (5) rewrite Consolidation PM PhaseElapsed handlers to use for_each + the new queries ; (6) verify consolidate_smoke runs through PM ; (7) delete body/consolidate.sh. Filed by i225 agent 2026-05-03 after PR #589 merged the runtime half.
