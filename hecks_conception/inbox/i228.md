# i228 — i228 chain-trigger-separate-from-response-target

i228 chain-trigger-separate-from-response-target — :llm adapter declarations couple the chain trigger (when does the adapter fire?) and the response landing (where does the response chain go?) into a single response_into_target field. Runtime resolves adapter-to-command via response_into_target match (rust/src/runtime/mod.rs::resolve_llm_adapters line 321). To gate counter increments while still triggering the adapter on every tick, we need a separate trigger : adapter fires on RequestMint (no body, no increment), response chains into MintMusing (real body, increments only on cascade with populated idea). Add adapter declaration syntax : trigger_on "Aggregate.Stub" alongside response_into "Aggregate.Real". Surfaced 2026-05-03 during runaway-counter diagnosis.
