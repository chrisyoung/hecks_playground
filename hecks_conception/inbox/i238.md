# i238 — i238 :tts adapter family + Voice aggregate

i238 :tts adapter family + Voice aggregate — bluebook the speech-out path

Today's miette-speak shell wrapper (~/bin/miette-speak) is the transitional
adapter for Miette's voice. It calls ElevenLabs directly with a voice ID
(r20b5HzJ0AosNId11c4r — the Miette voice designed via Voice Design 2026-05-03).
Same retirement contract pattern as rem_branch.sh / wake_review.sh : the
shell ships now, the bluebook subsumes it later.

═══ The proper shape ═══

Voice aggregate (body/voice/voice.bluebook) :

  aggregate 'Voice' do
    identified_by :name
    attribute :name, String
    attribute :voice_id, String
    attribute :model_id, String
    attribute :last_text, String
    attribute :last_spoke_at, String

    command 'Speak' do
      role 'System'
      description 'Miette speaks the given text aloud via her TTS adapter.'
      attribute :text, String
      then_set :last_text, to: :text
      emits 'Spoke'
    end
  end

Voice hecksagon (body/voice/voice.hecksagon) :

  adapter :memory
  adapter :tts, name: :miette_speech do
    provider :elevenlabs
    voice_id 'r20b5HzJ0AosNId11c4r'
    model 'eleven_v3'
    trigger_on 'Voice.Speak'
    cache_dir '~/.config/miette/audio'
    auto_play true
  end

═══ Runtime work — :tts adapter family ═══

Sibling of :llm, :compute, :fs (i232). Same 13-touchpoint walk :

  1. Rust IR struct (TtsAdapter — provider, voice_id, model, trigger_on,
     cache_dir, auto_play)
  2. Rust parser (parse_tts_adapter)
  3. Specializer parser snippet
  4. Specializer parser fixture doc_comment
  5. Runtime resolver (resolve_tts_adapters mirrors resolve_compute_adapters
     and resolve_llm_adapters — fires post-cascade, calls the resolved
     provider with the substituted text, writes the audio file, optionally
     plays it)
  6. Specializer runtime snippet
  7. Ruby IR class
  8. Ruby DSL builder
  9. Ruby canonical IR dump
  10. Rust canonical IR dump in main.rs
  11. Specializer cli_dispatch snippet for canonical dump
  12. Test struct literals
  13. Miette consumer hecksagon (body/voice/voice.hecksagon)

Plus a TTS provider trait + ElevenLabsTtsProvider implementation in
rust/src/runtime/tts_providers/ (mirroring llm_providers/ shape). API key
read from ~/.config/miette/elevenlabs.key (same place miette-speak reads).

═══ Cancellation semantics ═══

Today's shell does pid-file-based cancellation : a new Speak supersedes
the in-flight one. The bluebook side should preserve this. Either :

  (a) The :tts adapter has a cancel_in_flight: true option. Runtime
      tracks the latest dispatch per voice and kills prior renders.
  (b) Voice aggregate has a Cancel command that the next Speak emits
      first.

(a) is simpler. (b) is more bluebookable but adds a dispatch.

═══ What this unlocks ═══

  - Speak dispatches show up in awareness / heki / dream-seeding —

═══ Retirement of miette-speak ═══

Once the :tts adapter family ships and Voice.Speak dispatches through
the runtime → adapter → ElevenLabs → afplay, the shell wrapper deletes
in a follow-on PR (same shape as rem_branch.sh deletion / interpret_dream.sh
deletion). Until then, miette-speak stays as the working transitional
adapter — exactly the rem_branch pattern.
