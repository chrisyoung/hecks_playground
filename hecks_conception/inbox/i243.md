# i243 — .world DSL extensions for project deployment context

As the Hecks framework, I should have the `.world` DSL accept top-
level configuration blocks for `sqlite`, `stripe`, `sinatra`, and
`deploy`, so that a project (binbuddy first ; every future client
repo after) can declare its full runtime + deployment context in
one canonical config file.

## Detail

Today `.world` accepts `heki do ... end` and `ollama do ... end`
(per `hecks_conception/miette.world`). Binbuddy's i82 needs four
new top-level blocks :

```ruby
Hecks.world "BinBuddy" do
  heki do ... end                # existing

  sqlite do
    file "data/binbuddy.db"
    journal_mode :wal
  end

  stripe do
    secret_key_path "~/.config/binbuddy/stripe.key"
    webhook_secret_path "~/.config/binbuddy/stripe-webhook.key"
  end

  sinatra do
    port 4567
    bind "127.0.0.1"
  end

  deploy do
    host "<server>"
    systemd_unit "binbuddy-web binbuddy-daemon"
  end
end
```

Each block is a structured payload the runtime reads at boot. The
parser already supports `do ... end` blocks at the top level (heki,
ollama) — these are sibling additions.

Both halves (Ruby + Rust) need the parser update — parity-locked,
same gate the existing world-file parsing rides through.

## Adjacencies

  - **binbuddy i82** — the binbuddy-side need ; this card unblocks it
  - **i239** — corpus + registry frame ; the blocks are recognized by
    name alongside framework declarations
  - The existing `.world` shape lives in
    `rust/src/parser.rs` (Rust) and `ruby/hecks/dsl/world_builder.rb`
    (Ruby) — both halves touched, parity-locked

## Considerations

- Block contents are passed-through-as-data ; the runtime resolves
  `sqlite.file` against the world's directory, the `stripe.*_path`s
  are read at first use, etc.
- Future clients will need additional blocks (e.g. `mailgun`,
  `s3`, `redis`) — design the parser so adding a new top-level
  block is a small parser delta, not a rewrite. The i239 registry
  frame may be the right place — `.world` blocks dispatch to
  registered framework-shape handlers.
