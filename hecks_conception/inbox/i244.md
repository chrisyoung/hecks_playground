# i244 — generate_sinatra per-hecksagon scope

As the Hecks framework, the `hecks generate_sinatra` command should
scope generation per-hecksagon (not per-bluebook), so that multi-
portal projects like binbuddy (customer / employee / driver-mobile,
each its own hecksagon over a shared bluebook corpus) generate one
Sinatra app per surface — each with the right routes, role-gating,
and view templates declared by that hecksagon.

## Detail

Today `ruby/hecks_cli/commands/generate_sinatra.rb` generates per-
domain : it walks a single bluebook's aggregates and emits routes
from queries + commands. Works for single-domain projects (the
historic Hecks shape).

Binbuddy is multi-portal — one bluebook corpus shared across three
hecksagons :
- `customer_portal.hecksagon` (i78)
- `employee_portal.hecksagon` (i79)
- `driver_mobile.hecksagon` (i80)

Each declares its own auth-required routes, view templates, role-
gating (i75), and exposes a different subset of the bluebook's
commands + queries.

Refinement needed :
- Generator accepts a hecksagon path : `hecks generate_sinatra
  customer_portal.hecksagon` (or implicit from the project's
  hecksagon list)
- Reads route declarations from the hecksagon (rather than emitting
  every command/query route automatically)
- Honors role-gating (the hecksagon declares `auth_required: :customer`
  on a route ; the generated app middleware enforces it)
- Per-hecksagon view-template directory (each portal has its own
  templates / look)

The single-domain path (current behavior) stays intact — this is
additive scoping.

## Adjacencies

  - **binbuddy i78 / i79 / i80** — the three portal hecksagons that
    need this scope ; without it binbuddy can't generate three
    distinct Sinatra apps from one shared bluebook corpus
  - **i239** — registry frame ; the hecksagon-as-scope is consistent
    with the corpus-as-source-of-truth
  - **i243** — `sinatra` block in `.world` declares port / bind ; the
    generator consumes that

## Considerations

- May land as a refinement of generate_sinatra OR as a sibling
  command (`hecks generate_portal <hecksagon>`) — operator's call
- Test the generator against binbuddy's three hecksagons during
  walking-skeleton build ; that's the proving ground
