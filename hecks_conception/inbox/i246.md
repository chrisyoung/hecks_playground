# i246 — aggregate-level rules

As the Hecks framework, an aggregate should be able to declare
*rules* — consistency rules that span multiple attributes and that
the runtime checks at command-dispatch time — so domain rules live
where they belong (in the bluebook, in the language people use to
talk about them) instead of being scattered across adapter code or
hidden behind programmer-jargon words like "rule."

## Why

VO-level rules (i245) check one value at a time : "Email
contains @", "Money is non-negative." But many real consistency
rules span MULTIPLE attributes of the same aggregate :

  - **Subscription** : `cancel_date must be after start_date`
  - **ServiceTask** : `completed_at must fall within
    window_start..window_end + grace_period`
  - **WorkerShift** : `clock_out_at must be after clock_in_at`
  - **DriverApplication** : `decision_at must be on or after
    background_check_started_at`
  - **AddOn** : `total_price must equal unit_price × quantity`

These are aggregate-level. They can't live on a single VO — they
need access to multiple attributes simultaneously.

## DSL

```ruby
aggregate "Subscription", "..." do
  attribute :start_date,  DateOnly
  attribute :cancel_date, DateOnly

  rule "cancel_date must be after start_date" do
    when_present :cancel_date            # only check if cancel_date is set
    requires { cancel_date > start_date }
  end

  rule "monthly_price must match the plan's price at start_date" do
    requires { monthly_price.amount_cents == lookup(Plan, plan_code).monthly_price.amount_cents }
  end
end
```

Rule matchers (composable) :
- `when_present :attr` — gate : only check when the attribute is set
- `when :attr_a, :is, value` / `when_state state_name` — multi-condition gate
- `requires { ... ruby block ... }` — predicate over the aggregate's
  current state
- Named matchers : `at_least`, `at_most`, `between`, `before`,
  `after`, `within`, `present`, `matches`

## When the check fires

After a command's `then_set` has applied (state mutation done) but
before the event emits and the record persists. If an rule
fails the command dispatch raises `RuleFailed { aggregate,
rule_message, state_snapshot }` ; the dispatch rolls back as
if the command never happened. Adapters / portal layer renders this
as a 422 with the structured error.

## Implementation surface

— **IR** : `Aggregate.rules: Vec<AggregateRule>` field.
  Each carries a name, a list of gate conditions, a predicate
  (closure / structured matcher tree).

— **Parser** : `codegen/parse_blocks_shape/snippets/` adds an
  `rule "..." do ... end` block recognizer at aggregate scope.

— **Runtime** : `runtime/command_dispatch.rs` dispatches the
  rule check after `apply_mutations` and before `emit_event`.

— **Behaviors** : new `expect_rule_failure :name` matcher
  in the test DSL.

## Considerations

- VO rules (i245) and aggregate rules are different
  scopes ; both coexist. VO rules check a single value ;
  aggregate rules check the aggregate's state graph.

- Performance : rules run on every command. Predicates should
  be O(1) over local state. Cross-aggregate lookups (e.g.
  `Plan.find_by_code`) are allowed but should be rare ; use
  `references` (i249) when one aggregate's rule depends on
  another's.

- bin-buddy needs at least 8 of these on day one. Without them,
  every command body needs imperative checks (anti-pattern).

## Parity gate

Every framework change in this card has to land in BOTH the Rust
parser/runtime AND the Ruby DSL/runtime ; the dual-runtime parity
contract (`parity/parity_test.rb`) must stay green when the PR
is opened.

  - Rust side : `codegen/<shape>/snippets/`, regenerated `rust/src/`
  - Ruby side : `ruby/hecks/dsl/`, `ruby/hecks/bluebook_model/`,
    `parity/canonical_ir.rb`
  - Verification : `ruby -Iruby parity/parity_test.rb` reports the
    expected pass count + 0 unintended drift
  - Hecksagon parity : `ruby -Iruby parity/hecksagon_parity_test.rb`
    when adapter / hecksagon surface changes

An agent’s PR is not ready for merge until parity is verified
locally and the relevant golden goldens / canonical-IR shapes are
updated together. No Rust-only or Ruby-only changes ship.
