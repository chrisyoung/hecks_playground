# i249 — typed aggregate references

As the Hecks framework, aggregates should reference each other
through a first-class `references` declaration that names the
target aggregate and identifying attribute, so the runtime can
validate FKs at dispatch time, generate query helpers, and the
admin dashboard can render references as click-through links.

## Why

Today aggregate FKs are stringly-typed. Subscription has
`attribute :customer_account_email, Email` — the *meaning* (this
points at a Customer record keyed by account_email) is in the
attribute name, not the type. The runtime can't validate the FK,
generate `Subscription.customer` accessor, or render dashboard
navigation between linked records.

## DSL

```ruby
aggregate "Subscription" do
  references Customer,        by: :account_email
  references ServiceAddress,  by: :id, as: :service_address
  references Plan,            by: :plan_code
end

aggregate "ServiceTask" do
  references ServiceAddress, by: :id
  references Subscription,   by: :stripe_subscription_id
  references Worker,         as: :worker, by: :account_email, optional: true
end
```

Each `references` declaration :
1. Adds an attribute typed by the target's identifier VO
2. Generates an accessor (`subscription.customer` returns the linked
   Customer record)
3. Validates at dispatch time that the FK resolves
4. Drives admin-dashboard navigation
5. Can power query traversals (`Customer.find_by_account →
   .subscriptions → .active`)

The `as: :alias` form lets multiple references to the same target
aggregate disambiguate (`worker` vs `dispatcher` vs `creator`).

## Implementation surface

— **IR** : `Aggregate.references: Vec<Reference>` ; each carries
  target aggregate name, FK attribute, optional alias, optional flag.

— **Parser** : `references AggName, by: :attr [, as: :alias] [, optional: true]`
  recognizer at aggregate scope.

— **Runtime** : at command dispatch, resolve referenced records.
  Optional refs may resolve to nil ; required refs that fail to
  resolve raise `BrokenReference { source, target, fk_value }`.

— **Specifications + queries** : i248 specs and queries can
  traverse references natively (`Subscription.customer.is_active`).

## Considerations

- Tie to i246 (aggregate invariants — can reference linked records).
- Tie to i248 (specifications — can traverse references in predicates).
- Defaults to `required` ; explicit `optional: true` for cases
  where the FK might legitimately be nil (e.g. ServiceTask.worker
  when the task is unassigned).
