# i275 — `read-watcher-log` hook silently no-ops because watcher gem moved

The PostToolUse hook in `.claude/settings.json` runs
`bin/read-watcher-log` after every Edit/Write/Bash. Its purpose
is to surface watcher output (file-size, autoload, cross-require
violations, etc.) to the agent in real time.

## What's wrong

`bin/read-watcher-log` does :

```ruby
$LOAD_PATH.unshift File.expand_path("../hecks_watchers/lib", __dir__)
$LOAD_PATH.unshift(File.expand_path("../hecksties/watchers/lib", __dir__))
require "hecks_watchers"
```

But `hecks_watchers/` and `hecksties/` no longer exist at the
project root :

```
$ ls /Users/christopheryoung/Projects/hecks/ | grep -i watcher
# (nothing)
```

Watchers exist under `ruby/hecks/capabilities/live_reload/watcher.rb`
and `ruby/hecks/extensions/serve/domain_watcher.rb`, but those are
runtime watchers, not the `hecks_watchers` library this hook
expects.

The hook command in `.claude/settings.json` is wrapped with
`2>/dev/null || true`, so the require failure is swallowed and the
hook silently exits 0. The agent gets no watcher output.

## Why it matters

The watcher feedback loop is part of the discipline — autoload
drift, cross-require leaks, file-size violations are supposed to
surface as the agent works, not at commit time. With the hook
silently no-op'd, every session loses real-time watcher signal.

This was discovered while investigating whether an "antibody hook"
was blocking edits during the mindstream-supervisor walk's Step 0.
It wasn't blocking ; it was no-op'd.

## What should happen

Either :

1. **Restore the gem path** — move/symlink the watcher library to
   where the hook expects it, OR
2. **Update the hook** — point at the actual current location,
   wherever the watcher entry-point now lives, OR
3. **Retire the hook** — if watchers are now invoked elsewhere
   (the post-commit hook, CI, a background daemon), remove the
   PostToolUse entry from `.claude/settings.json` to stop pretending
   real-time signal exists.

Option 2 is probably right, but I haven't traced where the watcher
gem moved during the i147+ wave. Whoever folds this in should
follow the trail of `HecksWatchers::LogReader.call` and find the
new home.

## Surface

- Wherever `HecksWatchers::LogReader` actually lives now (find it)
