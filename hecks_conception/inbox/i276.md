# i276 — `:overmind` generator capability

## Context

The boot-overmind walk (May 7, 2026) introduced the **Mindstream** domain :

- `aggregates/framework/mindstream/mindstream.bluebook` — defines `Mindstream` (a named
  group of overmind-supervised processes ; one Mindstream = one Procfile)
  and `MindstreamMember` (one Procfile entry).
- `aggregates/framework/mindstream/mindstream.fixtures` — declares the concrete
  *boot* Mindstream with one one-shot MindstreamMember.

The committed `hecks_conception/Procfile` and
`hecks_conception/.overmind.env` are **hand-derived** from these two
bluebooks. They contain a header comment naming the bluebook-of-record
and the generator gap. This card closes that gap.

## What

A capability under `ruby/hecks/capabilities/overmind/` (and `.rb`)
that, given the parsed Hecks domain, walks every `Mindstream` fixture
instance and emits :

- `<swarm.directory>/Procfile` — one line per `MindstreamMember` whose
  `swarm` attribute matches the swarm's name. Format :
  `<process.name>: <process.command>`.
- `<swarm.directory>/.overmind.env` — `OVERMIND_CAN_DIE` set to a
  comma-separated list of every MindstreamMember in the swarm whose
  `lifespan.kind == "one_shot"`, plus any framework env
  (`HECKS_DAEMON=1` for Miette's boot swarm).

The generator reads three Value Objects on the IR side :

- `Mindstream.directory : Directory { path }` — where to write the artifacts.
- `MindstreamMember.command : ShellCommand { line }` — the Procfile line.
- `MindstreamMember.lifespan : Lifespan { kind }` — discriminator for
  `OVERMIND_CAN_DIE` membership ("one_shot" vs "persistent").

Idempotent. Output is checked in (treated like a generated parser ;
the bluebook is the source of truth).

## Invocation surface

Two paths to consider :

1. **Runtime capability** : `runtime.capability(:overmind)` registers
   a hook that regenerates artifacts on boot if the bluebook is newer
   than the artifact. Convenient ; muddier (bootstraps from itself).
2. **Standalone generator** : `bin/generate-overmind` script that
   reads the bluebooks under `hecks_conception/` and writes the
   artifacts. Cleaner ; needs to be re-run by hand after swarm
   bluebook edits.

I lean (2). Generation is a build step, not a runtime concern.

## Why now

Without this card, the source-of-truth chain has a manual gap : the
bluebook says X, the artifact says Y, drift is possible. A generator
makes them mechanically identical and lets future swarms (body cycles
under overmind, integration tests, etc.) drop in by adding fixtures.

## Surface

- Read : `aggregates/framework/mindstream/mindstream.bluebook` IR (Mindstream,
  MindstreamMember aggregates) + `aggregates/framework/mindstream/mindstream.fixtures`
  (concrete instances).
- Write : `<swarm.directory>/Procfile` and
  `<swarm.directory>/.overmind.env`.
- Test : a parity-style fixture verifies the generator's output for a
  known swarm matches the committed artifact.
