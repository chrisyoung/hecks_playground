# i278 — `cargo build --release` carries 16 warnings ; clean them by source

The warnings appear after every `cargo build --release` :

    warning: `hecks-life` (lib) generated 16 warnings

They group naturally by source. Each group is its own small walk —
landing all 16 in one commit hides what's drift vs what's leftover
vs what's superseded.

## Group 1 — html_domain codegen drift (5 unused fns + 1 unused import)

    src/server/html_domain.rs:16   unused import super::html_kpi::kpi_cards
    src/server/html_domain.rs:344  fn module_navbar
    src/server/html_domain.rs:356  fn module_card
    src/server/html_domain.rs:406  fn command_section
    src/server/html_domain.rs:414  fn wizard_button
    src/server/html_domain.rs:428  fn inline_form

`html_domain.rs` is generated from `codegen/html_domain_shape/` ;
these helpers are emitted but no caller references them. The shape
is over-emitting. Fix lives in the shape, not the .rs file
(direct edits would just regenerate). **Pairs with i261 on the
prior branch (multi-server-primary-bluebook-walk)** which already
names html_domain_shape drift — same root cause, audit together.

## Group 2 — Hand-written dead fns (2)

    src/run_boot/discover.rs:138        fn count_top_level_bluebooks
    src/run_status/assemble.rs:376      fn mindstream_alive

Both are leftovers from earlier walks. The current run_status uses
a local `mindstream_alive` variable in `mod.rs:127` (different code
path) ; the standalone fn at `assemble.rs:376` is dead.
`count_top_level_bluebooks` has zero callers anywhere. Delete both.
~5 minutes ; antibody marker on each touched .rs (existing).

## Group 3 — Lifecycle helpers superseded (2)

    src/runtime/lifecycle.rs:13   pub fn check
    src/runtime/lifecycle.rs:42   pub fn apply_transition

`command_dispatch.rs:440` carries the comment *"Mirrors
lifecycle::check but routes through Resolution so entity ..."* —
the entity-aware port superseded the originals. Remove the
originals (and verify nothing in tests / parity references them).

## Group 4 — Codegen unused vars (4)

    src/server/html_kpi.rs:14            unused var `modules`
    src/server/html_kpi.rs:16            unused var `commands`
    src/conceiver/generator.rs:16        unused var `snake`
    src/conceiver/generator.rs:88        unused param `index`

Codegen-emitted code that computes values it doesn't use. Either
the shape needs to drop the computation, or rename to `_modules` /
`_commands` / `_snake` / `_index` in the shape so the generated
code carries the underscore prefix. Pick one convention for codegen
hygiene and apply uniformly.

## Group 5 — Hand-written unused vars (2)

    src/heki.rs:903                                   unused var `being`
    src/behaviors_conceiver/generator.rs:1305         unused param `domain`

Inline rename to `_being` / `_domain` (or remove if the variable's
declaration itself is dead).

## Why now

The 16-warnings line at the end of every build is the kind of
chronic noise that hides regressions when a NEW warning slips in.
Build output should be *quiet by default* ; new warnings should be
loud and immediately visible. With 16 warnings always present, that
signal is gone.
