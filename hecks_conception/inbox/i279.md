# i279 — `claude_harness` as a bluebook ; SessionStart hook becomes a generated artifact

## Context

The boot-overmind walk (PR #620) wired the SessionStart hook to call
`cd hecks_conception && overmind start` so the boot Mindstream
runs whenever a Claude session opens. The wiring lives in
`.claude/settings.local.json` — which is gitignored, so the change
only affects the operator's local machine. A fresh clone has no
overmind-aware SessionStart hook.

The committed `.claude/settings.json` does carry a SessionStart hook
(it runs `bin/update-codebase-index`). Two SessionStart hooks running
in series isn't necessarily wrong, but : the choice of *what* runs at
session start is currently scattered between a gitignored local file
+ a committed settings file + a hand-edited contract that nobody but
the operator sees.

## What

A `claude_harness` bluebook that conceives the harness configuration
as a domain :

  - **Hook** aggregate — name (SessionStart, PostToolUse, Stop, …),
    matcher (when it fires), command (what runs).
  - **Permission** aggregate — allow / deny entries from the same
    block.
  - **StatusLine** aggregate — the persistent statusline command.
  - **Plugins** value object — enabled plugins.

A `:claude_harness` capability emits `.claude/settings.json` from
the bluebook, the same way the `:overmind` generator (i276) will
emit Procfile + .overmind.env from the Mindstream bluebook.

`.claude/settings.local.json` keeps its role as the operator's
*per-machine override surface* — paths, secrets, machine-specific
permissions — but the *contract* (what hooks fire, what command they
run) lives in the bluebook + generated `settings.json` and is shared
across every clone.

## Why

The same source-of-truth argument as i276 :

  - Today : the SessionStart wiring is implicit, lives in a single
    operator's local file, drifts silently, and a teammate
    cloning fresh has no idea what the boot contract is.
  - With this card : the bluebook *names* the contract ; the
    generated `settings.json` *carries* it ; new operators get
    the working harness on first clone with zero ceremony.

## Adjacent

  - **i276** — `:overmind` generator that emits Procfile +
    .overmind.env from the Mindstream bluebook. Same shape, same
    pattern ; whoever closes one closes the other naturally.
  - **i277** — when the run-loop CPU pathology resolves and ctrl-C
    tears the swarm down clean, the SessionStart hook's
    `rm -f .overmind.sock` prefix retires (overmind cleans its own
    socket).

## Surface

  - `aggregates/framework/claude_harness/claude_harness.bluebook`
    (new) — Hook + Permission + StatusLine + Plugins aggregates.
  - `aggregates/framework/claude_harness/claude_harness.fixtures`
    (new) — concrete instances : the SessionStart hook that runs
    overmind, the codebase-index hook, the antibody PostToolUse
    hook (if it lands), the statusline command.
  - `ruby/hecks/capabilities/claude_harness/` (new) — generator
    capability ; reads the IR + fixtures, emits
    `.claude/settings.json`.
  - `bin/generate-claude-harness` (new) — invocation surface.
    Re-run after editing the bluebook ; check in the resulting
    `.claude/settings.json`.

## Tie-ins

  - Surfaced 2026-05-07 during the boot-overmind walk. Not in
    scope there ; the SessionStart wiring landed on
    `.claude/settings.local.json` as a transitional measure.
  - The committed `.claude/settings.json` already has hooks
    (codebase-index on SessionStart, read-watcher-log on
    PostToolUse, gem-rebuild on Stop, etc.) — auditing those
    against current state is its own micro-walk inside this
    one. Some are stale (i275 — read-watcher-log no-ops because
    the gem moved).
