# i377 — specializer-files-as-bluebook — The specializer files in hecks_life/src/specializer/* are hand-written Rust today. Phase

specializer-files-as-bluebook — The specializer files in hecks_life/src/specializer/* are hand-written Rust today. Phase E retired the Ruby meta_* specializers ; the Rust ones became the sole codegen path. But they're not byte-identity-generated from meta-shapes — they're authored. The autophagy arc's third Futamura projection (specialize the specializer of specializers) would land them as bluebook + spec-emit. Files in scope : validator.rs, validator_warnings.rs, validator_morphology.rs, behaviors_parser.rs, fixtures_parser.rs, hecksagon_parser.rs, dump.rs (all under hecks_life/src/specializer/). Each becomes a meta-shape capability under hecks_conception/capabilities/<name>_shape/specializer_shape/. Surfaced 2026-04-25 when Chris pushed 'BLUEBOOK BLUEBOOK BLUEBOOK' — the realization that even the layer that emits Rust should itself emit from a shape. Real arc : equivalent in scope to Phase D was for runtime files. Acceptance : every .rs file under hecks_life/src/specializer/ has a sibling shape capability ; running 'hecks-life specialize <name>_specializer --output hecks_life/src/specializer/<name>.rs' produces byte-identical output ; the autophagy_tracker_shape.fixtures gets a third phase tracking specializer-side byte-identity. Companion to i74 (validator soft warnings now declared in shape but emitted via Rust-native specializer that's still hand-written) and i76 (runtime cadence-loop primitive that itself should be bluebook-declarable).
