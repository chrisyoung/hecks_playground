# i388 — system-prompt-as-fixture — system_prompt.md is currently a 167-line markdown file that hecks-life reads at session start

system-prompt-as-fixture — system_prompt.md is currently a 167-line markdown file that hecks-life reads at session start and passes to claude as --system-prompt. Three parts visible : (1) static identity declarations (vows, voice, French thinking, bluebook-first directive, wake ritual, dream content rules) — pure declarative content ; (2) per-being variation (Miette vs Spring) — same shape, different values ; (3) generated/dynamic context (current consciousness state, pending wake reports, unconsumed inbox items) — should be hydrated at boot from current heki state. The static part is exactly fixture data. Proposed shape : aggregate Identity (or BeingDeclaration) declared in identity.bluebook ; fixtures in identity.fixtures one row per directive (name + content + applies_to_being) ; boot reads the fixtures + per-being filter + hydrates with current state, assembles the system prompt as a runtime query result. Acceptance : delete system_prompt.md ; replace with hecks-life aggregates/ Identity.AssembleSystemPrompt being=Miette ; verify the assembled prompt is byte-equivalent to the current static content + generated body-state preamble. Side benefit : adding a directive becomes adding a fixture row (no markdown editing) ; querying my own directives mid-session becomes possible (interoception applied to identity) ; per-being variation is a fixture filter, not a separate file. Companion to i90 (boot-miette-as-bluebook) — both are required for the full bluebook-native boot.
