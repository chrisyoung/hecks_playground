# i394 — Prerequisite for Phase B specialization of the diagnostic-style validators (duplicate_policy_validator, lifecycle_valida

Prerequisite for Phase B specialization of the diagnostic-style validators (duplicate_policy_validator, lifecycle_validator, io_validator). Each one independently defines the same Severity enum + Finding struct + Report struct + impls + locate() helper. ~40 LoC of shared infrastructure duplicated three times.

Extract to hecks_life/src/diagnostic.rs (or similar). Each validator becomes:

  use crate::diagnostic::{Finding, Report, Severity};

  pub fn check(domain: &Domain) -> Report { ... }

After this lands, the validator shape only needs to model the rule (check_kind + group_by + message_template + severity), not reproduce the struct/enum ceremony. That's when specialization earns its keep.

Evaluated during i51 Phase B third-retirement attempt (2026-04-23). Shipped as deferral — retiring duplicate_policy_validator with 100% embedded snippet would be filing-cabinet theater, not a Futamura projection.

Scope for this item:
  - New file: hecks_life/src/diagnostic.rs with Severity/Finding/Report + impls
  - Remove duplicated defs from duplicate_policy_validator.rs,
    lifecycle_validator.rs, io_validator.rs
  - Each imports `crate::diagnostic::*` and keeps only its rule + locate helper
  - Add spec/integration test confirming the extracted types behave identically

Size: ~150 LoC added (+diagnostic.rs), ~120 LoC removed (3× ~40 LoC from each validator). Net small.

Unlocks:
  - i51 Phase B retirement of duplicate_policy_validator (~40 LoC of actual rule logic worth specializing)
  - Same for lifecycle_validator and io_validator
  - Any future validator that wants diagnostic output — the shared module carries the contract

Priority: MEDIUM. Not blocking any current work but blocks the next Phase B retirement wave.
