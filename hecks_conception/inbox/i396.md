# i396 — validator-warning-bluebook-size-as-multi-domain-signal — Add a soft warning in validator_warnings.rs that flags bluebook

validator-warning-bluebook-size-as-multi-domain-signal — Add a soft warning in validator_warnings.rs that flags bluebooks above a threshold as candidates for multi-domain split. Origin: 2026-04-25 hour with Chris ; the duplicate-command-name pressure on dream_review.bluebook (Gap.Record + Edit.Record collision forcing rename to RecordGap/RecordEdit) was a smell that those aggregates belong in separate bounded contexts. Chris's framing: 'a large file is a signal — of course in bluebook it might make sense to have a big file but only if it really only covers one concern.' Soft warning, not error. Existing warnings (aggregate_count_warning at 7, mixed_concerns_warning at 5+ disconnected clusters) are first-pass approximations. The new warning is the strictest signal — raw size — and matches Chris's historical 200-line rule from the Ruby project. Two implementation paths: (a) approximate from IR using structural-unit count (aggregates + attributes + commands + policies + transitions), threshold ~50, no source file read needed ; (b) add source_path to the Domain IR struct, read the actual file, count non-doc-comment lines, threshold 200. Path (a) ships fast and is IR-pure (matches existing validator style). Path (b) gives literal LoC parity with the Ruby rule but touches parser + IR + every consumer. Recommended: (a) first as a soft signal, (b) later if (a) misses the cases that matter. Message shape: probing not prescriptive — '⚠ bluebook X has N structural units — is this really one concern, or is it two?' Concrete deliverables: (1) new fixture row in validator_warnings_shape.fixtures with check_kind=count_threshold + threshold=50 + message_template + body_strategy=templated ; (2) extend the templated specializer to handle structural-unit-count as a primitive (or use embedded snippet_path) ; (3) regenerate validator_warnings.rs via hecks-life specialize ; (4) byte-identity test ; (5) verify the warning fires on dream_review.bluebook at its current pre-split size + does NOT fire after the three-bluebook split. Companion deliverable: split dream_review.bluebook into dream_review (Cycle), dream_extraction (Gap), dream_synthesis (Edit). Three small bluebooks, each one concern, each ~70 lines, no Record-renamed collisions. The split is the first beneficiary of the warning — and the demonstration that the warning prompted the right action.
