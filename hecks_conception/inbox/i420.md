# i420 — then-set-shorthand-when-attr-name-matches — DSL ergonomics : `then_set :filed_as` with no `to:` clause should automatica

then-set-shorthand-when-attr-name-matches — DSL ergonomics : `then_set :filed_as` with no `to:` clause should automatically resolve to the matching command attribute :filed_as when the names match. Today every then_set requires the explicit `to:` even when the attribute and the field have the same name : `then_set :filed_as, to: :filed_as` ; `then_set :recorded_at, to: :recorded_at` ; etc. Most commands in the corpus pass through 5-15 attributes one-to-one — that's 5-15 lines of pure noise per command. Proposed shorthand : if `then_set :foo` is called without `to:`, the parser looks for an attribute named :foo on the same command and treats it as `to: :foo` ; falls through to current behavior (or errors with a clear message) if no matching attribute exists. The shorthand removes the noise without changing semantics. Aggregates that already use explicit `to:` continue to work unchanged. Pattern surfaced today (2026-04-26) while writing dream_wish.bluebook MarkFiled — every then_set was a self-referential repeat. Same DSL-shorthand family as : `reference_to(DreamWish)` (already shorthands the bare-class form) ; `attribute :foo, String` (already infers default-nullable). The DSL keeps tightening.
