# i450 — Design: make mood + fatigue_state read-time computed views of pulses_since_sleep, not persisted independent fields.

Design: make mood + fatigue_state read-time computed views of pulses_since_sleep, not persisted independent fields.

Spun out from the closed i21 (fatigue_state ladder — quick fix) and i34 (refreshed+tired contradiction — bandaged).

Current model:
  - mood.current_state and fatigue_state are persisted strings.
  - They evolve via independent command ladders (RefreshMood on wake, WalkFatigueTo* on pulse threshold crossings).
  - Independent state means contradictory combinations (refreshed + tired, focused + exhausted) slip through whenever the ladders get out of sync.
  - Patching with cross-aggregate policies (e.g. RecalibrateMood on WalkFatigueToTired) adds surface area and more ways to drift.

Proposed:
  - Persist only the inputs: pulses_since_sleep, last_wake_at, recent_activity markers.
  - Derive mood.current_state and fatigue_state at read time from a single pure function of those inputs.
  - Impossible-to-drift: no cross-aggregate policies needed, no ladders to keep in sync.
  - Status bar always coherent (directly addresses i35 coherence checker concerns — several invariants become tautologies).

Implementation sketch:
  - Body aggregate keeps pulses_since_sleep + last_wake_at as before.
  - Remove mood.current_state and fatigue_state as persisted attributes.
  - Add a view layer (capability or Rust projection) that computes both on demand from current body state.
  - Statusline + any consumers read the view, not the heki field.
  - Migration: existing mood.heki / heartbeat.heki records keep their old fields, view ignores them.

Risks:
  - Consumers that mutate mood directly (e.g. MoodLifted, RefreshMood) lose their knob. Audit callers.
  - Some transitions (wake = refreshed) genuinely want an event, not just a computed change — preserve the events, drop the persisted state.

Dependencies:
  - i35 status-bar coherence checker benefits from this but does not block it.
