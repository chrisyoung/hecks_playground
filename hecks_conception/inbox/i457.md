# i457 — validator-morphology-as-bluebook — The validator's word-classification logic (is_not_verb, suffix tables, exception list

validator-morphology-as-bluebook — The validator's word-classification logic (is_not_verb, suffix tables, exception list) lives as hand-written Rust in hecks_life/src/specializer/validator_morphology.rs. Adding a new rule (e.g., verb prefixes : en-, dis-, re-, un-, pre-, de-, mis-, over-, under-, out- + adj-suffix → verb) requires editing that Rust file. That's the wrong layer. The classification rules should be bluebook : morphology.bluebook (or extension to validator_shape) declares the algorithm declaratively (suffix tables, prefix tables, exception aggregates, decision tree), and the runtime interprets it. Adding a new rule becomes adding a fixture row, not editing Rust. Surfaced 2026-04-25 when Chris asked 'why does Enable look like an adjective?' — the answer required prefix awareness that the current Rust hardcodes around. Two layers : (a) extend validator_shape.fixtures to declare the algorithm not just the data ; (b) refactor the specializer to interpret the declared algorithm rather than hardcoding it. Connects to i75 (dream-shells-to-bluebook sweep) but is its own arc — extending the bluebook DSL with morphology-rule-declaration capability.
