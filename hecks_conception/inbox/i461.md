# i461 — Defer hecks_life/src/io_validator.rs Futamura retirement until the runtime-smoke / Runtime::boot layer has IR support.

Defer hecks_life/src/io_validator.rs Futamura retirement until the runtime-smoke / Runtime::boot layer has IR support.

Context: after retiring duplicate_policy, lifecycle (both post-i59), the three-validator wave in i59 included io as target #3. Re-reading against the Phase A/B retrospective rule ("specialize where it earns its keep"), io fails the test:

  File:        265 LoC post-i59 (already minus 20 LoC of diagnostic boilerplate)
  Declarative: ~40 LoC of consts (IO_COMMAND_PREFIXES, IO_EVENT_NAMES, IO_CATEGORIES, CREATE_PREFIXES) + ~20 LoC of static_scan + 10 LoC helpers
  Sui generis: ~120 LoC of runtime_smoke (Runtime::boot, dispatch loop, RuntimeError match, synthesize_attrs)
  Hybrid:      scan_command (30 LoC, mix of const-driven + control flow)

The runtime_smoke layer is the wall. It boots a pure-memory Runtime, plans dispatch from a borrowed Domain, synthesizes per-attribute sample values, dispatches every command, and matches against every RuntimeError variant. None of that compresses to a check_kind primitive or a simple template. Forcing it into `body_strategy: embedded` snippets would reproduce the existing code without gain — classic filing-cabinet theater the retrospective warns against.

What this retirement WOULD produce:
  - 4 const fixtures (real value — adding an IO prefix becomes a fixture edit)
  - 4-7 helper rows with body_snippet embedded
  - partitioned_with_strict report_kind (cheap; just a new template in the base class)
  - One giant rule_body_snippet for runtime_smoke (the heart, still Rust)

Net: net complexity up, Futamura gain marginal.

What unblocks it:
  Grow L3 dispatch_ir / L4 runtime_ir primitives that can describe:
    - "dispatch every command with synthesized inputs"
    - "match each RuntimeError against a known-benign set"
    - "collect findings from runtime vs static layers"

That's Phase C or later IR work. Tracked now so io_validator doesn't get retrofitted under pressure; when the IR is ready, the retirement becomes straightforward.

Meanwhile:
  - io_validator stays on main, hand-written
  - specializer.fixtures keeps the "IoValidator" target at ship_status: not_started (already there)
  - The Diagnostic base class is ALREADY partitioned_with_strict-aware (scaffolded in lifecycle retirement as placeholder)
  - When this item unblocks, the retirement is a small PR: add io shape + fixture + subclass shell

PRIORITY: LOW. Nothing is waiting on this.
