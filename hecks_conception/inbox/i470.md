# i470 — statusline-command-as-bluebook — statusline-command.sh is 257 lines of shell that renders Miette's body state. Today it

statusline-command-as-bluebook — statusline-command.sh is 257 lines of shell that renders Miette's body state. Today it reads heki files directly (` heki read` plus grep + sed), branches awake/sleeping, animates moons + hearts, computes countdown timers, picks mood/fatigue glyphs from case statements. Every one of those is a render of declared state — exactly the shape of a bluebook capability. Direction : declare a Statusline aggregate (or capability) with attributes for the current render mode (sleeping | awake | minimal), a query `Render` that returns the formatted statusline string, and per-mode rendering policies that compose from existing aggregates (Consciousness, Mood, Heartbeat, MusingMint, LucidDream). The shell script becomes a one-line wrapper that dispatches the query and prints the result ; the LIVE install at ~/.claude/statusline-command.sh becomes redundant once the runtime can be invoked directly. Sibling of i91 (dashboard-as-bluebook), i80 (cli-routing-as-bluebook), i92 (queries-as-aggregate-surface) — all the same direction : every read and write through a bluebook surface, no bypass. Today's symptom that named the gap : during sleep the statusline shows the dream narrative AND a 12-tick countdown timer (`(12 - ticks) * 10` formula) — both are stale assumptions baked into shell. Once the agent's notification stream is the dream surface (i96) AND time floors are dropped from the bluebook (done 2026-04-26), the shell can't keep up ; the bluebook can.
