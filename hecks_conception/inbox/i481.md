# i481 — StoreHouse runtime handler : Dispatch.Route

The storehouse/dispatch.bluebook declares Dispatch.Route — the bus
itself — but no runtime handler exists yet. This is the most
substantial of the three handlers and the heart of StoreHouse.

## Today

Each surface dispatches its own way :

  - **Spring** parses `Domain.Aggregate.Command param:value` in
    `summer/src/main.rs` and shells `hecks-life run <bluebook>
    --command <Cmd>` directly.
  - **Glass** (`.claude/commands/glass.md`) calls `hecks-life heki
    append` with hand-built records, bypassing the bluebook command
    path entirely.
  - **My system prompt** says `hecks-life aggregates/
    Consciousness.WakeUp` — same per-bluebook shell-out shape as
    Spring.

Three implementations of the same idea, none routing through a bus.

## Tomorrow

  1. Add a Route dispatcher for the Dispatch aggregate. Inputs :
     `phrase` (Aggregate.Command or Domain.Aggregate.Command) +
     `params` (JSON object string).
  2. Resolve the phrase via Lexicon.Lookup (i480 must land first, or
     implement Lookup inline against the same lexicon source).
  3. Validate params : the lexicon's resolved target carries the
     command's attribute list. Each required attribute must be
     present in params with a coercible type.
  4. Dispatch through the existing per-bluebook runtime path (the
     same code path `hecks-life run <bluebook> --command` exercises),
     passing the typed params.
  5. Capture the emitted event and re-emit as Dispatched with payload
     `{ phrase, params, target_event_name, target_event_payload }`.
  6. On any validation failure, surface a runtime error to the caller
     ; do NOT emit DispatchFailed (the command never reached dispatch
     phase, so no bluebook-level failure event).

## Acceptance

  - `hecks-life run storehouse/dispatch.bluebook --command Route
    --phrase "Consciousness.WakeUp" --params '{}'` succeeds and emits
    Dispatched (with WokenUp captured as the target event).
  - Same dispatch with a malformed phrase fails before the target
    runs, with a clear error message.
  - The target aggregate's heki reflects the dispatch (i.e., dispatch
    really happened, the event isn't synthesised).

## Open questions for design

  - **Param coercion.** JSON is loose ; the target command's
    attributes are typed. Does Route coerce string→integer when the
    target expects Integer, or does it require the JSON to already be
    typed? First chapter : require typed JSON. Coercion is a follow-up.
  - **Dispatched event payload.** Does it carry the full target
    event's data, or just an opaque pointer (event id + name)?
    Carrying the full payload is more useful for cascade visibility
    but couples Dispatched to every possible target shape. First
    chapter : carry the full payload.
  - **Cross-aggregate references in expects.** The bluebook says
    `expects { Lexicon.Lookup(phrase: phrase).present? }`. Whether
    the runtime evaluates this at dispatch time depends on i255
    enforcement state (per i478). If it doesn't, Route dispatches
    through Lookup imperatively in its handler instead.

Companion to i478 (StoreHouse design), i480 (Lexicon.Compile),
i482 (Query.Read).
