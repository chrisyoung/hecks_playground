# i484 — StoreHouse runtime : generic bluebook interpreter, not per-aggregate hand-written runners

The StoreHouse first chapter (commit 4e5f9a99) landed three bluebooks
declaratively : `lexicon.bluebook`, `dispatch.bluebook`, `query.bluebook`.

i480, i481, and i482 were filed as runtime-handler cards — one
hand-written `.rs` runner per StoreHouse aggregate, following the
precedent of `run_boot/`, `run_restructure/`, `run_status/`. Each
would have shipped under the same `[antibody-exempt: ... retires
under capability_runner_shape's specializer ...]` marker the existing
runners carry.

**Chris pivoted on 2026-05-07** : that path accumulates debt against
the very direction StoreHouse is going. If StoreHouse's `Dispatch.Route`
is the bus, adding three more hand-written runners alongside `run_boot/`,
`run_restructure/`, `run_status/`, `run_serve/`, `run_loop/`, `run_clock/`
… is exactly what StoreHouse exists to obviate.

## The pivot

Don't ship StoreHouse as per-aggregate `.rs` runners. Instead :

  - **The bluebooks at `hecks_conception/storehouse/` are the contract.**
    They already shipped (4e5f9a99) and are validated.
  - **The runtime grows a generic dispatch path** that reads any
    bluebook's IR and routes calls : input phrase + params → resolve
    target → validate → invoke → capture event → emit. ONE handler,
    not N.
  - **Once the generic interpreter exists**, every existing per-aggregate
    runner (`run_boot/`, `run_restructure/`, `run_status/`, the seven
    others) retires through it. StoreHouse becomes the bus that ate
    the runners.

This honours bluebook-first more strictly and stops the accumulation.

## What this card lands

A generic bluebook-driven dispatcher in the runtime that satisfies
StoreHouse's three commands :

  - `Lexicon.Compile` — walks the conception, indexes phrases, emits
    `LexiconCompiled` with `{ compiled_at, phrase_count }`. The
    existing `hecks-life lexicon` subcommand does most of this work
    already ; the new dispatcher just wires its output through the
    standard event-emit pipeline.

  - `Dispatch.Route` — the bus itself. Resolve phrase via Lexicon.Lookup,
    validate params against the target command's attributes, dispatch
    through the existing per-bluebook runtime path, capture and re-emit
    as `Dispatched`.

  - `Query.Read` — parse the dotted path into (aggregate, attribute),
    locate the heki via `heki::path_for_lookup`, project the named
    attribute, emit `ValueRead` with the flattened value.

But — and this is the reframing — these three handlers don't get
separate `.rs` files. They live as branches in **one** dispatcher
that routes by aggregate name + command name from the bluebook IR.
Every other aggregate's commands flow through the same dispatcher.

## Implementation order

1. **Carve the dispatcher seam.** Find where per-bluebook commands
   today get routed (likely in `rust/src/main.rs`'s `run` subcommand
   or a sibling). Extract a generic dispatcher that takes
   `(domain, aggregate, command, params)` and dispatches against the
   loaded IR.
2. **Three branches.** Within the dispatcher, branch on
   `(aggregate.name, command.name)` for Lexicon.Compile,
   Dispatch.Route, Query.Read — these three need bespoke logic the
   generic IR walk can't supply (lexicon walking, target dispatch,
   heki attribute projection). The branches are tiny — most logic
   sits in shared helpers.
3. **One file, well-bounded.** Likely `rust/src/run_storehouse.rs`
   (or `rust/src/storehouse_dispatcher.rs`) with three entry points
   inside. Single `[antibody-exempt: ... ]` marker. No multiplication.
4. **Wire into the run subcommand.** When `hecks-life run
   storehouse/<book>.bluebook --command <Cmd>` is invoked, route to
   this dispatcher.
5. **Tests.** One per command, plus a "phrase routes through Route
   end-to-end" integration.

## Out of scope for this card

The bigger refactor — retiring `run_boot/`, `run_restructure/`,
`run_status/`, etc. through StoreHouse — is a separate arc. This card
just establishes the seam. Existing runners stay where they are until
their own retirement cards land.

## Why this honours the Standards

- **Bluebook first** — the bluebooks are the contract ; the runtime
  is one generic walker, not N specialised runners
- **Big refactors get committed to** — instead of three new runners
  that retire later, one dispatcher that doesn't multiply the surface
- **No technical debt** — the kind we'd accumulate with three more
  hand-written runners is exactly what the antibody hook is trying
  to teach us not to do
