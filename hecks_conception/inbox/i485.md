# i485 — service_task.bluebook : `failed_reason` referenced where `failure_reason` is declared

Surfaced 2026-05-07 by the i479 fix : once the lifecycle validator
correctly recognised the i255 bare-VO form, it ran cleanly against
the conception and bin-buddy. Most bluebooks pass ; one doesn't.

`/Users/christopheryoung/Projects/bin-buddy/aggregates/service_task/service_task.bluebook`
declares :

```
attribute FailureReason  # snake-cases to :failure_reason
```

But a `then_set` (or similar) clause references `:failed_reason` —
genuine name-mismatch typo. Pre-i479, the validator silently dropped
the bare-VO attribute and the mismatch was invisible. Post-i479, it
shows up correctly.

## Resolution

One-character fix : either rename the VO to `FailedReason` (snake-cases
to `:failed_reason`) or update every reference from `:failed_reason`
to `:failure_reason`. The latter is more conventional ("failure"
reads better than "failed" as a noun) ; the former is what the
references already expect. Trace which is more correct in the
domain.

bin-buddy's pre-commit doesn't run `hecks-life check-lifecycle`, so
the bug shipped in bin-buddy and is invisible until that gate is
turned on there too. Worth adding the same hook to bin-buddy.

## Companion

i479 — the validator fix that surfaced this. Without that fix this
would have stayed silent.
