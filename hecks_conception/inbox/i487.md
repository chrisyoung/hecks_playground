# i487 — Ruby `role(name)` arity is the parity blocker for the new `role Role, as: Agent` form

Surfaced 2026-05-07 by the i483 agent while drafting the demo
bluebook (`framework/audit/dispatch_audit.bluebook`). The Ruby
parser at `ruby/hecks/dsl/command_builder.rb:249` accepts only one
positional argument for `role` :

```ruby
def role(name)   # one positional, no kwargs
  @role = name
end
```

The new `role Role, as: Agent` form passes a positional plus a
kwarg — Ruby crashes (ArgumentError), Rust silently accepts (it
doesn't lift the new form into the IR yet either). Asymmetry :
"Ruby crashes loudly ; Rust ignores quietly."

This is what listed `dispatch_audit.bluebook` as a known-drift
entry in the i483 commit — Ruby parity broken until the arity
opens up.

## Resolution

When the parser-support card lands for the new `role Role, as: Agent`
form, both parsers need updating in lockstep :

  - **Ruby** : extend `command_builder.rb`'s `role` method to accept
    `(role_type, as: alias_name)` — likely splat-args + kwargs.
  - **Rust** : update `parse_blocks.rs` (or its specializer source)
    to recognise the new form and lift it into the IR's role field
    with the alias.

Easy to forget the Ruby side in the moment because Rust's silence
hides the asymmetry until parity tests run.
