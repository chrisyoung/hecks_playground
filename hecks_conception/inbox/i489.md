# i489 — Cross-aggregate reference validation : Role.identified_by :name + Agent.role_name

Surfaced 2026-05-07 by the i483 agent while drafting Agent + Role.
Role is `identified_by :name`, so role-name is the natural key. The
storage layer enforces uniqueness — two Roles named "Operator"
collide ("Operator" being the canonical role, this is fine).

But every Agent's `Bind` command carries a string `:role_name`
intended to point at a real Role. The validator can't enforce
that the string corresponds to an existing Role record — there's
no cross-aggregate reference check today.

This is a sibling concept to i491 (cross-aggregate command-name
uniqueness) — both surface the same gap : the framework knows
about IR-local symbols, doesn't know about cross-aggregate
references in attribute values.

## Resolution

Once the parser supports the new role form (i487), a cross-aggregate
reference validator could check :

- Every command attribute typed as a foreign-aggregate natural-key
  (e.g. `attribute :role_name, String` referring to `Role.name`) is
  declared with a reference annotation, e.g.
  `attribute :role_name, references: Role.name`
- At dispatch time, the validator confirms a record exists with
  that natural key in the target aggregate
- Generators emit foreign-key constraints in SQL targets and
  existence checks in Ruby/Rust runtimes

First chapter scope : just the validator. SQL FK + runtime check
are follow-ups.
