# i490 — Converge `actor` / `role` / `agent` into one type system

Surfaced 2026-05-07 by the i483 agent. The DSL has three parallel
concepts today :

  - **`role "Chris"`** — string label on a command (the i483 starting
    point ; lifted into `role Role, as: Agent` by that card)
  - **`actor "Customer"`** — domain-level declaration
    (DSL reference §Actors). Used informally for documentation and
    sometimes wired into `port :role do allow ...` access control.
  - **Agent** — the new framework aggregate i483 conceived. Typed,
    referenced, audited.

Three concepts, partial overlap, no canonical winner.

## Resolution

Pick Agent as the canonical noun (i483 already implicitly did this).
Migrate :

1. **Every `role "string"` declaration** → `role Role, as: Agent`
   form. Mechanical sweep, one PR per anatomical cluster (per i112
   convention). Already named in i483.
2. **Every `actor "Name"` domain-level declaration** → an Agent
   record (or seed in the framework Agent aggregate). The actor's
   name becomes the Agent's name ; the actor's "kind" (customer,
   admin, etc.) maps onto Agent.kind or onto a Role binding.
3. **Every `port :role do allow ...` access control declaration**
   → expressed as a `rule` on the relevant command, referencing
   `agent.permissions` or `agent.role.name`.

After convergence : one type system for who-is-acting. The DSL
reference removes `actor` as a separate keyword (or notes it as
deprecated in favour of Agent records).

This is bigger than it looks because `actor` shows up in :
- Domain-level declarations
- Port access control
- Some generator templates (likely)
- Documentation

Worth a separate planning conversation before the sweep starts.
