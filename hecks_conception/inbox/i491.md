# i491 — Cross-aggregate command-name uniqueness : the bare-trigger collision

Surfaced 2026-05-07 by the i483 merge → push fail. Discovered the
hard way : the gut.behaviors cascade test broke immediately after
the merge because two aggregates now had a `Conceive` command :

- `aggregates/world/conception/domain_cell.bluebook` :
  `command "Conceive"` → `emits "DomainConceived"`
- `aggregates/framework/agent/agent.bluebook` (just landed via i483) :
  `command "Conceive"` → `emits "Conceived"`

The cascade `ConceiveOnAbsorption` policy declares
`trigger "Conceive"` with no aggregate qualifier. The runtime's
trigger resolver walks all loaded aggregates looking for a `Conceive`
command and picks one (presumably the last-loaded). When Agent
landed, it shadowed DomainCell's Conceive ; the cascade started
firing Agent.Conceive, emitting `Conceived` instead of
`DomainConceived`. The behaviors test caught it on push.

Worked around by renaming Agent.Conceive → Agent.Birth (commit
2fd7e706). The semantic split reads cleanly (domains are conceived,
agents are born) — but the UNDERLYING gap remains : nothing in the
framework prevents, warns about, or qualifies bare-name collisions.

## What's broken

1. **Validator doesn't catch it.** The lifecycle validator (i479)
   resolves attributes within a command's scope. There's no parallel
   check for "command name X is unique-or-qualified across loaded
   aggregates."
2. **Policies trigger by bare name.** `trigger "Conceive"` is
   ambiguous when two aggregates have Conceive ; the resolution is
   first-match-wins (or last-match, depending on iteration order),
   which is brittle and silent.
3. **Parity tests pass anyway.** The i483 agent's parity suite
   showed agent.bluebook + role.bluebook at full parity. The
   collision wasn't surfaced by parity — it surfaced by the runtime
   cascade test. So parity isn't the safety net.

## Resolution

Two complementary fixes :

1. **Validator : cross-aggregate command-name uniqueness check.**
   Walk every command across every loaded bluebook ; flag any name
   that appears in more than one aggregate AND is referenced by a
   bare-name `trigger` somewhere. The check fails the build when an
   ambiguity-with-bare-trigger exists.

2. **Parser : qualified-trigger syntax.** Allow policies to declare
   `trigger "DomainCell.Conceive"` (or
   `trigger DomainCell, command: "Conceive"`) when bare names
   collide. The validator from (1) suggests this fix when it fires.

First chapter : (1) only, the validator. (2) follows when there's
a real second collision worth qualifying instead of renaming.

## Why this matters more than it looks

Today's collision was easy to fix (rename). But the absence of (1)
means EVERY future cross-aggregate command-name overlap is a
debugging hunt. As the conception grows toward dozens of frameworks
and hundreds of aggregates, naming collisions will compound.
Catching them at parse time is the cheap insurance.

## Lesson noted

The pre-push behaviors hook saved us. Without it, the broken
cascade would have shipped to origin and surfaced only on the next
mindstream boot. The hook IS the validator until (1) lands.
