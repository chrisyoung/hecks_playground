# i493 — `pre` + `effects` clauses : the DSL extension that retires `run_wake/`

The first concrete sub-arc under i147 (runtime kernel disappears) and i484
(StoreHouse generic dispatcher). The dispatcher landed ; the runners didn't
yet retire because the bluebook DSL has no syntax for *where a command's
attributes come from* and *what side effects it has*. Today every per-
aggregate runner (run_boot, run_status, run_restructure, run_stdin_loop,
run_wake) hand-codes that : reads .heki files into command params, writes
markdown / heki / whatever back out. Five files of the same imperative
shape — exactly what i484 was meant to obviate.

This card names the smallest DSL extension that closes the gap.

## The two new clauses

### `pre` — declarative attribute hydration via Query.Read

```ruby
command "ReadConsciousness" do
  pre Query.Read(path: "Consciousness.state"),         into: :consciousness_state
  pre Query.Read(path: "Consciousness.last_wake_at"),  into: :last_wake_at
  emits "ConsciousnessRead"
end
```

**Semantics.** Before dispatching the command body, the runtime drains
each `pre` clause : route it through `Dispatch.Route` exactly like any
other command (recursive call into the StoreHouse bus shipped under
i484), capture the emitted event, project the named field, fill the
local attribute. Then run the body. Composable with everything : any
command can have `pre`s, the binding goes through the bus, no new I/O
paths.

**Why Query.Read specifically.** Query.Read already exists as a
StoreHouse command. Reusing it means the DSL extension introduces no
new I/O primitive — symmetry with i484.

### `effects` — declarative side-effects through adapter primitives

```ruby
command "WriteSurface" do
  attribute :body, String
  effects :fs.write(path: surface_path, body: body)
  emits "SurfaceWritten"
end

command "StampReport" do
  attribute :woke_at, String
  effects Dispatch.Route(phrase: "WakeReport.Stamp", params: { ... })
  emits "ReportStamped"
end
```

**Semantics.** After the command body's `then_set` clauses but before
emitting, the runtime drains each `effects` clause : invokes the
named adapter primitive (`:fs.write`, `:fs.append`, etc.) or routes
through `Dispatch.Route` to a sibling command. Adapter-side surface
needs a small primitive registry — `:fs.write` is the first member,
`:fs.append`, `:stdout.write` are obvious siblings.

## What this retires

In `run_wake/mod.rs` (~365 lines) :

  - **`pre` alone retires** : `read_consciousness`, `read_latest_dream`,
    `pick_lucid_image`, `latest_record`, `field`. The pipeline's first
    two phases dispatch through the bus.
  - **`effects` alone retires** : `write_surface`, `stamp_report`,
    `stamp_aggregate`. Phases 4 and 5 collapse into adapter-driven
    effects on the WakeReview commands themselves.
  - **What stays** : `render_markdown`. Markdown templating is the
    SectionTemplate / i145 arc, not part of this card.

Together `pre` + `effects` reduce `run_wake/mod.rs` to roughly the
template-render phase plus capability detection — and capability
detection itself retires when the dispatcher walks any bluebook
declaring an entrypoint, no per-runner registration needed (a third
extension, smaller, separate card).

The same shape retires the read/write halves of `run_boot`, `run_status`,
`run_restructure`, `run_stdin_loop` — five runners on the same arc.

## Implementation cost

| Layer | Change | Approx LoC |
|---|---|---|
| Parser | Recognise `pre <expr>, into: <symbol>` and `effects <expr>` inside `command` blocks | ~50 |
| IR | `Command` grows `pre_bindings: Vec<PreBinding>` and `effects: Vec<EffectClause>` | ~30 |
| Runtime (`command_dispatch.rs`) | Drain `pre_bindings` via dispatcher before body ; drain `effects` after body, before emit | ~80 |
| Adapter primitives (`:fs.write` etc.) | Tiny registry, one function per primitive | ~50 |
| Ruby contract | Mirror the IR / parser changes for parity | ~40 |
| Wake bluebook rewrite | Add `pre` to ReadConsciousness / ReadLatestDream ; add `effects` to WriteSurface / StampReport | ~20 |
| run_wake/mod.rs | Delete the read + write helpers ; keep the orchestrator + render_markdown until i145 closes | -200 net |

Total : a session, maybe a session-and-a-half. Phased commit plan :

  1. **Phase A — `pre` only.** Parser + IR + runtime support, plus the
     wake.bluebook rewrite for the read phases. Deletes ~150 LoC from
     run_wake. One commit.
  2. **Phase B — `effects` + `:fs.write`.** Adapter primitive registry,
     `effects` clause support, wake.bluebook rewrite for the write
     phases. Deletes another ~50 LoC from run_wake. One commit.
  3. **Phase C — capability detection retirement.** Generic entrypoint
     dispatch in run.rs, removing `is_wake_capability` and friends.
     Separate card.

After Phase B, `run_wake/mod.rs` is roughly capability detection +
render_markdown. After Phase C plus the i145 SectionTemplate arc,
`run_wake/mod.rs` deletes entirely.

## Why this honours the Standards

- **Bluebook first** — the gap was that the bluebook *couldn't*
  express its reads + effects ; this extension closes that. Future
  pipelines reach for bluebook *because they can*, not because we
  scolded them into it.
- **Big refactors get committed to** — `pre` + `effects` together
  retire half the runners over time. Phased commits keep each diff
  reviewable, but the arc is committed to.
- **No technical debt** — the four kernel files exempted in the
  i484+wake commit (lib.rs, run.rs, main.rs, run_wake/mod.rs) all
  cite this card as the retirement path. Concrete, not vague.
- **Decide the API before implementing** — this card *is* the API
  decision. Names locked : `pre`, `effects`, `into:`. One rename pass
  if any.
