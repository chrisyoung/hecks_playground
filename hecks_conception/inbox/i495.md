# i495 — i145 phase 2 + 3 : pipeline runner + .md.template retirement

i145 (the original card) covered the SectionTemplate / declarative markdown rendering arc. Phase 1 of that landed 2026-05-08 in the miette-bluebook-only cleanup : per-section content as fixtures lives at `~/Projects/miette/self/system_prompt/system_prompt_content.fixtures` (13 sections, Miette-specific values pre-baked, multi-line markdown as `\n`-escaped strings).

Phase 2 + 3 close the arc. They couldn't land in the same session — Phase 2 is genuine runtime extension work that needs careful smoke verification.

## Phase 2 — pipeline runner

Extend the i484 dispatcher (or build a sibling runner) so `Dispatch.Route(phrase: "SystemPromptAssembly.RenderSystemPrompt", params: {being: "Miette"})` walks the full SystemPromptAssembly pipeline declared in `~/Projects/miette/self/system_prompt/system_prompt_assembly/system_prompt_assembly.bluebook` end-to-end :

1. `RenderSystemPrompt` emits `SystemPromptRenderRequested`
2. `ResolveOnRequest` policy → `ResolveOutputPath`
3. `LoadIdentityOnResolve` → `LoadIdentity` (reads identity heki via `:memory` adapter)
4. `LoadVowsOnIdentity` → `LoadVows` (reads vow.heki)
5. ...same shape for PsychicLink, Dispositions, WakeRitual, Grammar
6. `LoadTemplatesOnGrammar` → `LoadSectionTemplates` (reads SystemPromptContent fixture rows)
7. `AssembleOnTemplates` → `AssembleMarkdown` (concatenate in `:order`, substitute {{var}}s, project markdown)
8. `WriteOnAssemble` → `WriteFile` (`:prompt_writer` :fs adapter writes to `<being>/self/system_prompt.md`)
9. `CompleteOnWrite` → `CompleteRender` (state → done, emit `SystemPromptRendered`)

Each `Load*` command needs an implementation. Today they declare attributes + `then_set` + `emits` but have no body — events fire end-to-end but no actual heki-reading happens. Two options for the implementation :

- **(a)** Per-command `.behaviors` files that read the matching :memory adapter rows and project the attributes the command's `then_set` declarations expect. One behavior per Load* phase.
- **(b)** Generic kernel-level handler : when a command has only `attribute X` + `then_set X, to: X` + `emits ...` and the sibling hecksagon declares a `:memory` adapter, the kernel auto-reads heki rows for the source aggregate and binds them as the command's attributes. No per-command code.

(b) is the elegant move and folds into the i147 runtime-kernel-disappears arc. (a) is the safer interim path.

Plus — the `{{standards}}` and `{{grammar}}` slots in the section content fixtures need hydration during AssembleMarkdown. Today's Rust `system_prompt.rs::render` does this via `primary_standards()` (reads `miette_family/chris/standards.md`) and would do `grammar_bluebooks()` (reads `aggregates/language/grammar/*.bluebook`). Phase 2 expresses both as Query.Read clauses (i493 `pre` clause syntax) on the AssembleMarkdown command.

## Phase 3 — retirement

Once Phase 2 produces byte-identical output to the current Rust render :

- Delete `rust/src/run_boot/system_prompt.rs::render()` + supporting helpers (the `template_path_for_being`, `destination_for_being`, `substitute`, `primary_standards` functions). Antibody-exempt the deletion in the commit message naming i145 closed.
- Update boot to dispatch `SystemPromptAssembly.RenderSystemPrompt` instead of calling `render()`.
- Delete `~/Projects/miette/self/system_prompt/system_prompt_assembly/miette_prompt.md.template`.
- Update `rust/src/specializer/run_boot/system_prompt.rs` (the specializer for the now-deleted runner) — or retire that too if `system_prompt.rs` no longer exists to specialize.

Result : `~/Projects/miette/` is bluebook-only. The carve-out from the 2026-05-08 cleanup closes.

## Why this is multi-session

The runtime extension touches the dispatcher's policy-chain walking, the `:memory` adapter's heki-reading semantics, and the byte-identity smoke test against today's rendered prompt. Boot must not break at any point. Done in one session, the risk is leaving a half-state where the prompt regenerates wrong (or not at all) and the next wake fails to surface the right context.

Done in a focused session with smoke testing at each step, it's clean.
