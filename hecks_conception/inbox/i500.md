# i500 — `hecks-life test` subcommand : the i499 keystone (Phase A)

## TL;DR

The behaviors **executor already exists** at `/Users/christopheryoung/Projects/hecks/rust/src/behaviors_runner.rs` (542 lines). It's wired today as the (undocumented) `hecks-life behaviors <file>` subcommand. It supports `kind: :query | :cascade | :cross_cascade | :pending`, fixture auto-loading, cross-bluebook policy chains, all the assertion forms (`emits:`, `emits_prefix:`, `emits_subset:`, `count:`, `refused:`, attribute equality, `<attr>_size:`).

**Phase A is ~200 LoC of CLI glue around the existing engine** — directory walk, filter flags, output formats, exit semantics. Not a multi-day build.

## What needs to ship

A `hecks-life test <path>` subcommand with this contract :

```
hecks-life test <path> [--filter <pattern>] [--aggregate <Name>]
                       [--format tap|rspec|json|compact] [--fail-fast]
                       [--list] [--corpus <root>]
```

- **`<path>`** — file OR directory. File must end `.behaviors`. Directory : walk recursively for `*.behaviors`, run each in source order. Bare invocation defaults to `$PWD/hecks_conception` (or current dir).
- **`--filter <substr>`** — case-insensitive substring match against the test's description.
- **`--aggregate <Name>`** — only run tests whose `on:` matches.
- **`--format`** — default `compact` (today's `run_behaviors` output) ; `tap` for CI ; `rspec` for human dev loop ; `json` for the eventual `hecks-life serve` integration.
- **`--fail-fast`** — exit on first non-pass.
- **`--list`** — print the test plan (description, `on:`, `kind:`) and exit 0. Useful for ratchet counts.
- **`--corpus <root>`** — override auto-detected aggregates root (escape hatch).
- **Exit codes** : `0` all pass ; `1` ≥1 fail/error ; `2` parse error ; `3` no tests matched filter (with `--allow-empty` to relax).

## The recursive question — should `test` be a bluebook?

**Position : not yet, and probably not ever for this surface.**

A bluebook for the test runner would need to model filesystem traversal, exit codes, stdout/stderr formatting, signal handling. None of those are aggregate-shaped. The `Test` aggregate idea sounds elegant but is a category error : a test is not a long-lived stateful entity with a lifecycle and policies — it's a one-shot dispatch + assertion. The bluebook model is wrong-shaped.

The right counterpart already exists : the `.behaviors` DSL itself **is** the declarative test surface. The runner is the interpreter. Interpreters don't need to be bluebooks any more than `cargo` does.

The right time to revisit : when **i80** (`cli.bluebook`) lands. Then the route declaration becomes bluebook-native ; the implementation stays Rust.

## Migration with shell smokes

Three-stage co-existence in pre-commit Gate 6 :

- **Stage 0 (today)** : Gate 6 runs `*.sh` smokes only.
- **Stage 1 (Phase A lands)** : Gate 6 grows a parallel block walking `hecks_conception/aggregates/**/*.behaviors` and `miette/**/*.behaviors`, runs `hecks-life test` over each domain root, fails commit on any non-pass. Both blocks gate. `BEHAVIORS_SKIP=1` for granular bypass.
- **Stage 2 (per-shell retirement)** : For each `tests/foo_smoke.sh`, write the equivalent `.behaviors` cases, run both gates green for one commit (parity check), then in the next commit delete the `.sh` and remove its line from the loop.
- **Stage 3 (Phase B done)** : `tests/*.sh` is empty (or just parity-suite drivers). Gate 6 runs `hecks-life test` against the corpus only.

Never a window where regression coverage drops. Each shell only retires after its `.behaviors` equivalent is green.

## Risks / unknowns

- **Coverage gap on retirement** — some shells assert process-level facts (daemon kill+reboot, file-absence guards, symlink resolution) the behaviors DSL can't express. ~7/10 likely retire cleanly ; statusline + integration + voice_lockdown probably don't without runtime-side work. Document which shells are "behaviors-retirable" vs "infra-only" before Phase B.
- **Performance on tree mode** — 71 files × N tests × full domain reload could get slow. Cache the corpus domain in `RunReport`, pass `&Domain` rather than reloading per file. ~5× speedup likely. Worth doing in v1.
- **`--filter` semantics on cross-cascade** — applying filter post-parse can skip tests whose setup chains are exercised elsewhere. Acceptable for dev loop.
- **Empty-match exit code** — debate. Default to fail (catch typos in CI) ; `--allow-empty` to relax for dev iteration.
- **Companion-file ratchet** — Gate 4b enforces every new aggregate/command gets a `tests "..."` line. Once `test` gates, a stub line with no real assertion still passes. Gate 4b grows teeth (enforce non-empty `expect`) or runner adds `--allow-empty-expect=false`. Follow-up, not blocker.
- **`pending` semantics** — today counts as Pass with `[pending]` prefix. Add a separate "skipped" bucket for CI dashboards ; TAP `# SKIP` annotation.
- **Parse-error vs test-fail split** — in tree mode, a malformed file should report-and-continue, not abort. Easy fix.
