# i509 — statusline byte-snapshot suite retired ; reseed contract if it returns

## Context

i502 phase 3 called for regenerating the 14 fixtures in
`core/research/dream-study/test-gate/statusline_snapshot/fixtures/`.
Investigation showed the divergence is structural, not just rename
drift, so the suite was deleted entirely (i502's documented bailout
path).

## What changed under the renderer

Comparing fixture `expected_render` to live `hecks-life statusline`
output (against the same seeds) :

1. **Musings counter `💭 N` no longer rendered** for awake mode. Every
   awake fixture lost the `💭 <total_minted>` segment.
2. **Trailing `(global)` annotation** now appears after the inbox
   count : `✉️ {{INBOX}} (global)` instead of bare `✉️ {{INBOX}}`.
3. **Coherence-violation shield prefix** : the renderer prepends `⚠`
   to the *whole* line in some awake states it didn't previously
   (e.g. `awake_excited_alert`, `awake_flowing_focused`,
   `awake_fresh_wake`). The fixture for the explicit incoherence case
   (`minimal_coherence_violation`) shows the inverse — its expected
   `⚠` is now in a different slot.
4. **Retired fatigue rungs** : 4 fixtures use
   `fatigue_state: "alert" | "focused" | "delirious"`. These are gone
   from the ladder
   (`rested → limber → tuned → normal → tired → exhausted → spent`).
   `fatigue_icon_for` returns "" for the retired terms, so the
   renderer skips both icon and word — meaning those fixtures test a
   state the bluebook no longer recognises.

The 5 sleep_* fixtures still render byte-identically to their
expected output ; only the 9 awake/minimal fixtures broke.

## Why we deleted instead of regenerating

- Half the fixture seeds (the ones with retired rungs) need *seed*
  rewrites, not just `expected_render` rewrites. That requires picking
  current-ladder rungs that demonstrate the same edge cases — a
  judgement call about what's worth snapshotting.
- The structural changes above (musings, `(global)`, coherence shield
  scope) suggest the render contract is still in flight. Snapshotting
  it now would freeze drift-in-progress.
- `hecks_conception/tests/statusline_regression_smoke.sh` already
  covers the live contract end-to-end. The byte-snapshot suite was a
  defence-in-depth layer that hadn't run cleanly in weeks ; it was
  producing zero signal.

## What to do if/when the suite returns

1. Re-establish the contract first : pick the canonical rendering
   shapes worth snapshotting (sleep stages × awake mood/fatigue
   crosses × coherence-shield branch).
2. Reseed against the **current** bluebook — `rested`, `limber`,
   `tuned`, `normal`, `tired`, `exhausted`, `spent` for fatigue ;
   confirm the musings + `(global)` + shield scope behaviours are
   intentional before locking them.
3. Re-add `core/research/dream-study/test-gate/statusline_snapshot/`
   with a fresh harness + new fixtures. The old harness was sound
   (drives `hecks-life statusline`, normalizes wall-clock glyphs,
   byte-diffs) so it can be re-imported from git history if useful.
