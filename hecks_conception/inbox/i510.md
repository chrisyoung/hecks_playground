# i510 — Shell-adapter test verb in `.behaviors` runner

## TL;DR

Converting `spec/integration/shell_adapter_end_to_end_spec.rb` (3
examples, all integration) to `.behaviors` surfaced a structural gap :
the `.behaviors` runner has no shape for testing `:shell` adapters.

All three new behaviors at
`examples/shell_adapter/hecks/shell_demo.behaviors` are checked in
`kind: :pending` — they parse and run, but assert nothing real.

## What's missing

The `.behaviors` runner (rust/src/behaviors_runner.rs) only knows how
to dispatch **bluebook commands** through `Runtime::dispatch`. It does
not :

1. Load a sibling `.hecksagon` (so `adapter :shell, name: :foo, …` is
   never seen by the runner — only the `.bluebook` is parsed).
2. Expose a `tests :shell, name: "foo", attrs: {…}` form (parallel to
   the existing `tests "Cmd", on: "Aggregate"` form for commands).
3. Route through `runtime::shell_dispatcher::call` (the Rust mirror of
   the Ruby `ShellDispatcher` — already complete and parity-tested).
4. Recognize shell-result expect keys :
   - `output:`           → exact match against `Result.output` text form
   - `output_includes:`  → substring match against text/lines output
   - `exit_status:`      → integer match against `Result.exit_status`
   - `refused:`          → message match for unregistered-name path

## Why it matters

The Rust ShellDispatcher exists. The hecksagon parser reads
`adapter :shell, …` cleanly. The Ruby end-to-end spec proves the whole
chain works. The only thing keeping shell-adapter integration tests on
the Ruby runtime is a `.behaviors` runner gap — five-or-so functions
to wire the existing pieces together.

Per `CLAUDE.md` "Always use Rust runtime", the `.behaviors` framework
is the long-term home for this kind of integration test. Until the gap
closes, every new shell adapter (and there will be more — `:sms`,
LLM-call-out shape, daemon health probes) has no behaviors-level test
shape and stays on Ruby.

## Sketch

A behaviors test would look like :

    test "echo_args returns input via :text output" do
      tests :shell, name: "echo_args"
      input  msg: "hello"
      expect output: "hello\n", exit_status: 0
    end

Runner steps :

1. On suite load, locate sibling `.hecksagon` by stem (same trick as
   the existing source-bluebook lookup) ; parse via
   `hecksagon_parser::parse`.
2. When `tests :shell` is the verb, look up the named adapter on the
   parsed `Hecksagon`.
3. Substitute `input:` kwargs into the adapter's `args` via
   `runtime::adapter_io::substitute` (already wired in the Rust call
   path).
4. Invoke `shell_dispatcher::call(adapter, &attrs)`.
5. Compare the `Result` shape against the test's `expect:` map using
   the four new keys above.
6. `refused:` asserts the adapter lookup returned `None` and the
   expected message matches (parallel to the existing command-level
   `refused:` for `RuntimeError::GivenFailed`).
