# i514 — Retire-list : the 40 `kind: :pending` tests scrubbed tonight

## Why this exists

Chris's directive : "no pending tests — we want to be clean by the end
of the night." All 40 `kind: :pending` cases that the i499 conversion
pass had introduced are now deleted from the .behaviors corpus. This
inbox is the consolidated record of what was deleted, why each deletion
is safe, and what each item needs to come back.

## What got scrubbed (40 tests across 8 files)

### Group 1 — PM event-injection gap (17 tests)

**Files**
- `/Users/christopheryoung/Projects/miette/body/sleep/consolidation/consolidation.behaviors` (9 PM tests)
- `/Users/christopheryoung/Projects/miette/body/dream/dream.behaviors` (8 PM tests)

**Why pending** : the .behaviors runner only knows command dispatch
(`rt.dispatch_isolated(name, attrs)`). PMs observe events, not
commands. There is no `kind: :process_manager` mode that lets a
behaviors test inject `SleepEntered` / `RemEntered` / `PhaseElapsed` /
`DeepEntered` / `WokenUp` into the runtime so a PM can observe it.
Also `dispatches_subset` is not a recognised assertion key in the
runner.

**Coverage today** : the per-PM smoke shells (`tests/consolidate_smoke.sh`,
`tests/dream_content_smoke.sh`) drive these end-to-end via real
`run-loop --emit` + heki-growth assertions. Coverage is intact ; only
the bluebook-native mirror is missing.

**Re-add when** : i500 + a follow-up runner extension lands a
`kind: :process_manager` arm in `rust/src/behaviors_runner.rs` that
emits an event onto `rt.event_bus`, lets PM handlers fire, and reads
PM-instance state (the runner's `find` only walks aggregate repos
today, not pm_engine instances). At that point both files re-grow
their PM birth/transition + sweep tests against the same shell-smoke
specs.

**File**

(`ConcernNoted on irregular felt_quality also concerns`) covers the
production path through the policy. The deleted test exercised the
direct-create path which is not how the command is reached in the
field.

**Re-add when** : the runtime `then_set from: :kwarg` bug on
multi-attr CREATE commands is fixed. File a runtime-gap inbox if not
already filed.
