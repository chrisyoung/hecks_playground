# i515 — Move .behaviors close to source-of-truth bluebooks (post catalog-mirror retirement)

## What surfaced

Chris asked : *"can we move all the behaviours close to the bluebooks they test?"*

The triage agent inventoried 173 `.behaviors` files :
- **150 already colocated** — the same-stem `.bluebook` next to it IS the source-of-truth (or a same-purpose stub).
- **6 misplaced** but only mechanically — moving them to the source dirs breaks the runner's same-stem companion contract because the source dirs hold *aggregator* bluebooks (e.g., `bluebook/bluebook.bluebook` is one giant kernel file with 248 commands ; there's no `bluebook/cli.bluebook` for `cli.behaviors` to live alongside).
- **10 ambiguous** — touch aggregates from multiple non-mirror dirs ; need split decisions.
- **7 catalog-mirror-only** — aggregates exist *only* in mirror dirs ; no canonical aggregate dir to move toward.

The naive `git mv` failed when tried this session (parse errors on missing companion `.bluebook` at the new location).

## Why this is bigger than a relocation

The deeper structural truth : the catalog-mirror system doesn't fit "every .behaviors next to its source-of-truth bluebook" cleanly because :

1. **Aggregator bluebooks** like `bluebook/bluebook.bluebook` (248 commands) collapse 5+ subsystems (cli / hecksagon / persist / rails / workshop) into one file. To move `cli.behaviors` next to its source, the aggregator needs to retire and split into `bluebook/cli.bluebook`, `bluebook/hecksagon.bluebook`, etc. Then each `.behaviors` lands cleanly.

2. **Catalog mirrors** like `hecks_conception/catalog/appeal.behaviors` test ~30 aggregates from 10+ source dirs. The mirror collapses them ; the source-of-truth is fragmented across `bluebook/`, `tools/project_management/`, `cli/console/`, `cli/terminal/`, `discipline/restructure/`, `integrations/cloudflare_deploy/`, `aggregates/framework/agent/`, `aggregates/library/index/`, `miette/surface/`, `miette/mind/musings/`. Splitting requires per-cluster decisions about which behaviors land where.

3. **Catalog-mirror-only aggregates** (`Application`, `Law`, `Case`, `ChapterRegistry`, `NamingHelpers`, `Entry`, …) have NO source-of-truth bluebook — only the mirror exists. Moving `.behaviors` to source-of-truth requires *first conceiving* the source-of-truth bluebooks.

## Phased plan

### Phase A — Split aggregator bluebooks (high effort, high value)

Files to retire by splitting :
- `bluebook/bluebook.bluebook` (248 cmd) → `bluebook/{cli,hecksagon,persist,rails,workshop,…}.bluebook`. 5–8 stems.
- `hecks_conception/catalog/appeal.bluebook` → per-aggregate-cluster splits.
- `hecks_conception/catalog/mind.bluebook` (the Miette-mind aggregator) → per-cluster split (perception, awareness, musings, state, memory, identity, family, sleep, dream).
- `hecks_conception/catalog/body.bluebook` → cycles / organs / mind/state / immunity / world/conception.
- `hecks_conception/catalog/runtime.bluebook` → storage / dispatch / query / specializer / etc.
- `hecks_conception/catalog/boot.bluebook` → cli/console + cli/terminal + miette/surface + miette/mind/musings.

Each split lands its `.behaviors` companion alongside cleanly.

### Phase B — Move clean splits

Once Phase A lands, the 6 currently-misplaced + 10 ambiguous become mechanical `git mv`s. Each gets a same-stem companion at the destination.

### Phase C — Conceive source-of-truth bluebooks for catalog-only aggregates

The 7 catalog-mirror-only files need source-of-truth bluebooks first :
- `Application` / `DomainLifecycle` / `AppRegistry` (catalog/applications/applications.behaviors)
- `App` (catalog/applications/rvdc/rvdc.behaviors)
- `Case` / `Finding` / `Precedent` (catalog/court.behaviors)
- `Entry` / `Version` / `Mirror` / `Index` (catalog/catalog.behaviors)
- `ChapterRegistry` / `ChapterSelector` / `ChapterFile` (catalog/packaging.behaviors)
- `NamingHelpers` / `SmokeTest` / `EventChecks` (catalog/templating.behaviors)
- `Law` / `Enforcement` (catalog/law.behaviors)

Each needs a deliberate domain-conception pass before behaviors can move.

## Why P:medium

The corpus is already gated and green (catalog joined the gate this session — 1175/0/0 across catalog, on top of 558 across the other 9 roots). The mirrors *work*. They're just not the right shape for "every test next to source." The retirement is correct directionally but not blocking.
