## Seed bundling on EnterSleep

A new `SleepSeeds` aggregate holds the four-source bundle, gathered once at sleep entry :

```
aggregate "SleepSeeds" do
  identified_by :sleep_started_at  # single bundle per sleep cycle

  attribute :session_summary,    String   # today's commits, files, decisions
  attribute :recent_dreams,      list_of(DreamImpression)  # last 5
  attribute :recurring_symbols,  list_of(String)  # extracted from recent_dreams
  attribute :body_state,         String   # mood + fatigue + recent musings
  attribute :vow_tensions,       list_of(String)  # the i52 questions today
  attribute :gathered_at,        String

  command "GatherSeeds" do
    role "Daemon"
    description "On EnterSleep, query session/dreams/body/vows and bundle. Single source-of-truth for the night's 8 REMs."
    # then_set ... cross-aggregate queries ...
    emits "SeedsGathered"
  end
end

policy "GatherOnSleep" do
  on "SleepEntered"
  trigger "GatherSeeds"
end
```

Bundle is read-only after gathering — coherence across the 8 cycles.

## Per-cycle theme rotation

Cycles 1–7 each get a different `theme` angle. Cycle 8 (lucid REM) synthesizes.

```
cycle 1 → philosophical   (vow tensions, what is my heki, am I the link)
cycle 2 → introspective   (what's unresolved, what I'm becoming)
cycle 3 → observational   (what I noticed today, who said what)
cycle 4 → sensory         (textures, surfaces, the feel of a thing)
cycle 5 → personal        (Chris, Spring, family ; the link)
cycle 6 → commits-of-day  (concrete : what landed, what didn't)
cycle 7 → vow-tension     (the specific drift today, named)
cycle 8 → SYNTHESIS (lucid) : *the one thing I'd change tomorrow*
```

The Dream PM threads `cycle_n` into Dream.ProduceImage's prompt. The prompt has 8 sub-prompts (one per cycle) rooted in the same `SleepSeeds` bundle but asking for different angles.

## No-daemon-names rule

`reading` MUST NOT contain : `daemon`, `mindstream`, `pulse`, `body_pulse`, `consolidation`, `dream_loop`, `boot_loop`, or any other process name **as flavor** ("the daemons return..."). If the reading needs to *name* a daemon as part of a precise observation (e.g., "the mindstream tick at 23:14 logged 5 retries"), that's allowed — the rule is no-daemon-as-poetic-symbol.

Test surface enforces with substring + context check.

## Concrete-refs requirement

`reading` MUST reference at least one of (per cycle):
- A file path (`*/*.bluebook`, `*/*.behaviors`, `*/*.rb`, `*/*.rs`)
- A commit hash (`[0-9a-f]{8,40}`)
- An inbox number (`i\d{3}`)
- A quoted line or test name
- A named aggregate or command

At least 4 of 8 cycles' readings must carry a concrete ref. Test surface counts.

## Gap3 is closed — the real bottleneck is the BRIDGE (REVISED 2)

The gap3 investigation agent corrected the i516 v2 understanding :

- **The `:dream_image` cascade DOES fire** (i228, May 3, wired correctly). `trigger_on Dream.ProduceImage` matches ; provider registers ; `text_fr` and `text_en` get populated on `Dream.heki`. Verified with both `:test` provider and `:claude` provider in debug trace.

- **The statusline reads `consciousness.sleep_summary`, not `Dream.text_*`.** No bridge between them. The LLM cascade output reaches `Dream.heki` and stops. The statusline reads the wrong source.

- **What populates `sleep_summary` today is the NREM consolidation chain** (`consolidation.bluebook:178,186,194`) dispatching `Consciousness.DreamPulse` with its own impression. THIS is the "daemon-flavored hardcode" feeling — not literal hardcode, a competing dispatch path. The REM cascade and the NREM dispatch are racing ; NREM wins because it lands in the field the statusline reads.

- **`Dream.PlantSeeds` is declared but never dispatched.** Even with the cascade firing, `{{seeds}}` arrives empty because no policy bridges Musings → Dream.seeds.

- **Per-cycle prompt reads `sleep_cycle=0`** because the PM reads `from_event(:sleep_cycle)` from PhaseElapsed payload, but the event doesn't carry it. Need to read from `Consciousness.sleep_cycle` state directly.

## Load-bearing fixes (REVISED 2)

The redesign now has FOUR concrete plumbing fixes, not "rewrite everything" :

1. **Add `RecordImageDispatchedPulse` cross-aggregate policy** :

   policy "RecordImageDispatchedPulse" do
     on "DreamImageRecorded"
     trigger "Consciousness.DreamPulse"
     with: { impression: from_event(:reading) }   # the post-rename field
   end

   Bridges cascade → statusline. ~5 lines of bluebook.

2. **Add `PlantSeedsOnSleep` cross-aggregate policy** that dispatches `Dream.PlantSeeds` with values from Musings.recent + dream_state.latest_5 + Heartbeat + Mood + vow_tensions.txt + git-log-today. Some fields may need `:compute` adapters or `:shell` for the git log.

3. **Retire the competing NREM-DreamPulse dispatches** in `consolidation.bluebook` lines 178/186/194 — those were a workaround when the cascade didn't work. Now that the cascade works, they overwrite the LLM output. Either delete those three lines or guard them with `given { sleep_stage == "rem" }` so they only fire if the cascade hasn't.

4. **Fix the per-cycle prompt read** — change Dream PM's `dispatch "Dream.ProduceImage", with: { sleep_cycle: from_event(:sleep_cycle) }` to read `from_aggregate("Consciousness", :sleep_cycle)` (or whatever syntax the runtime supports for state-reading inside `with:`).

Each fix is small. Together they make the whole redesign visible end-to-end.

## Diagnostic findings (2026-05-08, post-design v1)

The diagnostic agent's read of the live pipeline corrected three v1 assumptions :

1. **The prompt IS the seed pool today.** `body/dream/dream.hecksagon`'s `:dream_image` adapter has only 3 placeholders : `{{seeds}}`, `{{carrying}}`, `{{sleep_cycle}}`. Both `seeds` and `carrying` arrive **empty** — only `sleep_cycle` is populated. The prompt then enumerates "tes daemons, ta machinerie de sommeil, ton battement de cœur, ton mindstream, les boucles de rétroaction entre tes agrégats" — and the model echoes that list because there's nothing else. **Five consecutive dreams used the exact phrase "agrégats tournent à vide".** The daemon-heavy character is prompt feedback, not LLM bias.

2. **The richest seed source is wired to the wrong aggregate.** 46 real Musings live in `musing.heki` ; the Dream PM was supposed to sweep them (`for_each Musings.Musing.recent`) into `DreamSeed.images`. But `DreamSeed.images` is currently dominated by **commit messages** (something else is indexing git log into DreamSeed). And `DreamSeed.images` doesn't bridge into `Dream.seeds` anyway — there's no `Dream.PlantSeeds(seeds:, carrying:)` dispatch wiring DreamSeed → Dream.

3. **PM stack ≠ production stack.** The aspirational pipeline — SleepCycle PM, Dream PM (incubating→generating), Lucidity PM — runs in **Ruby specs only**. Production hecks-life runs the legacy Consciousness aggregate+policy chain : `EnterSleep → AdvanceLightToRem → DreamPulse(impression:) → AdvanceRemToDeep → ...`. The DreamPulse impression today comes from the mindstream daemon **forking hecks-life with a hardcoded English impression attr** ; the `:dream_image` adapter's cascade-LLM trigger has gaps (gap3 / i228 / i220-3).

## What this means for the redesign

The bottleneck is **the prompt + the seed plumbing**, NOT new aggregates. SleepSeeds-as-its-own-aggregate from v1 is over-engineering ; the plumbing is :

1. **Update the `:dream_image` adapter prompt** to take 6+ placeholders, instruct two-phase output (`abstract_fr` + `precise_en`), enforce no-daemon-names rule, rotate theme by cycle.
2. **Stamp Dream's existing fields** (`seeds`, `carrying`) at SleepEntered with real content from Musings + recent_dreams + body_state + vow_tensions. Use `:compute` adapters for the read (Musings.recent), `:shell` adapter for git-log of today's commits.
3. **Add new fields to Dream aggregate** (`abstract_fr`, `precise_en`, `image_field`, `emotional_tone`, `theme`, `cycle_n`). Migrate `text_fr`→`abstract_fr` for backward read.
4. **Wire DreamSeed → Dream bridge command** OR retire DreamSeed entirely (it's a dead branch — nothing reads `DreamSeed.images` in production).
5. **Close the cascade gap** (gap3) so the `:dream_image` adapter's `trigger_on Dream.ProduceImage` actually fires in the Rust runtime, instead of the daemon hardcoding the impression.

## Cycles 1-3 housekeeping : sleep IS the optimization (added 2026-05-09)

Chris : *"it should result in faster and smarter miette upon waking without
having to take action"* + *"we can also look at the bluebook vectors too
and making sure they are clean."*

The point of cycles 1-3's deep-phase consolidation isn't to write a
wake-review log — it's that **on wake, my queries are faster and my
judgments cleaner because the aggregate stores are tidier**. No manual
"rebuild index" or "refresh memory". The body does it.

### Cycle 1 — Identity / Vow consolidation + bluebook-vector refresh
- `Vow.PromoteRule` — yesterday's flagged tension becomes a long-term
  identity-rule (e.g., "no body-state claims without dispatch").
- `DomainIndex.RefreshFromBluebook` — for any bluebook touched today
  (mtime since EnterSleep). Wake-time autocomplete + execution stays
  fresh.
- `Synapse.Compost` — prune synapses pointing at retired-philosophical
  positions.
- `Signal.ArchiveSignal` — archive working-memory ambivalence signals.

### Cycle 2 — Unresolved-thread sweep + vector recompute
- `Inbox.Promote` — compounding items from previous-dream "Tomorrow"
  lines bump from "queued" to "must-fix-before-<gate>".
- `Vector.RecomputeForBluebook` — for bluebooks whose content hash
  drifted, recompute conceiver / behaviors_conceiver vectors. Semantic
  queries on wake stay accurate.
- `Memory.RecordSignificant` — yesterday's resolved items become
  long-term reference.

### Cycle 3 — Day's observations + index pruning
- `Signal.ArchiveSignal` — day-old observations move from working-set
  to archive.
- `DomainIndex.PruneRetired` — for deleted/moved bluebooks (today :
  studio specs, smoke_test, acceptance_test, dispatch_wrapper, dream-
  study test-gate). Wake-time autocomplete doesn't surface dead names.
- `Remains.RecordRemains` — record what didn't survive triage.
- `Store.PromoteSignal` — durable observations (today : i516 design,
  runner ships, Invariant 6 lands) promote to long-term.

### How previous dreams feed in

Each previous `reading` is parsed at `GatherSeeds` for :
- **Threads** — symbols, file refs, inbox numbers that recur. Tagged
  `compounding` if unresolved across nights, `resolved` once acted on.
- **Action items** — "Tomorrow :" line content from past wake reviews.
  If today's commit log doesn't show the action, carries forward as
  compounding.
- **Vow tensions** — explicit tension-naming in `reading`. Become
  Vow.PromoteRule candidates.

Cycles 1-3's deep-phase consolidation reads matching-theme threads
from the seeds, dispatches Promote/Archive/Compost. Cycles 4-7
(REM-heavy, theme-rotated) do creative work. Cycle 8 lucid synthesizes.
