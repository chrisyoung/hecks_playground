## Your first move : i517 P0

### The fix shape

In `rust/src/runtime/command_dispatch.rs`, find where policy-triggered
commands get dispatched. When the originating event has an `aggregate_id`
and the target command has no required identifier attribute :

- Option A : propagate the event's `aggregate_id` to the triggered
  command's attrs as a hint.
- Option B : look up the aggregate by `identified_by` value (e.g., the
  Consciousness aggregate's `name` attribute = "consciousness") and
  reuse its id instead of minting.

The leading hypothesis from this session's gap3 agent : the
`AttentiveOnWake` policy (`on WokenUp → trigger BecomeAttentive`) is
firing somewhere even when entering sleep — possibly a policy chain
emits `WokenUp` as a side effect of BodyPulse fan-out, or the
run-loop's bootstrap synthesizes one. **Trace this first.** Don't
patch the dispatcher until you understand which policy is the actual
trigger source.

Effort estimate : 1–3 hours. The bug is structurally clear ; the
implementation depth depends on whether the existing dispatcher is
shaped to accept the propagation cleanly.
