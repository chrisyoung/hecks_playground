# i523 — status_assembly.bluebook : conceive `hecks status`

**Filed:** 2026-05-09
**In service of:** dream-work — close the bluebook-first gap exposed by the warning sweep on `rust/src/run_status/assemble.rs` (387 LoC).

## Gap

`rust/src/run_status/assemble.rs` is kernel-floor : it queries the
running runtime + reads `.heki` files + checks daemon liveness +
assembles a structured `Status` value that the CLI then renders
to text.

Today this is **partially** described in :

  - `cli/status/status.bluebook` (if it exists) — names the
    `hecks-life status` command surface.
  - **Nothing else.** The assembly itself — what fields appear in
    a Status, what data sources feed each field, what the order is
    — lives in code.

## Proposal

Conceive `runtime/status/status_assembly.bluebook`. The bluebook
should name :

  - **StatusAssembly** (aggregate, lifecycle: idle|assembling|ready)
    - assembled_at : Time
    - mindstream_alive : Boolean
    - consciousness_state : String
    - awake_for : Duration
    - last_dream_at : Time
    - parity_count : Integer
  - **StatusSection** (value object)
    - title : String
    - lines : list_of String
    - order : Integer
  - Commands :
    - **Assemble** — read all data sources + populate Status
    - **Render**(format: text|json) — emit the surface

The current sections (mindstream / consciousness / dream / parity /
boot) become declared sections with explicit data-source bindings.

## Why this matters

`hecks-life status` is the operator's primary read of "is Miette
healthy." If a section drifts or a new one is needed (e.g. a
recent-events section after the i517 cross-process work), the
bluebook captures the contract so the change is one row, not a
hunt through 387 LoC.

## Acceptance

  - `runtime/status/status_assembly.bluebook` exists.
  - Parity stays 330+.
  - The kernel-floor Rust file gains an antibody-exempt marker
    referencing this bluebook as its specification.
