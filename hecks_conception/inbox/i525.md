# i525 — graph-walking `map` syntax in policies

**Filed:** 2026-05-09
**Surfaced by:** banking-bluebook review (Q2 — "how do you prevent a loan being deposited into the wrong customer's account?").

## Gap

`policy ... map ...` today is a flat key→key transfer :

```ruby
policy "DisburseFunds" do
  on "IssuedLoan"
  trigger "Deposit"
  map account_id: :account_id, principal: :amount
end
```

The runtime takes whatever `account_id` is on the `IssuedLoan`
event payload and forwards it to `Deposit`. There's no
re-derivation through the originating aggregate's reference graph.

This is naive saga semantics : downstream commands trust the event
payload. If the upstream command was issued with mismatched ids
(or any future flat-payload corruption), the cascade dutifully
forwards the corruption.

The DDD-correct shape is **graph-walking** : the policy declares
the cascade target as a *path through the originating aggregate's
references*, not as a string transfer.

## Proposed syntax

```ruby
policy "SuspendOnDefault" do
  on "DefaultedLoan"
  trigger "SuspendCustomer"
  map customer_id: :loan.account.customer_id
end
```

Reading : "when DefaultedLoan emits, resolve `loan` from the event,
walk to `loan.account`, take that account's `customer_id`, and
dispatch SuspendCustomer with that id."

## Runtime resolution

For each path source like `:loan.account.customer_id` :

  1. Identify the originating aggregate type from the event name
     (DefaultedLoan → Loan).
  2. Resolve the aggregate instance from the event id (the Loan
     record by id).
  3. Walk the chain — `loan.account` resolves the Account by the
     reference declared in the Loan bluebook (`reference_to
     Account`), then `.customer_id` reads the field.
  4. Pass the resolved value to the trigger command's named param.

Walks must be guarded :
  - Reference resolution failure → policy short-circuits with a
    named error (LoanReferenceMissing, AccountReferenceMissing).
  - Walk depth limit → reject paths longer than N hops (e.g. 4)
    to prevent accidental graph-traversal pathologies in
    composite domains.

## What this closes

  - **banking.bluebook** : restores `SuspendOnDefault` (currently
    retired pending this syntax).
  - **General**: any saga that needs a downstream attribute
    resolvable through the upstream aggregate's reference graph.

## Out of scope (named follow-ons)

  - **Cross-domain walks** : `loan.account.customer.organization.id`
    where each hop crosses a Bounded Context. Same primitive,
    but bounded-context routing semantics may differ ; defer.
  - **Aggregate-state in events** : an alternative that subsumes
    most of this gap is to have events carry the resolved
    aggregate state alongside command payload. That's a deeper
    architectural decision (event size, event-store contract) ;
    file separately if pursued.

## Acceptance

  - `policy ... map foo: :ref.path.field` parses in both Ruby +
    Rust loaders with byte-equal IR (parity 330+).
  - At runtime, the cascade dispatch carries the resolved value.
  - Walk failures emit a structured error, not a panic.
  - banking.bluebook's SuspendOnDefault policy can be reinstated
    using the new syntax.
