# i530 — Local hook parity with CI — local must equal CI

## Why this card exists

The i528 storehouse arc PR (chrisyoung/hecks#640) tripped two CI
checks that local pre-commit didn't catch :

1. **LoC ratchet** : `bin/loc-ratchet` is in the repo and runs in CI
   (`.github/workflows/ratchet.yml`) but the local pre-commit hook
   never invoked it. The wasm32 cfg-gate added 16 lines to
   `rust/src/main.rs` ; CI caught it, local didn't.

2. **Cargo test compile** : the local smoke gate runs only the
   `smoke_test` binary (one `cargo test` invocation against a
   single test name). The CI parity job runs the full Rust test
   suite. Result : `validator_rules_test.rs` and
   `validator_warnings_test.rs` had been failing to compile on
   `origin/main` for some time (missing the
   `emits_identified_by` field after the IR Command struct grew
   it) and nobody noticed locally. The PR's CI run surfaced it.

Both were pure local-vs-CI gaps. Local hook was incomplete.

## The principle

**When a CI gate fires that local didn't, that's an antibody
failure for the hook — the hook is incomplete.**

The local pre-commit hook must run every gate that CI runs.
Otherwise the developer's commit isn't really verified : it just
passes the *subset* of gates the hook implements, and the rest are
discovered late, at PR time, costing context-switches and fix
commits.

The hook should keep growing until **local = CI**.

## What was added in this PR (2026-05-11)

Two new gates landed in `tooling/git-hooks/pre-commit` :

- **Gate 7** : LoC ratchet — `bin/loc-ratchet --base origin/main`.
  Authorise growth with `[loc-ratchet-override: <reason>]` on a
  branch commit. Bypass with `RATCHET_SKIP=1`.
- **Gate 8** : Cargo check tests — `cd rust && cargo check --tests
  --quiet`. Builds every test target without running them ; catches
  missing struct fields, type mismatches, renamed exports — anything
  the compiler sees but the smoke binary doesn't reach. ~10-30s warm
  cache, ~60s cold. Bypass with `CARGO_CHECK_SKIP=1`.

After the hook update, `tooling/install-hooks` re-copied the hook
into `.git/hooks/` so the new gates fire on the next commit.

## What's still missing (audit follow-ups)

I haven't done a full audit of `.github/workflows/` against
`tooling/git-hooks/pre-commit`. Likely additional gates the hook
doesn't run :

- **Rust unit tests (`cargo test`)** : CI runs them ; local only
  runs smoke. Heavyweight — would add ~30-60s per commit. Could
  be a Gate 9 with a skip env or a tiered (fast/full) mode.
- **Hecksagon parity (`.github/workflows/parity.yml`)** : checks
  `.hecksagon` files against their `.world` blocks. Local has
  Gate 1b for some of this ; verify it covers the same fixtures.
- **Smoke + Behaviors workflow** : local has Gate 6 + 6b. Check
  the fixture sets match.
- **Fuzz nightly** : intentionally CI-only (slow). Document as
  "not for local pre-commit" so the discipline knows the exclusion
  is deliberate.

## Discipline going forward

When a CI gate blocks a PR :

1. **Fix the immediate failure.**
2. **Ask : did the local hook run this gate ?** If yes, why did
   it pass locally — flakiness or environment drift to investigate.
   If no, the hook has a gap.
3. **Close the gap.** Add the missing gate to
   `tooling/git-hooks/pre-commit`. The same PR that fixes the
   failure can extend the hook.
4. **Reinstall** : run `tooling/install-hooks` so the local hook
   on every dev's machine picks up the new gate.

Repeat until local = CI for every dispatchable check.
