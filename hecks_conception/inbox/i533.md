# i533 — Parallel agents racing /tmp/ commit-message scratch space

## What happened

On 2026-05-11 the i532 follow-up dispatched five parallel sidequest
agents into the hecks tree to fix the five validate-failing /
warning bluebooks (heki, ollama, web_components, cloudflare_deploy,
web_application_creation). They shared one working tree.

Each agent followed the conversation's established pattern : write
the commit message to `/tmp/<name>_commit.txt`, then `git commit -F`.
Three or more agents wrote their messages to the same file path (or
near-same) within seconds of each other. By the time `git commit -F`
ran, the file on disk had been overwritten by a sibling agent. The
diff each agent staged was correctly scoped (most used `git commit --
<pathspec>` to lock in their own files), but the commit MESSAGE was
whoever wrote last.

Resulting hecks/main history :

| commit  | actual diff | commit message says |
|---------|-------------|---------------------|
| `122612e8` | heki bluebook wrap | web_application_creation split (wrong) |
| `9c3ad913` | web_components bluebook wrap | cloudflare_deploy split (wrong) |
| `fa22aa87` | web_application_creation split | unknown — to verify |
| `3dc18ed5` | web_application_creation monolith deletion | unknown — to verify |
| `ce024d21` | ollama bluebook wrap | ollama bluebook wrap (correct — agent used `-m` inline) |

Note `ce024d21` got it right — that agent abandoned `/tmp/` after
its first attempt was blocked by the bluebook-first enforcer
(deleted `/tmp/ollama_commit.sh`) and switched to chained inline
Bash. Its commit message survived.

## The lesson

Parallel agents in one working tree must not share `/tmp/`-resident
mutable state. The fix is mechanical :

1. **Never** read commit messages from `/tmp/<name>.txt` when running
   in a parallel cohort. Use heredoc or inline `git commit -m "..."`
   directly. The shell quotes the message into the commit ; nothing
   touches disk between the write and the commit.

2. If the message is long enough that heredoc is the only sane form,
   write it to a per-agent path like
   `/tmp/<agent-id>/commit_msg.txt` and delete on success. The
   per-agent prefix eliminates the race.

3. Document this in the parallel-dispatch brief that the main agent
   writes when spawning the cohort. Each child agent should be told
   explicitly :

   > Do not write commit messages to `/tmp/*.txt`. Use heredoc /
   > inline `-m` only. Multiple agents in this cohort share the
   > working tree's /tmp/ namespace and last-writer wins.

## Cleanup decision

**Not rewriting history.** Force-pushing to fix commit messages on
origin/main is destructive and asymmetric to the actual harm — the
diffs are correct, the lesson is recorded here, and the audit trail
is recoverable by grep against the file paths in each commit's diff.
This card IS the cleanup.
