# i534 — `html_domain` renderer upgrades

## Why this card exists

bin-buddy/inbox/i104 audits the walking skeleton's UX after it went
live at https://bin-buddy-2pf.pages.dev/. Most of the friction is in
the framework's renderer at `rust/src/server/html_domain.rs` (and
`html_diagram.rs`), not in bin-buddy itself :

| bin-buddy ticket | Renderer change |
|---|---|
| i106 | Typed inputs (Int / Decimal / Bool → number / checkbox ; enum / VO → select) |
| i107 | Reference fields → `<select>` populated from `runtime.repository(:ref).all()` |
| i108 | Every command per aggregate card (stacked collapsibles or tabs) |
| i109 | Required-field asterisks + browser-level `required` attr |
| i111 | Sidebar default-closed + localStorage persist + mobile collapse |
| i112 | Per-aggregate icons (from bluebook `icon "🚛"` declaration with a fallback table) |
| i113 | Lifecycle rules scoped per-aggregate card, not flat-dumped |
| i117 | Top-bar nav rendered on every framework surface |
| i119 | View-mode filter (customer / driver / operator) |

## Scope

`rust/src/server/html_domain.rs` is ~344 LoC today and generates one
HTML page per domain. The audit list breaks roughly into :

- **Form input rendering** (i106 + i107 + i109) — biggest refactor.
  Replace the single `<input type="text">` path with a type-aware
  field renderer. Reference fields query the runtime for live
  records. Required attrs render with asterisk + `required`.

- **Command iteration per card** (i108) — today renders the first
  command only ; loop over every command, emit a collapsible per.

- **Sidebar render** (i111 + i112) — change default `<details open>`
  to `<details>`, inject `localStorage` JS, swap icons.

- **Rules scoping** (i113) — move the global rules dump into each
  aggregate card.

- **Top-bar** (i117) — small new module that emits a shared header
  across html_domain + html_diagram.

- **Role filter** (i119) — top-bar-driven, CSS class on each card
  that the browser toggles.

## Antibody

`html_domain.rs` and `html_diagram.rs` already carry kernel-floor
markers ; the upgrades stay within the same exempt surface. Each
change strengthens the bluebook-first claim — the renderer reads
declared types / required-ness / icons / roles directly from the IR.
