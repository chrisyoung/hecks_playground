# i535 — Worker state + cascade + universe view + error translation

## Why this card exists

The walking-skeleton worker landed tonight (`bin-buddy/worker/src/
lib.rs`, hand-extended prototype of the wasm_worker codegen, marked
antibody-exempt). It serves live runtime output but boots a fresh
runtime per request and discards cascade information.

bin-buddy/inbox/i104 (audit) names the gaps :

| bin-buddy ticket | Worker change |
|---|---|
| i114 | R2-backed state persistence — read on cold start, write on dispatch |
| i115 | Surface cascade events in dispatch response (`cascade: [...]`) |
| i109 | Runtime-side : validate required attrs + value-object membership |
| i110 | Translate `RuntimeError` to human strings (message + suggestion + field) |
| i116 | `/diagram` returns universe view, `/diagram/:domain` returns single |
| i118 | `/diagram/_all/graph.json` route |

Plus the always-needed work of loading the new fixtures (bin-buddy
i105) at boot via `Domain.fixtures` once they're embedded.

## Scope

`bin-buddy/worker/src/lib.rs` is currently ~280 LoC. The changes :

- **State persistence (i114)** — biggest piece. Two paths :
  1. R2 read-on-boot : after constructing the Runtime, iterate every
     aggregate, fetch `<bucket>/state/<aggregate>.heki`, seed the
     repo. After every dispatch, write each touched aggregate's
     records back.
  2. (Future / out of scope here) — Durable Objects for per-request
     in-memory persistence. Filed for later.

- **Cascade surface (i115)** — read `rt.event_bus.history()` after
  dispatch, return as a JSON array of every event emitted during
  this dispatch.

- **Universe view + graph json (i116 + i118)** — separate code paths
  for `/diagram` (uses `_all` rendering via
  `html_diagram::all_domains_graph_view(runtimes)`) and
  `/diagram/_all/graph.json` (returns
  `html_diagram::all_domains_graph_json(runtimes)`).

- **Error translation (i110)** — new helper
  `humanize_runtime_error(&RuntimeError) -> {message, suggestion,
  field}` consumed by `walking_skeleton_dispatch`.

- **Required + VO validation (i109)** — may need to land in the
  runtime itself (`rust/src/runtime/command_dispatch.rs`) rather
  than the worker ; check if existing validation is wired but not
  surfaced first.

- **Fixture loading (i105 follow-on)** — extend `boot_runtimes` to
  parse `.fixtures` content from `EMBEDDED_BLUEBOOKS` and seed each
  repo before serving the first request. Today the runtime's
  Domain.fixtures gets populated but isn't loaded into repos ;
  identify the gap, close it.

## Antibody

prototype antibody marker. These changes stay within the same
surface ; the durable codegen path (`i528_explorer_codegen`)
captures them all in one specialization shape when it lands.
