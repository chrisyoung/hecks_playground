# i536 — Type-aware form inputs

## Why this card exists

Every input on every aggregate card is `<input type="text">`,
regardless of the attribute's declared type. `monthly_price` is
Decimal but free-text. `recycle_enabled` is Bool but free-text.
`role` is constrained to a value-object enum but free-text.
`included_movements` is Int but free-text. Result : users type
"yes" / "true" / "1" / "$45" arbitrarily and the runtime accepts
anything.

The bluebook declares the type at the source. The IR walker carries
it through. The renderer in `rust/src/server/html_domain.rs` just
emits text fields uniformly.

## What changes

In `html_domain.rs` form rendering :

| Attr type in IR | HTML input |
|---|---|
| `Bool` | `<input type="checkbox">` |
| `Int` | `<input type="number" step="1">` |
| `Decimal` | `<input type="number" step="0.01">` |
| `String` | `<input type="text">` (today's default — kept) |
| Value-object with enum members | `<select>` populated from VO members |
| `reference_to(...)` | covered in i537 |

The value-object enum case is the trickiest : Role, Direction,
Status — each is declared as a value object with a list of allowed
String values. The renderer needs to introspect the VO IR and emit
each as `<option>`.
