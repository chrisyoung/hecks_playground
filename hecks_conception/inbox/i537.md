# i537 — Reference fields render as dropdowns of live records

## Why this card exists

A reference attribute today renders as `<input type="text"
placeholder="Service Address">`. The user has to know to type "1"
or whatever id the runtime gave the last record. There's no
discovery, no validation, no autocomplete.

The bluebook declares the reference target. The runtime holds every
record of that target in its repository. The renderer can ask :
`runtime.repository(:service_address).all()` → list of records →
one `<option>` per record.

## What changes

In `html_domain.rs`, when rendering a form field whose IR type is
`reference_to(TargetAggregate)` :

```html
<select name="service_address" required>
  <option value="">— pick a Service Address —</option>
  <option value="1">1 — 9512 N Hayden Rd · Scottsdale</option>
  <option value="2">2 — 415 E Camelback Rd · Phoenix</option>
</select>
```

The option's label needs a sensible projection of the target record
— at minimum its id, plus a couple of identifying attrs (the address
text for ServiceAddress, the email for Account, the name for Plan).
Pick the first ~2 String attrs that aren't internal (`status`,
`created_at`).

When a referenced aggregate has zero records, the dropdown shows
"— no Service Address records yet — create one first —" and disables
submit, so the user understands what's missing.
