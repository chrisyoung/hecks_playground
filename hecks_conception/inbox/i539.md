# i539 — Required-field marks + value-object validation

## Why this card exists

Two related gaps :

1. **No visual cue for required fields.** Empty submit succeeds —
   `Account.Register` with `{}` returns `ok: true`. The user gets
   no warning that `auth_identity` was needed.
2. **Value-object membership isn't enforced.** `role: "banana"` is
   accepted by Account.Register even though Role is a value object
   with a fixed allowed list (`customer / owner / admin_manager /
   dispatcher / driver / support`).

The bluebook declares both required-ness and VO membership. The
runtime currently honours neither at dispatch time.

## What changes

**Renderer side** (`html_domain.rs`)

- Each input whose attr is required in the IR gets an asterisk and
  `required` attribute. Form submit is blocked by the browser if
  empty.
- Each input whose attr type is a value object with members gets a
  `<select>` (already in i536) — invalid input becomes impossible
  to enter.

**Runtime side** (or whatever layer holds it today)

- Before applying mutations, validate every required attr is present.
  Missing → `RuntimeError::MissingAttribute(name)`.
- For each VO-typed attr, validate the supplied value is a member.
  Not a member → `RuntimeError::InvalidValueObjectMember(field,
  value, allowed)`.

Both errors translated via i540 to human strings the dropdown form
displays inline.

## Companion

- i536 / i537 — typed inputs the required-mark sits on
- i540 — error rendering
- `hecks_conception/inbox/i534` — renderer side
- `hecks_conception/inbox/i535` — runtime side validation
