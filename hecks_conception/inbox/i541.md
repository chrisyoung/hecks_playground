# i541 — Sidebar default-closed + persist state + mobile collapse

## Why this card exists

The walking-skeleton sidebar renders `<details open>` for every
aggregate in the domain. With 16 aggregates × ~10 link rows each
(Commands subsection + Queries subsection + References subsection),
that's ~160 visible rows on first load — a 240px column scrolling
the whole height of the page. Most users see "Bin Buddy" at the top
and walls of links beneath.

On mobile the sidebar is `position: fixed; width: 240px` which
either overlays the content or pushes everything off-screen.

## What changes

**Default state.** First open per aggregate is the one the URL hash
targets (`#agg-Account` → Account expanded, others closed). All
others closed.

**Persistence.** On user click (open / close), write
`bin-buddy.sidebar.<aggregate>` to localStorage. On page load,
read each key and respect the user's last state. The hash-target
rule wins if nothing's stored.

**Mobile.** Below md breakpoint, the sidebar becomes a top-bar with
a hamburger that toggles a slide-in drawer. Content area takes the
full viewport when the drawer is closed.

## Implementation

Renderer-side change in `html_domain.rs` :
- Emit `<details>` instead of `<details open>` unless the aggregate
  matches the URL hash.
- Inline JS reads localStorage in `DOMContentLoaded` and toggles.
- Tailwind classes for the mobile breakpoint already mostly there ;
  just need `md:` prefixes on the sidebar's positioning + a
  small hamburger button hidden above md.
