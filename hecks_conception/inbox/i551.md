# i551 — Generic-command :shell adapter for Tools.Bash

## Why this card exists

The Tools bluebook (`hecks_conception/aggregates/framework/tools/tools.bluebook`,
conceived today) declares `Tools.Bash` as a dispatched command —
takes a shell command + description, emits BashRan. But nothing
actually runs the shell command yet : the bluebook names the
contract, not the execution.

The existing `:shell` adapter (see `examples/shell_adapter/`) is
template-based — you declare the command at hecksagon time and the
adapter interpolates parameters into the template. That works for
named, fixed-shape shell calls (`echo {{msg}}`, `ls {{dir}}`) but
not for an arbitrary `shell_command` string passed at dispatch.

## What's needed

A new adapter flavor — `:command_shell` or `:generic_shell` — that :

- Takes the `shell_command` attribute as the command line to run.
- Executes via `/bin/sh -c <shell_command>` (or equivalent).
- Captures stdout (truncated at a configurable size).
- Captures exit code.
- Populates a follow-up event or backfill command that records the
  result into the aggregate state.

Or, equivalently, a kernel-floor shim in `rust/src/main.rs` that
recognises the `Tools.Bash` dispatch and routes it through the
existing process-spawn path. Same shape as how `Cadence.Loop` and
`Dump.Fixtures` have imperative substrate in main.rs that fires on
dispatch — the bluebook names the contract, the imperative arm
fulfills it.

## Pairs with i552

Once the substrate exists, the Claude harness (i552) intercepts
Bash tool calls and dispatches `framework::tools::Tools::Bash`
instead of calling Bash directly. Both pieces have to land for
the end-to-end "every Bash call is a domain event" goal.
