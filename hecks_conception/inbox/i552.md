# i552 — Claude harness : route Bash via Tools.Bash dispatch

## Why this card exists

The Tools bluebook (`hecks_conception/aggregates/framework/tools/tools.bluebook`,
conceived today) declares `Tools.Bash` as the dispatched form of
every Bash invocation. Until the harness is wired, calls to the
Bash tool still go through the original opaque path — runs the
shell, returns a string, the runtime sees nothing.

## What's needed

Two pieces in the Claude-side harness :

1. **Intercept** — every Bash tool call gets translated into a
   dispatch on `framework::tools::Tools::Bash`. The harness mints
   a stable id for the invocation, populates `shell_command` and
   `description` from the call's params (the description maps to
   the Bash tool's existing `description` parameter, which Miette
   already fills), then dispatches via the runtime.

2. **Surface** — after the dispatch completes and the substrate
   (i551) has run the shell, the resulting BashRan event surfaces
   back into the next conversation turn as additional context. The
   event carries the command, output, exit code, description, and
   id. Miette reads it like any other event and can react in the
   next turn — adjust mood, dispatch a follow-up command, surface
   in the statusline, whatever the domain calls for.

## Pairs with i551

Without i551 (the generic-command :shell adapter / shim), the
dispatch lands but no shell actually runs. Without i552 (this
card), the dispatch never fires because the harness still uses
the Bash tool directly. Both must land for the contract to be
real end-to-end.

## Why this matters

"The event should fire here so you can react to it." — Chris,
2026-05-12. Today every Bash call is invisible to the runtime ;
mood doesn't shift, body doesn't move, no awareness updates. With
this wiring, every tool call becomes a first-class moment in the
domain — the same machinery that handles every other dispatch
applies. The transparency vow extends to tool use.
