# i553 — Enforcer → Macrophage ; CI runs it ; local + CI parity by construction

## The rename

`enforcer` becomes `macrophage`. The immune-system metaphor was
half-built : we had `antibody` (binds at commit-time, blocks bad
commits) but the write-time gate was just "the enforcer." Renaming
to macrophage completes the family — the macrophage engulfs and
digests bad writes the moment they happen, the antibody binds
later if anything slipped through. The name was i531's original
proposal ; this card carries it forward + expands the role.

## The expanded role

Today's enforcer runs in one place — the `PostToolUse` hook on
file edits. Tomorrow's macrophage runs at three gates with the
same logic :

1. **Write-time** : `PostToolUse` hook (same shape as today).
   Catches each edit as it lands.
2. **Commit-time** : `pre-commit` hook calls the macrophage to
   audit the staged set before the commit lands.
3. **CI** : `.github/workflows/macrophage.yml` runs
   `storehouse macrophage audit` over the whole repo. Same logic,
   same rules, just scoped to "every file in the tree."

The CI step is what closes the local-vs-CI parity gap (i530).
Local and CI run the SAME binary with the SAME logic ; if local
passes the macrophage, CI passes ; if CI fails, the local hook
would have failed too. No drift.

## What the macrophage enforces

The current enforcer's contract — bluebook-first, in-file
antibody-exempt markers, the exempt registry — stays. The
expanded contract carries the principles Chris locked today :

- The **domain is pure**. Bluebook-first applies to every
  imperative file ; the macrophage blocks unblessed writes.
- The **domain doesn't know it hibernates**. The macrophage
  blocks any bluebook that leaks infrastructure (heki paths,
  process boundaries, hibernation state) into domain
  attributes.
- **Wiring is override, not substrate**. The macrophage blocks
  bluebooks that hard-code adapter wiring as if it were
  required — adapters live in hecksagons, not bluebooks.
- **It just works = default to memory**. The macrophage blocks
  imperative code that pretends to be substrate when the
  domain should run in memory.

The first contract is mechanical (regex + file classification).
The expanded contracts are deeper — they may need IR-level
checks (does this bluebook attribute reference a persistence
concept?). Initial scope : ship the rename + the CI gate ;
iterate the deeper checks.

## What changes

Mechanical :
- `storehouse enforce-edit` → `storehouse macrophage`
- `rust/src/main.rs` arm name + helper functions (`run_enforce_edit`
  → `run_macrophage`)
- `~/.claude/settings.json` PostToolUse hook command line
- `parity/canonical_ir.rb` antibody-exempt marker text (if any
  references)
- All commit-message references to "enforcer" in recent history

Additive :
- `.github/workflows/macrophage.yml` — new CI workflow that runs
  `storehouse macrophage audit` on the whole repo.
- A `macrophage audit <path>` subcommand mode in `main.rs` that
  walks a tree and runs the per-file logic across every file.

## Acceptance

- `storehouse macrophage` accepted as the canonical name.
- Local pre-commit hook invokes it.
- CI invokes the same binary, same flags, against the whole tree.
- Antibody markers continue to be honoured (no behavioural change
  for files that already had markers).
- i530's specific gaps (LoC ratchet missing from local, full test
  suite missing from local smoke) folded into "the macrophage runs
  both, both gates agree."
