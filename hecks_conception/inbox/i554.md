# i554 — Macrophage : wrap primitive attrs in value_objects

## Why

`storehouse validate hecks_conception/aggregates/discipline/macrophage/macrophage.bluebook`
reports 29 `no_primitive_envy` errors today. Every attribute on
the Macrophage aggregate (and its Check / Violation / Complaint
/ FixturesViolation entities) uses a bare `String` or `Integer`
primitive instead of a typed value_object.

The bluebook predates the no-primitive-envy rule (commit
`7a3c66d0`, 2026-05-09). The 2026-05-12 rename + dense
restructure preserved the existing shape so the move stayed
small ; this card is the hygiene pass.

## What to wrap

Distinct value_objects to introduce :

  * `Name`             — the singleton key
  * `Timestamp`        — every ISO-8601 string (session_started_at,
                         complained_at, violated_at, last_complaint_at)
  * `FilePath`         — any path the macrophage records
  * `ComplaintText`    — the text body of a complaint
  * `EditCount`        — counter for edit-kind tallies
  * `ViolationCount`   — counter for violation tallies
  * `CheckId`          — the slug identifying a registered check
  * `PatternKind`      — the detection-strategy name
  * `Severity`         — enum-shaped (block | warn)

Each replaces the corresponding `attribute :x, String|Integer`
with `attribute :x, X`. Command attributes use the same VOs.

## Pairs with

- **i532** — five framework adapter bluebooks fail validate
  similarly. This card is the same kind of work scoped to the
  Macrophage.
- **i531 / i553** — the rename + dense restructure cards. This
  card is the hygiene tail of that work.

## Acceptance

`storehouse validate hecks_conception/aggregates/discipline/macrophage/macrophage.bluebook`
returns `VALID — Macrophage (1 aggregates)` with zero errors,
and Ruby / Rust parity stays green.
