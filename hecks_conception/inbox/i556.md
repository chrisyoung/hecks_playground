# i556 — Kernel hook for `invoke_claude_tool` behavior

## What this card carries

The substrate for i551. The bluebook side is fully declared :
`claude_tool.hecksagon` (adapter family) + `invoke_claude_tool.hecksagon`
(behavior kind) + `tools.hecksagon` (the six bindings) all sit in
`framework/`. The runtime auto-discovers them at boot.

What's missing : the kernel hook that ACTUALLY executes the tool
when an adapter fires. Six native primitives :

  | tool   | hook input                              | hook output                  |
  |--------|-----------------------------------------|------------------------------|
  | :bash  | shell_command + description             | output (stdout), exit_code   |
  | :edit  | file_path + old_string + new_string + replace_all | success / error  |
  | :read  | file_path                               | contents (truncated)         |
  | :write | file_path + content                     | success / error              |
  | :grep  | pattern + search_path                   | match list (path:line:text)  |
  | :glob  | glob_pattern + search_path              | matching file paths          |

## Where it lives

`rust/src/runtime/behavior_hooks/invoke_claude_tool.rs` (new file).
Sibling to existing behavior-kind handlers if they exist
(render_text_to_audio, call_sms_api). Registers with the kernel's
behavior_kind dispatcher.

## Acceptance

A Tools.X dispatch via storehouse fires the matching
`:claude_tool` adapter, the kernel hook executes the native
primitive for that tool kind, and the result routes into the
adapter's `result_into` target as a follow-on dispatch carrying
the output.

End-to-end test path :

```
storehouse <root> Tools::Tools.Bash \
  id=abc123 shell_command="echo hello" description="say hi"
```

→ records the dispatch  
→ matches `:claude_tool, command: "Tools.Bash"` from
  `framework/tools/tools.hecksagon`  
→ kernel hook branches to `:bash`, spawns `sh -c "echo hello"`  
→ captures stdout = "hello\n", exit = 0  
→ dispatches `Tools.RecordResult` with output="hello\n", exit_code=0  
→ aggregate state shows the result.

## Pairs with

- **i551** — declares the adapter family + behavior_kind (done)
- **i552** — Claude calls StoreHouse (the dispatch direction)

## Why this is the only code left

Per Chris's "adapters should be auto registered" principle, the
adapter parsing / IR / canonical-dump work doesn't happen — it
emerges from the bluebook discovery. Only the actual SIDE-EFFECT
substrate lives in code. That's i556.
