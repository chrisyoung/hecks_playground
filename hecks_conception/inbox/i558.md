# i558 — Retired-trigger audit : markers whose retirement condition has landed

## Method

Walked every file under `hecks/` (excluding `.claude/worktrees/` and
`hecks_conception/inbox/`) carrying an `[antibody-exempt: ...]` header
with a "retires when X" / "retires once X" / "until X" phrase. Found
**~50 candidate markers** across **~40 unique files**. For each
trigger family, traced `git log` for the named issue/condition and
checked whether the structural enabler (bluebook, hecksagon, shape,
behaviors-runner capability) is now in tree. Cross-referenced with
inbox card statuses where the trigger was a card. Bucketed into
LANDED / IN-FLIGHT / PENDING / UNCLEAR.

The single biggest LANDED bucket is the i147 W1-W9 wave : each target
`.rs` file now regenerates byte-for-byte from a shape capability
under `codegen/<name>_shape/`. But every i147 marker explicitly
defers FINAL retirement to **i78** (the specializer itself
regenerated from a meta-shape), and i78 is queued. So those markers
still describe accurate state — the regeneration form is shipped but
the deeper retirement step has not.
