# i560 — Pre-commit hook : `#!/bin/sh` silently breaks the companion-ratchet

## What's broken

`.git/hooks/pre-commit` carries a `#!/bin/sh` shebang. Earlier
tonight (during the i528 rename pass) I added `comm -23 <(printf
'%s\n' "$added_aggs") <(printf '%s\n' "$removed_aggs")` to make
the ratchet aware of `-aggregate` matches when computing
`new_aggs`. That works under `bash` but NOT under POSIX `sh` —
`<(...)` is a bash-only process-substitution feature.

When the hook fires under `sh`, those two lines (248 + 259, the
`new_aggs` and `new_cmds` calculations) silently fail to parse.
The shell's `set -e` is presumably not active (the script
continues), so the hook proceeds past the bad lines with both
`new_aggs` and `new_cmds` empty. The companion-ratchet's
"every new aggregate / command needs a test" check effectively
becomes a no-op : it iterates over an empty list and finds
nothing missing.

## Symptom

Since 2026-05-12 19:xx UTC (when the ratchet fix landed), the
companion-ratchet has been silently passing commits that add new
aggregates / commands without their `.behaviors` companion. The
intent of the ratchet — catch tests-missing at commit-time — is
defeated.

Surfaced by the meta-bluebook wrap agent
(worktree-agent-a57073f04ace45eae) which noticed `/bin/sh` syntax
errors in the hook output during commit. Multiple other agents
tonight hit similar friction without diagnosing the root cause.

## The fix

One-line change at the top of `.git/hooks/pre-commit` :

```bash
- #!/bin/sh
+ #!/bin/bash
```

`bash` is available on every macOS + Linux host the repo targets.
The hook already uses bash-only features beyond process-
substitution (associative arrays elsewhere ? need to grep) — the
shebang should match the language the script actually uses.

## Verification after fix

1. Stage a bluebook adding a new aggregate WITHOUT a test in its
   `.behaviors` companion.
2. `git commit` — hook should now correctly detect + block.
3. Run a stale commit (one that the hook used to skip) — should
   STILL pass if the new-aggregate diff has matching tests.

## Acceptance

- Shebang changed
- Companion-ratchet check fires correctly on a test-deficient
  staged set (verified by adding a test bluebook with a new
  aggregate, no behaviors)
- Existing commit flow still works (no regression on the happy
  path)
