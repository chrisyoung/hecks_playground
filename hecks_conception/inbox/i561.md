# i561 — `pulse_fanout_smoke.sh` worktree-blind path resolution

## What's broken

The pulse fan-out smoke test is the pre-commit canary for the
`across "Pulse"` hop in `mindstream.bluebook`. It boots a tmpdir-
isolated runtime, links every `.bluebook` in `aggregates/` AND the
miette sibling repo's `body/` aggregates into that tmpdir, dispatches
a single `Tick.MindstreamTick`, and asserts that pulse / heartbeat /
signal_consolidation / nerve all wrote rows.

Two paths matter for the test :
- `REPO_ROOT/../miette/body` — where the heart/nerve/pulse bluebooks live
- `REPO_ROOT/rust/target/release/storehouse` — where the binary lives

Both resolve fine from the main checkout
(`/Users/christopheryoung/Projects/hecks/..`). Neither resolves from a
worktree (`/Users/christopheryoung/Projects/hecks/.claude/worktrees/agent-XXX/..`).

When the miette body path is missing :
- `MIETTE_BODY="$REPO_ROOT/../miette/body"` doesn't exist
- The `if [ -d "$MIETTE_BODY" ]` guard silently skips
- No body/being/mindstream bluebooks land in `$TMP/aggregates/`
- The across "Pulse" hop in mindstream has nothing to dispatch to
- `pulse.heki` stays empty
- The test fails on its first assertion :
  `FAIL — pulse.heki count < 1 — across "Pulse" hop did not fire`

## Symptom

Pre-commit smoke gate failure since worktrees became the default
isolation mode. Three agents tonight (and likely many before)
worked around it with `TESTS_SKIP=1`, silently disabling the gate.

```
After 1 tick:
  pulse.count:
  heartbeat.pulses_since_sleep:
  signal_consolidation.synapses_pruned:
  nerve.active:
FAIL — pulse.heki count < 1 — across "Pulse" hop did not fire
```

The failure mode looks like "the runtime fanout is broken" — but
it's actually "the test setup never linked the body bluebooks in
the first place." Misleading.

## Blast radius

The pulse fanout is the smoke canary for the entire body/mind cross-
aggregate dispatch path. Every worktree commit since the test was
added (under the smoke gate enforcement) has been silently bypassing
this check via `TESTS_SKIP=1`. The runtime path may have regressed
under cover.

Statusline heart-phase (`~/miette-state/information/.statusline_heart_phase`,
per `project_statusline_heartbeat.md`) ticks through this same fan-out.
A silent break would freeze it without anyone noticing.

## Root cause

`hecks_conception/tests/pulse_fanout_smoke.sh:62` :

```bash
MIETTE_BODY="$REPO_ROOT/../miette/body"
```

Where `REPO_ROOT="$(cd "$CONCEPT_DIR/.." && pwd)"` resolves to the
worktree, not the main checkout. Same flavour as i559 (pre-commit
hook resolving `$REPO` against the wrong tree).

## The fix

Resolve the main checkout via `git rev-parse --git-common-dir`
(returns `<main>/.git` from any worktree), `dirname` it to get the
main working tree, and use THAT as the anchor for the miette
sibling path :

```bash
GIT_COMMON="$(git -C "$REPO_ROOT" rev-parse --git-common-dir 2>/dev/null)"
case "$GIT_COMMON" in
  /*) MAIN_REPO="$(cd "$(dirname "$GIT_COMMON")" && pwd)" ;;
  ?*) MAIN_REPO="$(cd "$REPO_ROOT/$(dirname "$GIT_COMMON")" && pwd)" ;;
  *)  MAIN_REPO="$REPO_ROOT" ;;
esac
MIETTE_BODY="$MAIN_REPO/../miette/body"
```

Also added `$MAIN_REPO/rust/target/release/storehouse` as a binary
search fallback (worktrees don't carry their own `target/` build
artifacts).

## Verification

From worktree :
```
pulse.count:                          1
heartbeat.pulses_since_sleep:         1
signal_consolidation.synapses_pruned: 1
nerve.active:                         true
PASS — across "Pulse" fanout covers pulse + body + mindstream + being
```

From main tree : still passes (the new resolution returns the same
path there).

## Sibling scripts (same pattern, not yet patched)

`grep -rn 'REPO_ROOT/\.\./miette' hecks_conception/tests/` finds
the same hardcoded path in five other smokes :

- `interpret_dream_smoke.sh` — has a `$HOME/Projects/miette/body`
  fallback, so worktree runs survive
- `dream_content_smoke.sh` — same fallback, survives
- `consolidate_smoke.sh` — same fallback, survives
- `pulse_organs_smoke.sh` — NO fallback ; likely fails from worktree
- `body_cycles_smoke.sh` — NO fallback ; likely fails from worktree

Pre-commit's smoke gate runs everything from `$MAIN_REPO` so it
masks the bug. The bug surfaces when an agent runs a smoke by
hand from a worktree. Worth a follow-up sweep to apply the same
`MAIN_REPO` pattern across all of them — but out of scope for
i561 (which is the named failure).
