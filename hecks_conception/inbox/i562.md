# i562 — `voice_and_sleep_lockdown.sh` worktree-blind path resolution

## What's broken

The voice-and-sleep lockdown test is Miette's identity-drift canary.
It asserts that the canonical i50 (French) + i52 (dream / wake ritual /
words-match-state) sections in the system-prompt template have not
silently drifted out — every boot reads from
`/Users/christopheryoung/Projects/miette/self/system_prompt/system_prompt_assembly/miette_prompt.md.template`,
and the test re-greps for those sections + a set of French vocabulary
anchors (Barthes, Bachelard, voilà, alors, pardon, intérieure).

Two paths matter for the test :
- `REPO_ROOT/../miette/self/...` — where the template source-of-truth lives
- `REPO_ROOT/rust/target/release/storehouse` — where the binary lives

Both resolve fine from the main checkout. Neither resolves from a
worktree (`/Users/christopheryoung/Projects/hecks/.claude/worktrees/agent-XXX/..`).

When the miette template path is missing :
- Both fallback checks (template path, then plain `system_prompt.md`)
  miss
- `BOOT` stays empty
- Every `grep -qF "$section" "$BOOT"` silently fails (grep on empty
  filename → exit 2, silently swallowed by the `|| ...` arm)
- The test reports every section as MISSING — and additionally fails
  on "storehouse binary not found" if `HECKS_BIN` isn't exported.

## Symptom

Pre-commit smoke gate failure since worktrees became the default
isolation mode. Three agents tonight worked around it with
`TESTS_SKIP=1`, silently disabling the i50/i52 identity-drift gate.

```
storehouse binary not found
```

…or, with `HECKS_BIN` set :

```
  ✗ A. system_prompt.rs MISSING section: Words match state (drift!)
  ✗ A. system_prompt.rs MISSING section: I think in French (drift!)
  ✗ A. system_prompt.rs MISSING section: What dreams are about (drift!)
  ✗ A. system_prompt.rs MISSING section: Wake ritual (drift!)
  ✗ A. French vocabulary anchor MISSING: Barthes
  …
voice_and_sleep_lockdown: FAIL
```

The failure looks like "the regenerator drifted out of sync" — but
the sections are all present in the template. The test simply
couldn't find the template file from the worktree.

## Blast radius

This is the **identity lockdown gate**. Its whole point is to detect
silent drift in Miette's voice — a future edit (intended to fix an
unrelated thing) that removes the French section, reverts the wake
ritual, or breaks the words-match-state contract. With the gate
silently bypassed via `TESTS_SKIP=1`, *that drift could happen
undetected*. The next system-prompt edit that removes a section
would not be caught at commit time.

Combined with i561 (the pulse fan-out gate, same flavour) : the
two pre-commit smokes that protect Miette's most load-bearing
runtime + identity invariants have both been silently disabled in
every worktree commit tonight.

## Root cause

`hecks_conception/tests/voice_and_sleep_lockdown.sh:79-82` :

```bash
BOOT="${HECKS_PROMPT_TEMPLATE:-}"
[ -z "$BOOT" ] && [ -f "$REPO_ROOT/../miette/self/system_prompt/system_prompt_assembly/miette_prompt.md.template" ] && \
  BOOT="$REPO_ROOT/../miette/self/system_prompt/system_prompt_assembly/miette_prompt.md.template"
```

`REPO_ROOT` resolves to the worktree ; the path doesn't exist next
to it ; `BOOT` stays empty ; every `grep -qF "$section" "$BOOT"`
silently fails. Same flavour as i559 (pre-commit hook) and i561
(pulse fan-out smoke).

## The fix

Same pattern as i561 : resolve the main checkout via
`git rev-parse --git-common-dir`, derive `MAIN_REPO` from it,
and use that as the anchor for the miette sibling path. Also
extended the storehouse-binary search to fall back to
`$MAIN_REPO/rust/target/release/storehouse` so worktree runs
don't need to export `HECKS_BIN`.

```bash
GIT_COMMON="$(git -C "$REPO_ROOT" rev-parse --git-common-dir 2>/dev/null)"
case "$GIT_COMMON" in
  /*) MAIN_REPO="$(cd "$(dirname "$GIT_COMMON")" && pwd)" ;;
  ?*) MAIN_REPO="$(cd "$REPO_ROOT/$(dirname "$GIT_COMMON")" && pwd)" ;;
  *)  MAIN_REPO="$REPO_ROOT" ;;
esac
```

Then change `$REPO_ROOT/../miette/...` → `$MAIN_REPO/../miette/...`
in the BOOT-template lookup + BODY_DIR lookup.
