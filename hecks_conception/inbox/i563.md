# i563 — Three antibody markers placed past the 30-line scan window

## What's broken

`rust/src/dispatch_query.rs:file_has_in_header_marker` reads :

```rust
text.lines().take(30).any(|line| line.contains("[antibody-exempt:"))
```

The header-marker exemption path therefore requires the marker to appear
in the first **30 lines** of the file. Three files in `rust/src/`
(outside `runtime/`) currently have their marker pushed below that
threshold by a long usage / design / preamble doc comment :

| File | Marker line | Pre-marker comment kind |
|---|---|---|
| `rust/src/specializer/run_boot/system_prompt.rs` | 35 | 27 lines of usage + bullet-tree describing the system-prompt assembly snippets |
| `rust/src/run_restructure/mod.rs` | 44 | 39 lines of "design + meta-shape" preamble explaining the three-phase capability runner |
| `rust/src/specializer/parse_blocks.rs` | 31 | 26 lines of recursive-descent design notes + a usage example |

For each of these, the file has a valid kernel-surface justification
(documented inside the marker text), and neither the central
`exempt_registry.heki` nor any other marker covers them. So when any
Edit hits these files, the macrophage blocks even though the file IS
structurally exempt.

## Symptom

Discovered while grooming `[antibody-exempt: storehouse/src/...]` →
`rust/src/...` path-narrow updates across `rust/src/` (post-i118
rename). The macrophage hook fired on every Edit to these three files
even though the only delta was inside the marker's own text :

```
[macrophage] bluebook-first violation : Edit wrote .rs
(rust/src/specializer/run_boot/system_prompt.rs). The enforcer expected
a bluebook (.bluebook / .hecksagon / .fixtures / .behaviors / .world).
```

The marker text says the file IS exempt (kernel-floor specializer for
the system-prompt assembly under i146 piece 4), but the antibody scan
can't see the marker because it's past line 30.

## Root cause

The 30-line scan window in `is_imperative_exempt` was tuned for files
whose `//!` doc-comment header is short (a couple of lines of summary
+ usage + marker). Files that grow more elaborate preambles — design
documents inline with the source — push the marker out of view.

## Two possible fixes

### Option A — relocate the marker (small, per-file)

Move the `[antibody-exempt: ...]` block to the very top of the `//!`
doc comment, right under the first summary line. The design /
usage / preamble paragraphs follow afterward. Three files, three
small edits.

Pro : surgical, no antibody-mechanism change.
Con : still leaves the 30-line ceiling brittle for the NEXT file
that grows an elaborate preamble.

### Option B — widen the scan window (one-line antibody fix)

Bump `text.lines().take(30)` → `text.lines().take(200)` (or whatever
the macrophage's own "first 200 lines" body-read uses ; main.rs has
markers as deep as line 55 and works because the macrophage reads
200 lines for exempt-detection, but the in-file scan only reads 30).

Pro : closes the inconsistency between the macrophage's read budget
and the antibody's scan budget — they should agree.
Con : weakens the scan-window discipline ; a file could carry a
deeply-buried marker and still be exempt.

Recommended : **option B** — change one line in
`rust/src/dispatch_query.rs` (`take(30)` → `take(200)`) and let
`storehouse specialize dispatch_query` regenerate. This unifies the
two scans (macrophage's body-read + antibody's marker-check) at the
same 200-line budget. The three blocked files then become editable
without any per-file relocation.

## Files affected

- `rust/src/dispatch_query.rs` (one-line edit + specializer regen)
- `codegen/dispatch_query_shape/` (snippet update if `take(30)` is in
  a `.rs.frag`)
