# i563 — `worktree-agent-abeb2168` (HEC-469 governance) — obsolete, flagged for archive

## What it was

A 41-day-old branch (2026-04-01) with two commits adding `GovernanceGuard`
to `hecks_ai/lib/`. The original intent :

> GovernanceGuard intercepts `execute_command` and validates proposed
> actions against the domain's `world_goals` before allowing execution.
> Refused commands return structured JSON with violations and active
> goals. New MCP tools: `explain_governance` (list goals/constraints)
> and `check_governance` (pre-check a command). `Workshop#world_goals`
> propagates goals to domains built via the workshop API.

## Why it can't land

1. **Target dirs are gone.** `hecks_ai/` and `hecks_workshop/` were
   retired by `3a9f0b81` (2026-04-08, one week after this branch
   forked). The current ruby layout puts everything under `ruby/`
   (`ruby/hecks_ai/`, `ruby/hecks/chapters/ai.rb`, etc.).

2. **The concept has been superseded.** Current main implements
   `Hecks::GovernanceGuard` (`ruby/hecks_ai/governance_guard.rb`)
   but with a different model :
   - **Branch model** : runtime interception of `execute_command`
     against `world_goals` (Workshop#world_goals → guard refuses bad
     commands at dispatch time → MCP tools to introspect).
   - **Main model** : design-time validation of `world_concerns`
     (transparency, consent, privacy, security) against the domain
     model itself, with rule-based `ConcernChecks` and optional
     AI enrichment.

   These are different governance theories. The branch gates the
   stream of commands ; main gates the shape of the domain.

3. **No `world_goals` runtime consumer exists.** Main's AST extractor
   still parses `world_goals` from bluebooks
   (`ruby/hecks/bluebook/ast_extractor/domain_visitor.rb:101`), but
   nothing in the runtime consumes them. If we want to revive the
   "intercept dispatch against world_goals" idea, it should be
   rebuilt as a fresh bluebook against the current dispatch path
   (`bus_pipeline`, `dispatch.bluebook`), not cherry-picked.

## Decision

Branch obsolete — do not land. Flagged for formal archive.

If the runtime-governance idea is still wanted, it should be
re-conceived against current main's dispatch architecture
(StoreHouse `Dispatch.Route`, `bus_pipeline.bluebook`,
`bus.bluebook`) and the current `Hecks::GovernanceGuard` design-
time API. File a fresh inbox card with a current-main implementation
plan rather than reviving the April branch.
