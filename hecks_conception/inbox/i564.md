# i564 — `worktree-agent-af9a2c1a` (ExtensionContract) — already landed, flagged for archive

## What it was

A 41-day-old branch (2026-04-01) with one commit adding
`Hecks::Conventions::ExtensionContract` under `hecksties/lib/`.
Original intent :

> Extensions (logging, sqlite, tenancy) follow a two-step registration
> pattern but nothing validated it. `ExtensionContract` checks
> `describe_extension` + `register_extension`, `adapter_type` is `:driven`
> or `:driving`, and boot hook has 3-arity block.

Files touched :

```
hecksties/lib/hecks/conventions.rb                       |   1 +
hecksties/lib/hecks/conventions/extension_contract.rb    | 127 +++
hecksties/spec/conventions/extension_contract_spec.rb    | 124 +++
```

## Why it doesn't need to land

**The contract is already on main, byte-equivalent.**

`hecksties/lib/` was folded into `ruby/` during the
2026-04-08 directory consolidation (`3a9f0b81 feat: product executor,
UL tagging, domain tag validation, legacy cleanup`). The contract
landed at `ruby/hecks/conventions/extension_contract.rb` with
exactly the same module body, constants, and methods :

- `REQUIRED_META_KEYS = %i[description adapter_type wires_to]`
- `VALID_ADAPTER_TYPES = %i[driven driving]`
- `BOOT_HOOK_ARITY = 3`
- `self.shape`, `self.validate`, `self.validate_all`,
  `self.all_extension_names`
- Private `check_metadata`, `check_boot_hook`, `validate_meta_shape`

```bash
$ diff <(git show ab4324e1:hecksties/lib/hecks/conventions/extension_contract.rb) \
       ruby/hecks/conventions/extension_contract.rb
# Only diff: 4-line redundant doc comment on the inner module on main
```

It's also registered :

```ruby
# ruby/hecks/conventions.rb:61
Contracts.register(:extensions, Conventions::ExtensionContract)
```

And declared as a bluebook aggregate :

```
hecks_genetics/binding.bluebook:118
  aggregate "ExtensionContract", "Extension registration and wiring rules"
```

## Minor gap : the spec did not come across

`hecksties/spec/conventions/extension_contract_spec.rb` (124 lines)
was NOT brought across in the consolidation. But main's testing
discipline is now parity-suite + smokes ; there is no
`spec/conventions/` directory on main. Other contracts
(`AggregateContract`, `EventContract`, etc.) also don't have
per-contract specs — they're exercised by the parity suite and
by the smokes that consume them.

If we ever want a regression spec specifically for
`ExtensionContract.validate`, file a fresh inbox card targeted at
the current spec layout rather than cherry-picking the April spec
file blindly.

## Decision

Branch obsolete — do not land (would be a no-op for the production
code ; would resurrect a spec file in a directory that no longer
exists). Flagged for formal archive.
