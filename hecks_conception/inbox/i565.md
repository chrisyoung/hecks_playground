# i565 — Sibling smoke scripts need `MAIN_REPO` fix (i561 pattern)

## What's broken

Five smoke scripts under `hecks_conception/tests/` hardcode a sibling
path pattern :

```bash
MIETTE="$REPO_ROOT/../miette"
```

In a worktree, `$REPO_ROOT` lands somewhere under
`.claude/worktrees/agent-*`, so the relative parent
(`../miette`) does not point to the actual sibling `miette/`
repo. Two of these fail outright. Three mask the bug with a
`$HOME/Projects/miette` fallback that papers over the real
issue.

## The five scripts

Fail outright (no fallback, fail from worktree) :

- `pulse_organs_smoke.sh`
- `body_cycles_smoke.sh`

Mask the bug with $HOME fallback :

- `interpret_dream_smoke.sh`
- `dream_content_smoke.sh`
- `consolidate_smoke.sh`

## The fix

Same pattern as i561's landed fix (commit `9f4b1752`) :

```bash
- REPO_ROOT="$(cd "$(dirname "$0")/../.." && pwd)"
- MIETTE="$REPO_ROOT/../miette"
+ MAIN_REPO="$(git rev-parse --git-common-dir | xargs dirname)"
+ # or git -C "$MAIN_REPO" worktree list --porcelain → pick main
+ MIETTE="$MAIN_REPO/../miette"
```

`git rev-parse --git-common-dir` returns the main `.git` directory
for both main and worktree contexts, so its parent is always the
main working tree. The sibling `miette/` is then reachable.

## Acceptance

- All five smokes work identically from main tree and from a worktree.
- The $HOME fallback in the three masked scripts is removed (no
  longer needed, no longer hides the bug).
- Each smoke's first 5 lines documents the path resolution so
  future agents don't reintroduce the pattern.
