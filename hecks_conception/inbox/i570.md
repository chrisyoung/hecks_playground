# i563 — `bin/nursery-parity-sweep` : bluebook or retire

## Surface

`bin/nursery-parity-sweep` is a 250-LoC Ruby script that mechanically
applies four idempotent transformations across `.bluebook` files :

1. `reference_to "X"` → `reference_to(X)` (string → constant)
2. `list_of "X"` (one-line) → `list_of(X)` (string → constant)
3. `list_of(X) :field` → `attribute :field, list_of(X)` (Gate A swap)
4. `list_of "X" do … end` → sibling `value_object "X" do … end`
   (extract attribute-only block to VO sibling, leave bare list_of)

It carries an `[antibody-exempt: i31 …]` marker that promises
retirement "when all nursery files are parity-clean AND new files
ship via DSL directly." With Ruby/Rust parity now locked (and the
locked DSL conventions from tonight 2026-05-12 — see CLAUDE.md
"Tonight's locked conventions" — explicitly retire the auto-list
heuristic and codify VO-inside-aggregate placement), the four
transformations the sweep performs are either :

- **One-shot** — already applied across the nursery, idempotent
  re-runs would be no-ops. Verify with a `--dry-run` pass and if
  zero diff, retire the script.
- **Re-expressible as a bluebook** — each transformation is a
  Tools.Glob + Tools.Read + (regex match) + Tools.Edit composition.
  The composition is exactly the shape `Tools.bluebook` supports
  (see `docs/usage/tools.md` — the locked conventions from tonight
  include first-class `Tools.Bash` / `Tools.Edit` / etc. dispatched
  through the bus).

## The two paths

### Path A — retire (preferred if the corpus is clean)

1. From main, `bin/nursery-parity-sweep --dry-run` over
   `hecks_conception/nursery/` and any sibling repos.
2. If all four transformation counts are zero AND skipped-files is
   empty, the corpus is parity-clean. Delete the script. Remove the
   `[antibody-exempt: i31 …]` marker (it goes with the file).
3. Note in the `i31` retirement arc that the sweep retired.

### Path B — restructure as bluebook (if residual rewrites remain)

Conceive `tools/nursery_parity_sweep/nursery_parity_sweep.bluebook`
with a `command` per transformation, each declaring its match-and-
rewrite shape against a Tools.Glob + Tools.Edit dispatch chain.
The bluebook becomes the contract ; the runtime dispatches Tools.*
to perform the actual edits.

Sketch :

```
Hecks.bluebook "NurseryParitySweep" do
  aggregate "NurseryParitySweep" do
    attribute :target, :string

    command "ApplyReferenceToConstant" do
      attribute :target, :string
      # Compose Tools.Glob + Tools.Read + Tools.Edit dispatches
      # against the target tree to apply the string-to-constant
      # transformation.
    end

    command "ApplyListOfConstant" do … end
    command "ApplyGateASwap" do … end
    command "ExtractListOfBlockToValueObject" do … end

    # A top-level "Sweep" command chains all four — runs Tools.Glob
    # once, dispatches per-file.
    command "Sweep" do
      attribute :target, :string
    end
  end
end
```

The Tools.bluebook surface lets the bluebook DOMAIN compose the
tool call ; the adapter runs it (per tonight's locked principle 4 :
"Domain composes the tool call ; the adapter runs it").

## Why this is the cleanest exemplar

`bin/nursery-parity-sweep` is the rare BLUEBOOKABLE script where :

- The intent (mechanical .bluebook transformation) is itself
  bluebook-shaped.
- The transformations are tool-call compositions, not novel runtime
  primitives — they fit Tools.bluebook exactly.
- The retirement contract (i31, "nursery files parity-clean") is
  testable today via a dry-run pass.
- If it can't retire entirely, the restructure showcases the
  Tools.bluebook + bus dispatch chain on a real script.

Either outcome closes a marker AND demonstrates the locked principle
"Wiring is override, not substrate" — the adapter (Tools.Bash /
Tools.Edit) runs ; the bluebook describes intent.

## Acceptance

- Either : script retired, marker gone, `i31` arc closed.
- Or : `nursery_parity_sweep.bluebook` shipped + bluebook-dispatched
  sweep replicates the four transformation counts byte-for-byte
  against a dry-run corpus.
