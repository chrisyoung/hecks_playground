# i564 — Pre-push hook : same `$REPO` resolution bug as i559

## What's broken

`tooling/git-hooks/pre-push` carries the identical pattern that
i559 fixed in `.git/hooks/pre-commit` :

```bash
REPO="$(cd "$(dirname "$0")/../.." && pwd)"
```

In a worktree, `$0` does not reliably resolve to the worktree's
working tree, so `$REPO` lands somewhere in the main tree.
Subsequent file reads (validate, storehouse invocation, etc.)
all read the wrong tree.

## Surfaced by

The i559 fix agent (commit `0ca7e4c2`) noticed the sibling pre-push
hook carries the identical bug. Currently a latent issue because
the pre-push gracefully no-ops if storehouse isn't built ; doesn't
cause false-positive blocks the way the pre-commit did. Still
wrong, still worth a one-line fix.

## The fix

Same one-liner as i559 :

```bash
- REPO="$(cd "$(dirname "$0")/../.." && pwd)"
+ REPO="$(git rev-parse --show-toplevel)"
```

## Acceptance

- `tooling/git-hooks/pre-push` uses `git rev-parse --show-toplevel`
  for `$REPO`.
- Pre-push from a worktree validates against the worktree's bytes.
- Pre-push from main tree is unchanged.
