## Why the gap matters

The antibody gate at `bin/antibody-check` is per-file : when a touched
`.rb` is on the diff and (a) the IR dispatch-query says "not claimed"
AND (b) the first 30 lines carry no `[antibody-exempt: ...]` marker,
the commit blocks. The marked subset above is touched on practically
every release (`identified_by` work, `cadence` shape, PM events, query
where-comparator hash form — each has triggered a marker over the
past few months). The unmarked subset has the same role but has
happened not to be touched in a commit where the antibody fired.

A future edit to e.g. `policy_builder.rb` or `read_model.rb` will
block — at which point an agent (or Chris) has to figure out the
justification on the spot. Better to either :

1. **Cluster-mark the whole `ruby/hecks/dsl/` + `ruby/hecks/bluebook_model/behavior/`
   tree once**, via per-file headers using a shared phrase
   ("kernel-floor Ruby parser/IR mirror of rust/src/specializer/parser.rs +
   rust/src/specializer/ir.rs ; retires under the i147 long arc once
   hecks_conception/aggregates/language/grammar/*.bluebook compiles
   to a generated parser"), OR

2. **Ship a `ruby_parser_parity` meta-shape** that the
   `storehouse is-dispatched` query recognises, so the antibody's IR
   dispatch-query path (i122) drops the whole cluster out of the
   "non-bluebook" set without needing per-file markers. This is the
   cleaner long-term form — it routes the exemption through the
   dispatch query rather than through file-header text, matching how
   the i147 W1-W9 specializer-shape clusters already work.

## Constraint

Per the grooming task : *"don't add new markers"*. So this card is

Chris decides whether to bulk-add headers (option 1, cheap and

## Acceptance

- Either every Ruby kernel-floor DSL builder + IR behaviour file
  carries an in-file `[antibody-exempt: ...]` marker with a coherent
  retirement target, OR
- A `ruby_parser_parity` (or similarly-named) shape under
  `codegen/` / `discipline/antibody/` causes `storehouse is-dispatched`
  to return success for the cluster, and the marker-gap files lose
  their need for headers.
- Touching any file in the cluster does not require manual exemption
  authoring at commit time.
