# i577 — Statusline command-display format v2 : `Domain::Aggregate.Command`

## The format

Two segments + dot. No entity slot in the path.

```
Domain::Aggregate.Command       (commands, PascalCase)
Domain::Aggregate.query_name    (queries, snake_case)
```

### Canonical examples

| Dispatch                          | Rendered breadcrumb                     |
|-----------------------------------|------------------------------------------|
| `Tools.Bash`                      | `Tools::Tools.Bash`                      |
| A root command on macrophage      | `Discipline::Macrophage.Run`             |
| `Immunity.recent_violations` query| `Discipline::Immunity.recent_violations` |

## Why this shape

- **Domain** answers "which bounded context owns this?" — the
  bluebook namespace (`Hecks.bluebook "Name"`), with a fall-through
  to the merged `Domain.category` and finally the aggregate name
  so the slot never empties.
- **Aggregate** answers "which heki record was mutated?" — always
  the root, even for entity-targeted dispatches. Entity slots were
  considered (an earlier attempt rendered `Tools::Tools::Tools.Bash`
  / `Macrophage::Macrophage::Check.Register`) and rejected. The
  duplication was visually loud and the entity layer is a structural
  detail callers reading the line don't need.
- **Command** answers "what was dispatched?" — the bare last segment
  of the address, after `rsplit('.').next()` strips any
  `Context.Aggregate.` prefix the caller passed.

## Implementation (landed alongside this card)

`Runtime::format_breadcrumb_phrase` (`rust/src/runtime/mod.rs`)
renders the phrase from a `CommandResult` + the dispatched command
name. Called once per dispatch from the `.last_dispatch` write path,
guarded by `is_daemon` + `data_dir` (unchanged from v1).

Mirror :
- Snippet : `codegen/runtime_shape/snippets/method_03a_format_breadcrumb_phrase.rs.frag`
- Fixture row : `FormatBreadcrumbPhrase` at order 5 in
  `codegen/runtime_shape/fixtures/runtime_shape.fixtures` (slots
  the helper between `dispatch` and `dispatch_isolated`).

The statusline reader (`rust/src/run_statusline.rs`,
`fn read_last_dispatch`) is unchanged — it reads the first line of
`.last_dispatch` verbatim and surfaces it as the 🛠️ breadcrumb
when the timestamp is `< 30s` old. The whole format change is on
the WRITE side ; readers automatically pick up the new shape.

## Test coverage

`rust/tests/breadcrumb_phrase_test.rs` — five tests cover :

1. `Tools.Bash` → `Tools::Tools.Bash` (canonical Chris example).
2. Entity-owned command (`Macrophage` aggregate, `Check` entity,
   `Register` command) → `Macrophage::Macrophage.Register`
   (entity does NOT surface).
3. Distinct aggregate + bluebook names (`Immunity` bluebook,
   `DetectThreat` command) → `Immunity::Immunity.DetectThreat`.
4. Qualified caller-side address (`Tools.Tools.Bash`) →
   `Tools::Tools.Bash` (prefix stripped to bare command).
5. Synthetic dispatch with no IR match → falls back to the
   aggregate name so the slot never empties.

## History

- **v1** (initial breadcrumb landing, pre-2026-05-12) :
  `Aggregate.Command` written directly from
  `result.aggregate_type` + `command_name` ; no domain segment.
- **v2 attempt #1** (rejected same day) : three-segment form
  `Domain::Aggregate::Target.Command` where Target was the entity
  when the command lived inside `entity "Foo" do ... end` and the
  aggregate name otherwise. Chris rejected this for the visible
  duplication on root commands (`Tools::Tools::Tools.Bash`).
- **v2 final** (this card) : two-segment `Domain::Aggregate.Command`,
  entity slot retired.

## Follow-on (not in scope)

- The statusline bluebook (`cli/statusline/statusline.bluebook`)
  doesn't yet declare the breadcrumb format as a section / value
  object. Today the format lives in the Rust runtime doc comment
  + this card. When the breadcrumb gains its own rendering surface
  (more than just `read_last_dispatch`'s verbatim pass-through),
  a `Breadcrumb` aggregate or section row in the statusline bluebook
  would carry the spec.
- A `BreadcrumbPhrase` value object (paired with `Domain`,
  `Aggregate`, `Command` VOs) would let downstream consumers
  pattern-match on the shape rather than parsing strings. Worth
  carrying when a second consumer beyond `read_last_dispatch`
  shows up.
