# i577 — Setup instructions : storehouse-mcp

A standalone MCP server lives in `tooling/storehouse-mcp/` that
exposes every `Tools.*` command as a native MCP tool. The companion
project deny rules in `.claude/settings.json` block native `Bash` /
`Read` / `Edit` / `Write` / `Grep` / `Glob` / `WebFetch` /
`WebSearch` and force every dispatch through the MCP. Setup needs
two manual steps before this lands on `main`.

## What got built

- `tooling/storehouse-mcp/` — the MCP server (Node.js stdio,
  `@modelcontextprotocol/sdk` v1.29)
- `.mcp.json.example` — template for the project-scoped MCP server
  registration (the real `.mcp.json` is gitignored, see step 0 below)
- `.claude/settings.json` — deny native tools + allow the nine
  `mcp__storehouse__*` tools
- `docs/usage/storehouse-mcp.md` — usage docs

The MCP exposes nine tools, one per `Tools.*` command :

| MCP tool                                       | Dispatches             |
|------------------------------------------------|------------------------|
| `mcp__storehouse__storehouse__bash`            | `Tools.Bash`           |
| `mcp__storehouse__storehouse__read`            | `Tools.Read`           |
| `mcp__storehouse__storehouse__edit`            | `Tools.Edit`           |
| `mcp__storehouse__storehouse__update`          | `Tools.Update`         |
| `mcp__storehouse__storehouse__grep`            | `Tools.Grep`           |
| `mcp__storehouse__storehouse__glob`            | `Tools.Glob`           |
| `mcp__storehouse__storehouse__web_fetch`       | `Tools.WebFetch`       |
| `mcp__storehouse__storehouse__web_search`      | `Tools.WebSearch`      |
| `mcp__storehouse__storehouse__record_result`   | `Tools.RecordResult`   |

## What Chris needs to do

### Step 0 — copy the MCP registration

`.mcp.json` is gitignored project-wide (line 31 of `.gitignore`) so
personal MCP credentials don't leak. The committed template is
`.mcp.json.example` ; copy it once :

```sh
cp .mcp.json.example .mcp.json
```

### Step 1 — first-time install

```sh
cd tooling/storehouse-mcp
npm install
```

`@modelcontextprotocol/sdk` is the only runtime dep. The smoke test
in `tooling/storehouse-mcp/test/smoke.mjs` exercises the full MCP
protocol path (boots the server, lists tools, dispatches three of
them, asserts the parsed JSON state round-trips) ; run with :

```sh
cd tooling/storehouse-mcp && npm run smoke
```

### Step 2 — first Claude session in this branch

When Claude Code first starts in this project after the merge,
there will be a prompt to approve the project-scoped MCP server
declared in `.mcp.json`. Approve it. From that point on, the
`mcp__storehouse__*` tools become available.

### Step 3 — decide on the deny scope

The current `.claude/settings.json` denies the eight native tools
**project-wide**. That means any existing slash-command, hook, or
agent that calls a native tool gets permission-denied. Options :

a. **Keep project-wide deny** — fully structural ; everything routes
   through the MCP ; existing tooling needs to be updated.
b. **Scope down to interactive only** — move the deny rules to
   `.claude/settings.local.json` so they only apply to Chris's own
   sessions, not to subagents and hooks.
c. **Soften to `ask` instead of `deny`** — every native tool call
   prompts ; the bus is the default, but escape hatches survive.

The sidequest brief implied (a) ; recommend (a) for the discipline
but (b) is the smaller blast radius if any background automation
breaks immediately.

## Toggle for the qualified-paths split

The `Tools.bluebook` 5-aggregate split on
`worktree-agent-a2c393f2905d4dfd1` (commit `4db717bf`) hasn't merged
to main yet. When it does, set the env var
`STOREHOUSE_MCP_QUALIFIED=true` in `.mcp.json` and the dispatcher
flips to the fully-qualified verb form
(`framework::tools::ShellTool::Bash` etc) — no server-side code
changes needed. The mapping lives in
`tooling/storehouse-mcp/src/dispatch.mjs` `QUALIFIED_PATHS`.
