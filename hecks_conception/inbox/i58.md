# i58 — i51 Phase B discovery: specializer check_kind taxonomy is too narrow for sui-generis rule bodies

i51 Phase B discovery: specializer check_kind taxonomy is too narrow for sui-generis rule bodies.

Context: Phase A's validator.rs had 6 rules, all expressible as 6 primitives (unique, non_empty, first_word_verb, reference_valid, trigger_valid, unique_across). Byte-identity worked.

Phase B's validator_warnings.rs has 2 rules:
  - aggregate_count_warning (11 LoC): fits a count_threshold primitive cleanly
  - mixed_concerns_warning (108 LoC): BFS over an adjacency graph built from references + policies. Sui generis — can't be templated from a check_kind without making check_kind "contains a full algorithm"

Workaround shipped in Phase B commit 1:
  body_strategy field on WarningRule fixtures — either "templated"
  (check_kind drives the body) or "embedded" (specializer reads a
  Rust snippet file from snippet_path and interpolates the fn body).
  Complex rules go "embedded" until the IR grows richer.

Proper fix (this item): extend the L2 flow_ir / L3 dispatch_ir to
describe graph algorithms declaratively. Probably needs:
  - a graph_builder concept: adjacency relation built from IR edges
  - connected_components or reachable queries as first-class IR
  - output rendering templates

This is deep IR work — Phase C or later. Until then, "embedded" is
the escape hatch.

Side effect: the mixed_concerns_warning function stays visible as a
.rs.frag snippet under the shape capability rather than a proper
declarative rule. Acceptable debt; named so it doesn't drift.
