# i591 — conception_dir() walks for a directory shape the current repo doesn't have

## Surface

`rust/src/run_boot/daemons.rs:237` (and the duplicate at `mod.rs:189`) :

```rust
fn conception_dir(script_path: &str) -> PathBuf {
    let abs = std::fs::canonicalize(script_path)...;
    let mut cur = abs.parent()...;
    for _ in 0..5 {
        if cur.join("information").is_dir() && cur.join("capabilities").is_dir() {
            return cur;
        }
        if !cur.pop() { break; }
    }
    abs.parent()...
}
```

The detector requires both `information/` AND `capabilities/` at the same level. Walking up from `hecks/runtime/boot/boot.bluebook` never finds that pair because :

- `hecks/capabilities/`        — exists
- `hecks_conception/information/` — exists
- nowhere has both

The fallback (`abs.parent()`) returns `hecks/runtime/boot/`, so `agg_dir = conception.join("aggregates")` becomes `hecks/runtime/boot/aggregates` — which doesn't exist. Any daemon command using `{agg}` then dies with `Cannot read /Users/.../hecks/runtime/boot/aggregates : No such file or directory`.

## Why it only surfaced today

Pre-2026-05-13, `storehouse loop` rejected short-form addresses (`Heart.Beat`) before checking the aggregates path, so the daemons failed at FQN-parse stage and `conception_dir`'s bogus output was masked. After the FQN lockdown, the FQN was correct, the path check ran, and the bug became visible : five daemons (heart, breath, circadian, ultradian, sleep_cycle) spawning + dying within one tick. Only mindstream survived because it uses `{body}`, which `resolve_body_dir` derives from the storehouse-binary path (robust).

## Workaround landed

`runtime/boot/boot.hecksagon` now routes the four body cycle daemons through `{body}/..` instead of `{agg}`. The Heart / Breath / Circadian / Ultradian aggregates live under `miette/body/`, so the `loop` and `clock` subcommands discover them from that root.

## Real fix candidates

1. **Single-marker detect** — `cur.join("information").is_dir()` alone (drop the `capabilities/` requirement). Cheapest. May misdetect if some sibling repo also has an `information/` dir.
2. **Two-marker detect with sibling sweep** — when one of `information/` / `capabilities/` lives at the parent and the other at this level, accept that pair. Mirrors the current repo layout.
3. **Pure env-var resolution** — let `HECKS_CONCEPTION_DIR` override and fall back to the storehouse-binary-rooted layout the way `resolve_body_dir` does. Stops the heuristic-walk dance entirely.
4. **Bluebook-first** — declare the directory roots as adapter options on the `Boot` hecksagon (e.g. `adapter :fs, conception_root: ".", aggregates_root: "{body}/.."`) so the substitution is data-driven instead of computed from a heuristic. Pairs with the "vitals.rs should be bluebook" direction (separate inbox).

## Acceptance

- Switching `boot.hecksagon` back to `{agg}` (instead of `{body}/..`) keeps heart/breath/circadian/ultradian alive after `storehouse run boot.bluebook` from `hecks_conception/`.
- `conception_dir` returns `hecks_conception/` (the true conception root) for both `runtime/boot/boot.bluebook` and `capabilities/boot/boot.bluebook` invocations.
- No silent fallback to a wrong parent.
