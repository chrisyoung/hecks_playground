# i592 — vitals.rs + classify.rs hardcode daemon presence ; should be bluebook-driven

## Symptom that surfaced this

During the 2026-05-13 overmind fix, the sleep_cycle daemon was removed from `boot.hecksagon` (its commands had been retired in i309). But `rust/src/run_boot/vitals.rs:53–56` still prints :

```
ultradian: <s> · sleep_cycle: <s>
```

— so the boot summary lies, claiming a sleep_cycle daemon with status `—` that doesn't exist in the source-of-truth bluebook anymore. Likewise `classify.rs:33` hardcodes :

```rust
"heart", "breath", "circadian", "ultradian", "sleep_cycle",
```

as part of the LINKED_STORES list, so the heki classification also drifts from the bluebook.

## Chris's direction

> "vitals.rs should be bluebook"

The vitals concept — what gets rendered, in what order, with what separators — is a domain concern (the body's daily-readout shape). It is not kernel-surface. The Rust file is a confession that the domain wasn't reached for first.

## The bluebook-first shape

A `Vitals` aggregate (or capability) that declares :

- Which daemon statuses to render, in what order
- The render template (one line per group, separators, units)
- The summary line shape (`feeling: X · Y · pulses since sleep: N · state: S · last wake: T`)
- The ASCII banner

The Rust `print_vitals` becomes a renderer that walks the declared shape — not a hand-coded list of `println!`s. Daemons in the boot.hecksagon directly drive the daemon-status section ; no Rust edit needed when a daemon is added or removed.

For classify.rs : a `StoreClassification` bluebook (or extend the existing classification capability) declares LINKED_STORES, PRIVATE_STORES as data. The Rust reads from there, doesn't hardcode.

## Scope

Touches `rust/src/run_boot/vitals.rs` (~150 LoC) and `rust/src/run_boot/classify.rs` (~80 LoC). Both replaced with thin renderers that read from a bluebook. New surface : `runtime/boot/vitals.bluebook` (+ optional `runtime/boot/classify.bluebook`) declaring the layouts.

Pairs with i591 (conception_dir gap) — the whole boot-discovery surface deserves a bluebook-first pass together.

## Acceptance

- Removing a daemon from `boot.hecksagon` causes its line to disappear from the boot summary without touching Rust.
- Adding a daemon to `boot.hecksagon` causes its status line to appear in the summary without touching Rust.
- LINKED_STORES / PRIVATE_STORES come from a bluebook, not a `&[&str]` constant.
- The macrophage hook is silent on the boot vitals path.
