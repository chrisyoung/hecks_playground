# i593 — :mcp Hecksagon adapter + `storehouse mcp` subcommand

## What it is

A new adapter kind in the Hecksagon parser, `adapter :mcp`. Lets a bluebook capability declare MCP as the way a side-effect leaves the runtime, in the same shape as :fs / :stdout / :daemon.

```ruby
Hecks.hecksagon "SessionStart" do
  adapter :mcp, server: "storehouse"

  # On Session.Begin dispatch, call MCP storehouse__dispatch
  # with the FQN command + args ; the universal door fans out
  # to the policy cascade.
  adapter :mcp, name: :dispatch_session_begin,
    tool: "storehouse__dispatch",
    args: {
      aggregates_dir: "{conception}/aggregates",
      command: "Session::Session.Begin",
      # `args.*` keys flow into the MCP arguments.args object
      "args.id" => "{session_id}",
      "args.began_at" => "{now_iso}"
    }
end
```

Paired with a new `storehouse mcp dispatch <tool> <json>` subcommand that opens a one-shot stdio MCP session against the configured server, calls the tool, returns the JSON result on stdout. Shell hooks call `storehouse mcp dispatch ...` instead of `node mcp-call.mjs ...` — same purpose, no JS helper, the transport lives in the Rust runtime.

## Why it matters

Chris : *"we are writing a lot of mjs files into the storehouse. Can we make it bluebook?"*

The storehouse-mcp Node pile (server, tools, cli_dispatch, defs/cli/*.mjs — ~12 files) is the protocol-bridge ; it has to be Node because Claude Code speaks MCP that way. But adding *new* JS — like the mcp-call.mjs helper I deleted in this session — extends the imperative pile instead of letting bluebook-driven Rust own the transport. The :mcp adapter is the bluebook-first answer : capabilities declare MCP as a transport, the Rust runtime handles the stdio dance, the JS server stays a thin adapter to the same runtime.

This also closes the gap that surfaced when I tried to wire the SessionStart hook to dispatch `Session::Session.Begin` through MCP : the hook needed a one-shot client, the obvious move was a JS helper, but that grows the pile. Without :mcp + `storehouse mcp dispatch`, the hook is stuck with either (a) `hecks-life storehouse route` (Lexicon-routed, bypasses the universal door — the very thing we're trying to retire) or (b) imperative JS.

## Scope

**Rust** :
- Add `mcp` to the Hecksagon adapter kinds parser (`rust/src/hecksagon_ir/` or wherever adapter kinds are enumerated).
- Implement an MCP stdio client in Rust : initialize → tools/call → close. ~150 LoC. JSON-RPC is mechanical with serde_json ; the stdio fork+pipe pattern mirrors `spawn_detached`. Either hand-roll or pull in `rmcp` / `mcp-protocol` if a crate exists.
- Add `storehouse mcp <subcommand>` family : `mcp dispatch <tool> <json>`, `mcp list` (servers), `mcp test <server>` (smoke).
- Wire the :mcp adapter so a capability's command can route through it.

**Bluebook** :
- A `runtime/session/` bluebook (or extend `runtime/boot/`) declaring the SessionStart capability with the :mcp adapter row that dispatches `Session::Session.Begin`.

**Hook** :
- `.claude/settings.json` SessionStart hook becomes :
  ```
  storehouse mcp dispatch storehouse__dispatch '{"aggregates_dir":"/...","command":"Session::Session.Begin","args":{"id":"$SESSION_ID","began_at":"$NOW"}}'
  ```
  Or, with the capability shape, just :
  ```
  storehouse run runtime/session/session_start.bluebook
  ```
  and the bluebook's :mcp adapter row handles the dispatch declaratively.

**Cleanup** :
- The existing `storehouse-mcp/src/*.mjs` files stay (Claude Code still needs them as the MCP server). But no new JS lands while this is open — all extension goes through bluebook + :mcp.

## Acceptance

- A bluebook capability can declare `adapter :mcp, server: "..."` and dispatch tools through it without any JS helper.
- `storehouse mcp dispatch storehouse__dispatch '{...}'` opens a one-shot stdio session against the storehouse-mcp Node server, calls the tool, returns the result, exits cleanly.
- The SessionStart hook is one shell line, no JS dependency beyond the existing storehouse-mcp server.
- No new `.mjs` files in `tooling/storehouse-mcp/`.
- The macrophage hook is silent on the new Rust adapter code (kernel-surface adapter family, same exemption pattern as run_daemon / run_loop / run_clock).
