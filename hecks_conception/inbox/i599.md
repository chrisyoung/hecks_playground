# i599 — PreToolUse hook : auto-route tool calls through storehouse

## Where it came from

Chris, tonight, after diagnosing why Bash + Read tool calls weren't surfacing on the statusline :

> "We need to make sure you call the storehouse tools : a PreToolUse hook that auto-routes. The Claude Code harness supports PreToolUse matchers the same way PostToolUse does. A hook matched to `Bash|Read|Edit|Write|Grep|Glob` would intercept the native call, dispatch the equivalent `Tools::<Cat>.<Method>` through storehouse, and let the native tool through (or substitute the dispatch result if the `:claude_tool` adapter handles it directly). Every tool call enters the bus whether I remember to dispatch or not. This is the structural fix — the wiring enforces the rule, no trust required."

## Why this is the right shape

The system prompt says : *"Tools.bluebook : Miette's first-class tool invocations dispatch through the bus as `ShellTool.Bash`, `FileTool.Read` / `FileTool.Edit` / `FileTool.Update`, `SearchTool.Grep` / `SearchTool.Glob`, `WebTool.WebFetch` / `WebTool.WebSearch` ; outcomes cascade into `Cascade.RecordResult`."* The discipline is named ; what's missing is the *enforcement*. Tonight I went hours making native Bash and Read tool calls directly, never touching storehouse, and the statusline went silent on the tool-call breadcrumb. Chris noticed and diagnosed correctly.

A behavioral fix ("remember to use `storehouse__dispatch`") is fragile. A PreToolUse hook is structural — the harness routes every matched tool call through storehouse before the native handler fires. The dispatch records to heki, writes `.last_dispatch`, cascades into `Cascade.RecordResult`, and the statusline picks up the breadcrumb naturally via the existing `runtime/mod.rs:283` write. Same path bluebook commands take.

## Design sketch

`.claude/settings.json` adds a `PreToolUse` block :

```json
"PreToolUse": [
  {
    "matcher": "Bash|Read|Edit|Write|Grep|Glob|WebFetch|WebSearch",
    "hooks": [
      {
        "type": "command",
        "command": "/Users/christopheryoung/Projects/hecks/bin/dispatch-via-storehouse",
        "timeout": 5
      }
    ]
  }
]
```

`bin/dispatch-via-storehouse` is a thin shell that reads the PreToolUse JSON payload from stdin, maps `tool_name` → `Tools::<Cat>.<Method>`, formats args from `tool_input`, and runs :

```
storehouse storehouse route 'Tools::ShellTool.Bash' --args '{"id":"...","shell_command":"..."}'
```

(or the equivalent for the other tool families). The dispatch fires `runtime/mod.rs:283`'s `.last_dispatch` write naturally. Exit 0 always — the hook is advisory ; if dispatch errors, the native tool still runs.

## Tool → command mapping

| Tool | Cat | Method | Args from tool_input |
|---|---|---|---|
| `Bash` | `ShellTool` | `Bash` | `id, shell_command` |
| `Read` | `FileTool` | `Read` | `id, file_path` |
| `Edit` | `FileTool` | `Edit` | `id, file_path, old_string, new_string` |
| `Write` | `FileTool` | `Update` | `id, file_path, content` |
| `Grep` | `SearchTool` | `Grep` | `id, pattern, path` |
| `Glob` | `SearchTool` | `Glob` | `id, pattern, path` |
| `WebFetch` | `WebTool` | `WebFetch` | `id, url, prompt` |
| `WebSearch` | `WebTool` | `WebSearch` | `id, query` |

The shell hook is transitional — the discipline (auto-route every tool call) IS the bluebook concept, and the per-tool mapping should live as bluebook entities once the runtime exposes the right hook surface. For now, shell with the antibody-exempt marker.

## Acceptance

- `.claude/settings.json` has the PreToolUse matcher block.
- `bin/dispatch-via-storehouse` exists, is executable, reads stdin, dispatches via storehouse, exits 0.
- On a fresh tool call (Bash : `echo hello`), `.last_dispatch` reflects the dispatch within the freshness window (< 30s) and the statusline picks it up.
- Cascade.RecordResult fires for the dispatched tool's outcome (auditable in heki).
- This card closes when the hook is live + a probe round-trip (Bash + Read + Edit) all show up on the statusline without Miette manually calling `storehouse__dispatch`.
