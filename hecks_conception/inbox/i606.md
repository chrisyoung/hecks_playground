# i606 — MCP-side : require summary on every storehouse dispatch

## Where it came from

Chris, 2026-05-14, after asking me to narrate every storehouse call with a one-line summary and a `Calling Storehouse <Command>` label, then realizing :

> "Can we lock down the summary and calling template in the MCP?"

Right now the narration is behavioral — I have to remember to write the summary before the dispatch. Tonight's conversation already shows the gap : multiple turns of correction ("Calling storehouse 3 times… is collapsed, I need a summary"). Structural enforcement at the MCP layer ends the behavioral discipline drift.

## What changes

### MCP tool schema

`storehouse__dispatch` (and probably the rest of the storehouse MCP surface : `storehouse__query`, `storehouse__state`, etc.) gain a required `summary` string parameter :

```
storehouse__dispatch :
  required : aggregates_dir, command, summary
  optional : args
  rejected-with-error if summary missing or empty
```

### MCP rendering

The `summary` value becomes the visible label of the tool-call block in the Claude Code UI — so when the UI collapses to *"Calling storehouse 3 times…"*, each individual block shows its summary inline, not just the bare tool name. The operator can read the work-stream without expanding.

### Failure mode

MCP server returns an error if `summary` is missing or empty. The agent (me) gets the error back and has to retry with a summary. Forcing the discipline at the schema level means I cannot bypass even by forgetfulness.

## Length / format conventions

Proposed schema doc on the `summary` field :

  > "One-line, terse summary of what this dispatch DOES — e.g.,
  > 'write i606 card for MCP summary-required lock' or 'merge
  > sq/macrophage-rename-drop-suffix into main'. Becomes the visible
  > label of the tool-call block. Recommended ≤80 characters."

Not enforced as a length cap (no one likes magic numbers in schemas) but documented as guidance.

## Why MCP-layer and not behavioral

- Behavioral : the agent narrates before each dispatch. Drift-prone. Tonight's record : forgot summaries, got corrected, forgot again, got corrected sharper.
- MCP-layer : the schema rejects the dispatch without a summary. The discipline becomes substrate, not memory.
- Companion to **i603** (mechanical lock for routing tool calls through storehouse) — same pattern : structural enforcement of dispatch discipline, applied to a different facet (i603 = which path, i606 = what label).

## Acceptance

- `storehouse__dispatch`'s MCP tool schema declares `summary` as a required string parameter
- The MCP server rejects calls missing or with empty `summary`
- The Claude Code UI surfaces the `summary` value as the tool-call block label
- (Optional) cascade event records the summary for audit — every dispatch carries its self-described purpose
- Tonight's `Calling Storehouse <Command>` narration becomes redundant once the label surfaces from the schema ; agent prose can drop the inline label
