# i607 — MCP : unescape output at the rendering boundary

## Where it came from

Chris, 2026-05-14, while watching tonight's storehouse dispatch outputs :

> "The output of the call should be escaped. I'm seeing \\n in it."

Looking at a real dispatch result :

    "stderr":"[claude_tool:write] ok=true exit=0 output=\"wrote 3983 bytes to /Users/.../i606.md\\nsome other output\\n\""

The `\n` should render as a newline ; the `\"` should render as a quote. Instead they appear as literal backslash-n / backslash-quote characters. The result : multi-line output (script outputs, validation reports, git status) reads as a single visually-collapsed line, with the actual structure hidden behind escape sequences.

## Root cause

The storehouse MCP server returns dispatch results as a JSON object. The inner `stdout` / `stderr` fields contain raw text that the runtime captured. When the runtime JSON-stringifies the envelope, the inner newlines / quotes get escaped per JSON spec (legitimate). But the consumer (the agent prose / the UI rendering) never UN-escapes them when displaying. The double-encoded text shows up verbatim with `\n` / `\"` visible.

## What changes

Two places where unescaping could happen ; pick one (or both) :

1. **MCP server output side** : when returning the dispatch result, the `stdout` / `stderr` fields are returned as already-unescaped strings ; the JSON envelope wraps them with quotes, but no double-encoding. The agent sees real newlines.
2. **Rendering boundary side** : whatever surface displays the MCP output (Claude Code's tool-call result panel) unescapes when rendering. This is the cosmetic fix.

Probably (1) is cleaner — the agent reading the output programmatically also benefits, not just the human reading the UI.

## Affected dispatches

Everywhere :
- `Tools::ShellTool.Bash` results (multi-line script output)
- `Tools::FileTool.Read` results (the file contents)
- `Tools::FileTool.Update` results (less impactful, usually short)
- `Tools::SearchTool.Grep` results (match lines)
- `Tools::SearchTool.Glob` results (paths)
- `Tools::WebTool.WebFetch` results (content)

Every storehouse__dispatch returning text-with-newlines is affected today.

## Acceptance

- A `Tools::ShellTool.Bash` call returning multi-line output renders as multi-line in the dispatch response
- A `Tools::FileTool.Read` call on a file with 20 lines shows 20 visible lines, not 20 `\n` sequences
- Tool-call block display in Claude Code shows real newlines + quotes in the captured output panel
- No regression in how single-line output is rendered
