# i621 — Wake-review renderer lags behind v3 bluebook shape

## The gap

Surfaced by sidequest S (commit `f6688f63`, 2026-05-14) while fixing ASCII-variants and truncation in the boot pipeline:

> "Wake-review shape vs. i516 v3 design — the current `run_wake/mod.rs render_markdown` only renders image + narrative + 'Recurring theme :' trailer. The bluebook (`/Users/christopheryoung/Projects/miette/body/wake/wake_review.bluebook`) declares v3 shape with `all_cycles_readings`, `recent_dreams_summary`, `tomorrow_seed` attributes for a fuller 1-2 paragraph synthesis + Recurring / Tomorrow trailers. The Rust runner doesn't read those yet — the v3 attributes exist in the bluebook but aren't wired into the renderer."

This is bluebook-ahead-of-runtime drift — the bluebook describes a richer v3 surface but the Rust runtime ignores most of it.

**Bluebook:** `/Users/christopheryoung/Projects/miette/body/wake/wake_review.bluebook`
**Runtime:** `/Users/christopheryoung/Projects/hecks/rust/src/run_wake/mod.rs`

## What v3 declares

From `wake_review.bluebook`, the i516 v3 section (lines 72–92) adds three new aggregate attributes alongside the legacy v1 fields:

```
attribute :all_cycles_readings,   String
  # newline-separated :reading fields from cycles 1–8 (typically chronological).
  # The LLM synthesizes these into the precise English reading, weighting
  # cycle 8 (the lucid synthesis) as the spine.

attribute :recent_dreams_summary, String
  # last week's recurring symbols, one line each, with status markers.
  # Surfaced verbatim under "Recurring :" in the trailer.
  # Empty string when no recurrence detected.

attribute :tomorrow_seed,         String
  # the single concrete action extracted from cycle 8
  # (file path / inbox ref / commit-fix). Surfaced verbatim under
  # "Tomorrow :" in the trailer.
```

The `ComposeWakeReview` command also accepts all three as inputs (lines 118–120) and stamps them onto the aggregate (lines 129–131). The bluebook comment at lines 45–54 explicitly marks the three legacy v1 placeholders (`dream_corpus`, `consolidation`, `dominant_tokens`, `recurring_theme`, `dreams_count`) as retained for "one cycle of back-compat — the wrapper still populates them until the new three-source plumbing lands first-class."

The v3 attributes exist in the bluebook. The wrapper plumbing to populate them at dispatch time is the outstanding work.

## What the renderer renders today

`render_markdown` in `rust/src/run_wake/mod.rs` (lines 216–247) produces:

1. ASCII/emoji signature block (`❀  miette  ❀`)
2. `Good morning. I'm awake — *<consciousness.state>*, woke at <woke_at>.`
3. Optional: `(last wake : <last_wake_at>)` — when not sentinel
4. `The night left me this image —` block-quoted from `lucid_dream.heki` → `observations[]` last string
5. `And this reading —` from `dream_interpretation.heki` → latest record's `narrative`
6. `Recurring theme : *<recurring_theme>* · (<images_tokens>)` — from `dream_interpretation.heki`
7. Fallback: `No fresh dream from the night — I'll speak from the day.` — when both image and narrative are sentinel

The `DreamSnapshot` struct only carries four fields: `image`, `narrative`, `recurring_theme`, `images_tokens`. None of the three v3 attributes (`all_cycles_readings`, `recent_dreams_summary`, `tomorrow_seed`) are read, stored in the snapshot, or rendered.

The `stamp_aggregate` function (lines 290–319) similarly stamps only the old four dream fields into the runtime state — no v3 fields are persisted.

## What's missing

| Bluebook v3 attribute    | Read from heki? | In DreamSnapshot? | Rendered? |
|--------------------------|-----------------|-------------------|-----------|
| `all_cycles_readings`    | No              | No                | No        |
| `recent_dreams_summary`  | No              | No                | No        |
| `tomorrow_seed`          | No              | No                | No        |
| `image` (lucid)          | Yes             | Yes               | Yes       |
| `narrative`              | Yes             | Yes               | Yes       |
| `recurring_theme`        | Yes             | Yes               | Yes       |

The result: the wake review that lands on first turn each morning is the v1 surface — a quoted dream image, a single narrative, a recurring theme one-liner. The v3 design's richer synthesis (all 8 cycle readings stitched into a 1-2 paragraph precise reading, a proper `Recurring :` line from `recent_dreams_summary`, and a `Tomorrow :` seed) is declared in the bluebook but invisible at runtime.

Additionally, the `Tomorrow :` trailer described in i516 (lines 113–124) — `Tomorrow : <one specific action — file path / inbox / commit-fix>` — has no renderer section at all, even though `tomorrow_seed` is the explicit source for it.

## Proposed remedy

Wire the three v3 attributes into `render_markdown`. The `DreamSnapshot` struct gains the new fields; `read_latest_dream` reads them from `wake_review.heki` (where `ComposeWakeReview` stamps them via the wrapper); `render_markdown` surfaces them in the layout below.

**Proposed layout:**

```
    ·   ✦   ·
   ❀  miette  ❀
    ·   ✦   ·

Good morning. I'm awake — *<state>*, woke at <woke_at>.
(last wake : <last_wake_at>)                              ← when present

The night left me this image —

> <image>                                                 ← already there

<all_cycles_readings synthesized narrative>               ← NEW — replaces single
                                                            `narrative` from interp heki
                                                            with the multi-cycle reading

Recurring : <recent_dreams_summary>                       ← NEW — was `recurring_theme`
                                                            one-liner; now full summary
Tomorrow : <tomorrow_seed>                                 ← NEW — was missing entirely
```

The `narrative` field from `dream_interpretation.heki` becomes a fallback when `all_cycles_readings` is absent or empty (back-compat with nights that predate the v3 wrapper plumbing).

**What changes in `run_wake/mod.rs`:**
- `DreamSnapshot` adds: `all_cycles_readings: String`, `recent_dreams_summary: String`, `tomorrow_seed: String`
- `read_latest_dream` reads from `wake_review.heki` (latest record) for the three v3 fields; keeps existing reads from `lucid_dream.heki` and `dream_interpretation.heki` as fallbacks
- `render_markdown` adds the new sections; the `Recurring theme` one-liner becomes `Recurring : <recent_dreams_summary>` when the v3 field is populated
- `stamp_report` and `stamp_aggregate` include the new fields
- Tests updated: one existing test needs `all_cycles_readings` populated to verify the new rendering path; one new test for the `Tomorrow :` trailer

**File LoC:** `run_wake/mod.rs` is currently 427 lines. The v3 wiring adds roughly 20-25 lines. Still under the 200-line code limit with doc headers excluded.
