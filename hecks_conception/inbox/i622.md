# i622 — StoreHouse should log to stdout

## 1. The verbatim quote

> "storehouse should log to stdout"

Said 2026-05-14, immediately after "sidequests should go through StoreHouse." Paired
observations: the bus should be a first-class visible entity, not a silent substrate.

---

## 2. What's logged today (and where)

### `rust/src/runtime/mod.rs` — adapter dispatch surface

All current runtime logging goes to **stderr** via `eprintln!`. The meaningful lines:

**claude_tool family** (lines 718–836):
- `[claude_tool:debug] resolve cmd=… target=… hecksagons=…` — emitted when
  `STOREHOUSE_DEBUG_CLAUDE_TOOL` is set; goes to stderr.
- `[claude_tool:debug] matched N adapter(s) for target=…` — same gate; stderr.
- `[claude_tool:<tool_name>] ok=… exit=… output=… error=…` — the one unconditional
  per-invocation summary line (line 798–801); goes to **stderr**. This is the
  closest thing to a dispatch log that exists today.
- `[claude_tool:debug] no result_into on adapter — skipping cascade` — stderr, debug-gated.
- `[claude_tool:debug] cascaded into <target> ok` / `cascade into <target> failed: …` — stderr, debug-gated.

**llm adapter family** (lines 547–573):
- `[llm:debug] resolve_llm_adapters cmd=… agg_type=… providers=… fired=…` — stderr,
  behind `STOREHOUSE_DEBUG_LLM`.

**compute adapter family** (lines 874–893):
- `[compute:debug] resolve_compute_adapters cmd=… fired=…` — stderr, debug-gated.

**heki.rs** (line 88):
- `[heki:<op>] <audit_tag> → <path>` — unconditional stderr on every read/write
  to the .heki store.

**loop_driver.rs** (lines 230, 260, 267):
- `[loop_driver] dispatch error '…': …` — stderr on dispatch failures inside the
  pulse loop.

**mcp_dispatcher/mod.rs** (line 127):
- Child process stderr is routed to `Stdio::null()` — MCP server stderr is discarded
  entirely.

### Summary of stream destinations today

| Surface | Destination | Gate |
|---|---|---|
| `[claude_tool:<name>] ok=…` | stderr | unconditional |
| `[claude_tool:debug] …` | stderr | `STOREHOUSE_DEBUG_CLAUDE_TOOL` |
| `[llm:debug] …` | stderr | `STOREHOUSE_DEBUG_LLM` |
| `[compute:debug] …` | stderr | `STOREHOUSE_DEBUG_COMPUTE` |
| `[heki:<op>] …` | stderr | unconditional |
| `[loop_driver] …` | stderr | unconditional (error paths) |
| MCP child stderr | /dev/null | — |
| Policy triggers (PolicyEngine::react) | **silent** | — |
| Cascade steps (dispatch_cascade) | **silent** | — |
| Macrophage complaints | stderr (main.rs) | unconditional |
| Top-level dispatch entry | **silent** | — |

## 3. What's silent today

Significant runtime events that fire but produce no output:

**Policy chains** — `PolicyEngine::react` yields `Vec<PolicyTrigger>`; the triggers
are drained and dispatched in the runtime's `drain_policies` path. No line is printed
for "policy X fired, triggering command Y." The engine has no print statements.

**Cascade.RecordResult invocations** — `dispatch_cascade` calls that chain a tool
result back into the aggregate via `result_into` are logged only on the debug-gated
`[claude_tool:debug] cascaded into … ok` line. The cascade entry is silent at
`normal` verbosity.

**Macrophage observations** — macrophage complaints live in `main.rs` and print to
stderr. But macrophage checks are invoked from the CLI, not from within the runtime
dispatch path — so an in-flight dispatch that triggers a macrophage concern produces
nothing at the dispatch layer.

**Identifier-service mintings** — when i614's substrate lands, every `mint_id` call
will be silent. No stdout record of which aggregate got a fresh identifier.

**Top-level dispatch entry** — calling `storehouse__dispatch` (MCP) or `storehouse
<root> <FQN>` (CLI) produces no opening log line. The operator sees no confirmation
that the command was received, only output from whatever adapter fires downstream.

## 4. The proposed shape

One-line stdout records, ISO-8601 timestamps, structured enough for `grep` / `jq`
pipelines. Three record kinds:

```
[2026-05-14T18:42:01Z] dispatch  Tools::ShellTool.Bash#cmd_abc123   "run bash command"
[2026-05-14T18:42:01Z] event     Tools::ShellTool.BashRan#evt_def456
[2026-05-14T18:42:01Z] cascade   Cascade.RecordResult#cmd_abc123     ok=true
```

Field layout:

| Field | Content |
|---|---|
| timestamp | UTC, RFC-3339, seconds precision |
| kind | `dispatch` / `event` / `cascade` / `policy` |
| subject | `Domain::Aggregate.Command#<invocation-id>` |
| trailer | human-readable label or `ok=true/false` |

**Per-dispatch line** — emitted at the entry of `Runtime::dispatch`, before adapter
resolution. Includes the FQN command name and the invocation ID (from i613's envelope
once that lands; use a short hex token until then).

**Per-event line** — emitted when an event is appended to the aggregate's event log.
Includes the event name and the originating invocation ID.

**Per-cascade step** — emitted when `dispatch_cascade` fires a chained command.
Includes the cascade target FQN, the upstream invocation ID, and `ok=true/false`.

**Per-policy line** — emitted when `PolicyEngine::react` returns a trigger. Includes
the policy name, the triggering event, and the follow-up command.

---

## 5. Volume concern and mitigation

A busy dispatch tree (boot, pulse, dream cycle) can produce dozens of lines per
second. Uncontrolled stdout would swamp `tee` pipelines and make `wrangler tail`
noisy.

Propose `STOREHOUSE_LOG` env var with three levels:

| Value | Behaviour |
|---|---|
| `quiet` | nothing to stdout; adapter errors to stderr only |
| `normal` (default) | one line per dispatch + one per cascade; events and policies suppressed |
| `verbose` | all four record kinds; no per-attribute trace |

The default (`normal`) gives a legible running record without per-event noise. Operators
who want full visibility set `STOREHOUSE_LOG=verbose`. Production deployments or
embedded runs set `STOREHOUSE_LOG=quiet`.

The existing `STOREHOUSE_DEBUG_CLAUDE_TOOL` / `STOREHOUSE_DEBUG_LLM` env vars stay as
fine-grained adapter-family gates on top of whatever `STOREHOUSE_LOG` selects.

---

## 6. Where the change goes

**Rust runtime — kernel-floor.** The print statements belong in:

- `rust/src/runtime/mod.rs` — `dispatch` entry (dispatch record) and `drain_policies`
  (policy record).
- `rust/src/runtime/event_bus.rs` or the emit path in `mod.rs` — event record.
- The `dispatch_cascade` call site in `mod.rs` — cascade record.

This is not bluebook work. The Bluebook contract is silent about observability
infrastructure; logging is substrate. No `.bluebook` file changes are needed.

The `STOREHOUSE_LOG` env var is read once at process start and stored in the
`Runtime` struct so every dispatch shares the same level without repeated env lookups.

## 7. Relationship to existing cards

**i613 — StoreHouse wraps every command** — i613 introduces a command envelope with
a shared invocation ID. The `#<id>` suffix in the proposed log format depends on that
envelope. i622 should land after i613 or co-ordinate so the ID field is available.

**i615 — PromptReceived / Unfurling** — i615 produces events that flow through the
same event bus. Once i622 is live, `verbose` mode will echo those events too (e.g.
`event Framework::Mind.PromptReceived#…`), giving Miette's boot a transparent trail.

**i618 — ResponseEmitted** — the ResponseEmitted event from i618 is another event
that will appear in the verbose log. Operators watching `tail -f` will see the full
request→response arc as three lines: dispatch, event, cascade.

**i620 — smoke test** — i620 aims to make the smoke test assert on structured output.
Once i622 lands, the smoke test can grep stdout for the dispatch line instead of
inspecting heki state — cleaner and adapter-agnostic.

---

## 8. Acceptance

This card is closed when:

1. Running any `storehouse__dispatch` call on the Rust runtime prints at least one
   stdout line in the format above (at `STOREHOUSE_LOG=normal` or unset).
2. Cascade chains (`result_into` wiring) print a cascade line on stdout.
3. Events appended to an aggregate's log print an event line when
   `STOREHOUSE_LOG=verbose`.
4. Policy triggers print a policy line when `STOREHOUSE_LOG=verbose`.
5. Stderr retains only adapter failures, macrophage complaints, and validator errors —
   no operational chatter moves to stderr that belongs on stdout.
6. `STOREHOUSE_LOG=quiet` suppresses all stdout records.
7. Existing `STOREHOUSE_DEBUG_*` gates continue to function independently.
