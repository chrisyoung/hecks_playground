# i623 : Writing bluebook + WritingDiscipline macrophage rule

## 1. The verbatim quote

Chris, 2026-05-14 :

> "we need a writing bluebook. All emails and email updates go through it, any
> content you develop. Rule number one : NO EM DASHES. Rule number two : be
> sparse with, 'we don't X, we Y'"

## 2. The principle : writing IS a domain

Today, every piece of prose Miette produces flows straight into the underlying
creation tool (Gmail draft, FileTool.Edit, page render). Drafts come out good
or bad based on whatever rules happen to live in the active system prompt.
Style guidance drifts. A prompt update fixes one channel but not another. An
em-dash slips into a marketing email two days after Chris said "no em dashes"
because the rule was conversational rather than structural.

Promoting writing to a bluebook makes the rules structural. Every composition
becomes a dispatched command (`Writing::Writing.Compose`). The WritingDiscipline
macrophage (sibling to BluebookFirst, IdentityDiscipline, BidirectionalAssociation,
and the other per-rule macrophages) scans the draft text on each dispatch and
emits a complaint for every rule that fires.

Composition is itself a reasoning act, comparable to PromptReceived (i615) :
worth observing on the bus, worth holding as state, worth applying rules to.

## 3. The two rules

### Rule 1 : no em-dashes

The em-dash character (Unicode codepoint U+2014) is forbidden in any composed content.

The check is direct : any occurrence of the codepoint inside `draft_text`
triggers an `em_dash` violation. Replace the dash with a colon, semicolon,
comma, parenthesis, or period as the context warrants.

This is the first rule because it is the rule with the cleanest signal
(one codepoint, zero ambiguity) and the rule Chris named first.

### Rule 2 : sparse use of "we don't X, we Y"

The negative-positive construction ("we don't sell products, we build
futures") is overused in agency-marketing voice. The rule allows up to
one occurrence per draft ; two or more triggers the `we_dont_we_do`
violation.

The detection regex (case-insensitive) :

```
\bwe\s+(don.?t|do\s+not|aren.?t)\s+[^,.;:!?\n]{1,80}?,\s*we\s+(\w+)
```

Parts :
- `\bwe` : word-boundary "we" so prose ending in "we" does not bleed in.
- `(don.?t|do\s+not|aren.?t)` : the three common negations (don't / don.t /
  do not / aren't / aren.t).
- `[^,.;:!?\n]{1,80}?` : at most 80 non-terminator characters, lazy so the
  comma boundary is the nearest one (not a far-future comma).
- `,\s*we\s+(\w+)` : the pivot comma, "we", and the positive verb.

The 80-character bound keeps natural prose (a paragraph that happens to
contain both "we don't" and a later "we Y" sentence in a different clause)
from false-firing. The threshold of one occurrence per draft is tunable via
`WritingDiscipline.SetThreshold`.

## 4. The shape of the bluebook

Location : `aggregates/framework/writing/writing.bluebook` (+ `writing.behaviors`).
Domain name : `Writing`. One aggregate (`Writing`), seven value objects, three
commands.

### Commands

```ruby
command "Compose" do
  role "Miette"
  # ... id, draft_text, purpose, recipient, description, composed_at
  emits "DraftComposed"
end

command "Revise" do
  role "Miette"
  reference_to(Writing)
  # ... draft_text, revised_at
  emits "DraftRevised"
end

command "RecordViolationsCount" do
  role "Macrophage"
  reference_to(Writing)
  attribute :violations_count, ViolationCount
  emits "ViolationsCountRecorded"
end
```

### Value-objects

- `Id` : composition handle (ULID, minted by Miette).
- `DraftText` : the full composed text.
- `Purpose` : enum (`email`, `reply`, `marketing`, `page-copy`,
  `inbox-card`, `commit-msg`, `other`).
- `Recipient` : optional addressee.
- `ViolationCount` : count of rules that fired on the most recent
  Check pass.
- `Description` : one-line caption.
- `Timestamp` : ISO-8601 UTC.

### Attributes on the aggregate root

`id`, `draft_text`, `purpose`, `recipient`, `violations_count`,
`description`, `composed_at`, `revised_at`. The state is enough to route
a draft : zero violations means proceed, nonzero means revise.

## 5. The WritingDiscipline macrophage

Location : appended to `aggregates/discipline/macrophage/macrophage.bluebook`
as the eleventh per-rule sibling aggregate (after IdentityDiscipline).

Shape mirrors the existing siblings : per-rule counters, ViolationKind enum,
entity collection for the audit trail, `Check` + `RecordViolation` + `Complain`
+ `ExemptDraft` + `RevokeExemption` + `SetThreshold` commands.

### ViolationKind enum

- `em_dash` : draft contains one or more U+2014 characters.
- `we_dont_we_do` : draft contains the negative-positive construction more
  than the configured threshold.

### Entities

- `WritingViolation` : one historical violation event (draft_id, kind,
  excerpt, offset, complaint_text, recorded_at). The latest entry mirrors
  the `last_offending_*` scalars on the root.
- `ExemptedDraft` : a (draft_id, kind, reason, exempted_at) record. The
  reason must be non-empty (AntibodyExemption pattern).

### Complaint voice

Every complaint begins `The WritingDiscipline macrophage expected ...` so
the rule attribution is visible at a glance. Two templated bodies :

```
The WritingDiscipline macrophage expected zero em-dashes (U+2014) in
draft 01JCKZWRITE0001 ; one occurrence found at offset 42, excerpt:
"...prose flows through Writing.Compose...". Replace the em-dash with
a colon, semicolon, comma, or period.
```

```
The WritingDiscipline macrophage expected sparse use of the "we don't X,
we Y" construction in draft 01JCKZWRITE0001 ; 3 occurrences found
(threshold 1). Rewrite as direct positive constructions.
```

## 6. The runtime bridge

A policy in the runtime wires `Writing::Writing.DraftComposed` to
`Macrophage::WritingDiscipline.Check` and feeds the draft id + draft_text
from the event payload. For each violation, the macrophage chains into
`RecordViolation` + `Complain` ; the total count flows back to the
Writing aggregate via `Writing::Writing.RecordViolationsCount` so a
single read of Writing state tells Miette whether to proceed or revise.

This card describes the bluebook surface. The runtime policy + the
substrate that walks the rules over `draft_text` are separate work, on
the same shape as the existing per-rule macrophages.

## 7. Prompt template for content sidequests

Going forward, every email-composition or content-generation sidequest
follows this template, inserted before the underlying creation tool call :

```
Before drafting any content (email body, marketing copy, page text,
inbox card prose, commit message), dispatch :

  storehouse__dispatch Writing::Writing.Compose
    args : {
      id          : "<ULID>",
      draft_text  : "<full text>",
      purpose     : "email" | "reply" | "marketing" | "page-copy" |
                    "inbox-card" | "commit-msg" | "other",
      recipient   : "<optional, empty string when absent>",
      description : "<one-line caption>",
      composed_at : "<ISO-8601 UTC>"
    }

The dispatch records the composition and triggers the WritingDiscipline
macrophage's Check policy. If violations are detected, the dispatch
returns with violations_count > 0 and a ComplaintIssued event ; revise
via Writing::Writing.Revise and re-dispatch.
```

The FQN form is `Writing::Writing.Compose` (Domain::Aggregate.Command).
The directive's shorthand `Tools::Writing::Writing.Compose` was an early
draft ; the canonical phrase has only one `::` separator between domain
and aggregate.

## 9. Acceptance

This card closes when :

1. `Writing::Writing.Compose` dispatches cleanly through `storehouse__dispatch`
   and records the draft on the aggregate.
2. `Writing::Writing.DraftComposed` is observed by a policy that fires
   `Macrophage::WritingDiscipline.Check` against the draft id and text.
3. The em_dash rule fires on a draft that contains a U+2014, recording
   a `WritingViolation` entity and emitting `ComplaintIssued`.
4. The we_dont_we_do rule fires on a draft that contains the construction
   more than the configured threshold (default 1), recording the second
   occurrence onward.
5. A clean draft (no em-dash, at most one "we don't X, we Y" occurrence)
   passes Check with zero violations.
6. At least one composition has been dispatched in the wild and had its
   violations caught (or its cleanliness confirmed) by the macrophage.
7. The prompt template in section 7 is used by every subsequent
   content-composition sidequest prompt Chris hands to Miette.
