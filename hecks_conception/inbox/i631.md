# i631 — swappable status bars + a "last command" status bar

## What Chris asked for

> "i should get a slash command that lets me swap status bars. We should
> build a command status bar so I can see the last command run."

Two pieces :

1. **A slash command to swap status bars** — cycle/select which status
   bar mode is rendered, from the prompt, without editing config.
2. **A new "command" status bar mode** — surfaces the last dispatched
   command (the "what are we working on" signal), not the body-vitals
   line.

## Relevant existing infra (so this composes, not duplicates)

- The statusline is a bluebook capability : `storehouse statusline`,
  brain in `capabilities/statusline/` (kernel-surface runner in
  main.rs `run_statusline`, same i80 retirement family).
- A status-bar **mode** concept already exists :
  `~/Projects/miette-state/information/status_bar/mode.heki`. "Swap
  status bars" ≈ a command that sets/cycles that mode ; the renderer
  branches on it.
- The "last command run" is **already plumbed** : `Runtime::dispatch`
  writes a breadcrumb to `<data_dir>/.last_dispatch` (the
  `format_breadcrumb_phrase` `Domain::Aggregate.Command` + a unix ts ;
  top-level, non-`HECKS_DAEMON` dispatches only — see
  rust/src/runtime/mod.rs). A "command" status bar mode is mostly a
  new render branch over that file.

## Bluebook-first shape (suggested, not locked)

- A `StatusBar` mode value object / aggregate with the set of modes
  (vitals / command / …) ; `StatusBar.SwapMode` (cycle) +
  `StatusBar.SetMode <mode>` commands ; the slash command is a thin
  route to those (rides i80 cli-routing-as-bluebook once it lands —
  do NOT add another hardcoded main.rs subcommand).
- The "command" mode renderer reads `.last_dispatch` and formats the
  phrase + relative age.

## Disposition

Filed for later per Chris. Not to build now. Good candidate to ride
the i80 cli.bluebook arc (the slash command becomes a declared route,
not imperative glue) and the existing statusline capability bluebook.
