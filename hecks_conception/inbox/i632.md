# i632 — validator escape hatch for documentation-only bluebooks

## Found by

The macrophage bluebook-audit sweep (agent a1d57263, 2026-05-16) over
77 bluebooks. `language/grammar/bluebook.bluebook` reports INVALID with
the single error **"Domain has no commands"** — but that file is
*intentionally* command-less: its own prose says "This domain is not
booted as a runtime organ — it carries no live state. It documents
shape." It declares entities to describe the IR contract, not a
dispatchable domain.

## The gap

The "Domain has no commands" DDD-consistency rule is correct for
behavioral aggregates but is a false positive for IR-contract /
documentation bluebooks. There is no current way to declare
"this bluebook documents shape, it is not a runtime organ."

## Proposed (decide API first)

An explicit, declarative escape hatch — e.g. one of:
- `category "meta"` (or `"documentation"`) recognised by the validator
  as command-optional ; or
- a top-level `documentation true` / `read_only` marker on the bluebook ; or
- the validator treats a bluebook with entities-but-no-aggregates-
  with-commands AND an explicit marker as VALID.

Not: adding a no-op `DescribeShape` command just to satisfy the rule
(dishonest — the agent explicitly rejected this).

## Parity note

The validator has a specializer golden (validator_shape). This change
is parity-sensitive — sequence it AFTER the Track-2 runtime/hecksagon
golden reconciliation (avoid concurrent specializer-golden churn).
Bluebook-first: the rule + its exemption should be expressed in the
validator's shape, not regex-patched.
