# i636 — seed SubcommandRegistry FROM subcommand.fixtures (not hand list)

## Now (i80 Unit D, committed)
- bin/seed-subcommand-registry : 30 hand-written `upsert` lines.
- cli/subcommand/subcommand.fixtures : 30 `fixture` rows (source of truth).
- information/subcommand_registry/subcommand.heki : 30 rows, seeded.
- fn main() load_cli_routes() reads the correct path ; routing is
  live-proven (keystone `storehouse loop aggregates Inbox::Inbox.Check`
  resolved through the registry, not fallback). NO orphan catalog
  (the old information/subcommand.heki does not exist).
- State : functionally complete + consistent, NOT drift-proof.

  `Subcommand.Register` dispatch per fixture row (bluebook-first),
  or a parser that materialises the heki from the .fixtures DSL.
- Add a parity check : fixtures row count == heki row count (CI/smoke).

fixtures↔heki parity guard exists.
