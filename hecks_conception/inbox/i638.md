# i638 — Unit E : handler bodies -> typed cadence VOs (E-0 .. E-4)

## ⚠ Original premise was DEAD (resolved 2026-05-17)

The original design (from the i2 restart card, verbatim) said : *graft
CadenceInvocation / CadenceInterval / GatePredicate / ClockSegment
onto the EXISTING `SubcommandRegistry::Subcommand` aggregate.*

**That aggregate does not exist on origin/main.** `6ca50098 cli:
strip Subcommand catalog — registry belongs in main.rs as kernel-
floor` is published on origin/main (verified : `git merge-base
--is-ancestor 6ca50098 origin/main` → YES). The commit message is an
explicit architectural decision *against* the original mechanism.
Same staleness class as i637 — the i2 card's SHAs/premises were
written against the i630 branch, origin/main has since moved.

**Lesson (meta) :** the i2 restart-card pattern needs a freshness-check
step — "verify the card's structural premises against current
origin/main before executing, not just its SHAs". **Filed as i643.**
The i2 card itself said "verify real state, do not trust this card's
SHAs blindly" — that instruction is what caught both i637 and i638.

## Resolution : HeartbeatScheduler host (Chris's call, 2026-05-17)

Keep the registry kernel-floor (honors 6ca50098). Host the cadence
value-objects on the EXISTING `HeartbeatScheduler` bluebook
(`aggregates/framework/heartbeat_scheduler/heartbeat_scheduler.bluebook`)
— it already models rhythmic command dispatch ("any 'fire X every N
ticks' intent in the framework lands here"), is a documented stub
awaiting runtime iteration, and already declares `Cadence` (ticks),
`ScheduledCommand` (verb = the FQN), `Schedule` entity, Tick /
Dispatch / RegisterSchedule. Bluebook-first AND honors the published
decision. No revived/reversed decisions.

## Locked design (E-0 complete — verified against origin/main 1b08a2d4)

### The i630 bug class, concretely
`run_loop` (main.rs ~4042–4188), `run_pm_loop` (~4225–4413),
`run_clock` (~4447–4562) each carry FQN dispatch addresses as raw
`String`/`&str` and slice them with `split(',')` / `splitn(2,':')` /
`split_once('=')` / `split_once('.')`. `require_fqn_dispatch_address`
+ the "i630 : do NOT truncate" comments are *comment-guards*. The
structural fix : parse each FQN exactly once into a typed VO at the
arg boundary ; handlers then hold only typed values and dispatch from
`.verb` — `.split('.').last()` truncation becomes inexpressible.

### VOs grafted onto HeartbeatScheduler (E-1)
- `ScheduledCommand` — **EXISTS** (`attribute :verb, String`). The
  crux : once an FQN is a ScheduledCommand it is never sliced again.
- `CadenceInterval` — NEW. Wall-clock loop interval (`--every` /
  `--poll`). `attribute :millis, Integer`. (Distinct from the
  existing `Cadence`, which is tick-count for autonomic dispatch.)
- `GatePredicate` — NEW. The `--gate <file.heki>:<field>=<value>`
  triple. `attribute :heki_path, String ; :field, String ;
  :expected, String`.
- `ClockSegment` — NEW. `--segment <lo>-<hi>:<FQN>`. `attribute
  :lo_hour, Integer ; :hi_hour, Integer ; :command, ScheduledCommand`.
- `CadenceInvocation` — NEW. The parsed result of one CLI cadence
  invocation : `commands` (list of ScheduledCommand — i106 rotation),
  `interval` (CadenceInterval), `gate` (optional GatePredicate),
  `segments` (list of ClockSegment — clock mode). This is exactly
  what the bridge returns.
Companion ratchet : extend `heartbeat_scheduler.behaviors`. `storehouse
validate` must be VALID.

### The single bridge (E-2)
One Rust fn `parse_cadence_invocation(handler: &str, args: &[String])
-> CadenceInvocation` — the ONLY place FQN/duration/segment string
surgery is allowed. Each FQN → `require_fqn_dispatch_address` →
`ScheduledCommand`. Kernel-floor Rust mirror of the bluebook VOs
(bluebook = contract, main.rs = kernel-floor — consistent with the
loop/daemon/macrophage family + the 6ca50098 principle). Must be
IR-claimed or it counts against the LoC ratchet.

### The shims (E-3)
`run_loop` / `run_clock` → ~30-line shims : `let inv =
parse_cadence_invocation(..); load+boot ; loop { gate? ; dispatch
inv.commands[idx].verb ; sleep }`. `run_pm_loop` keeps `LoopDriver`
(tick-engine untouched per design) but is fed typed `inv` instead of
raw `Vec<String>`. Net : large LoC *reduction* in main.rs.

### ⚠ Scope constraint the original card MISSED (E-3/E-4)
`rust/src/main.rs` is a **specializer byte-identity-tracked shape**
(pre-commit Gate 9 ; cf commit `29436f98 ... shape-edited, main.rs
regenerated, gate 29/0/1`). Rewriting the handlers is NOT "edit
main.rs" — it is "edit the `cli_dispatch_shape` (or owning shape)
codegen fragments so `storehouse specialize` → `rust/src/main.rs`
is BYTE-IDENTICAL, then regenerate". This is real extra surface the
original card did not account for and is the main reason E-1..E-4
is a fresh-focused-session job, not a deep-context tail.
