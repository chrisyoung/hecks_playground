# i640 — dispatch silently no-ops on unresolved reference; file-vs-dir loads different wiring

## Found
Conceiving Governance (aggregates/framework/governance). Policy.Permit
(reference_to(Policy)) returned ONLY `[ts] dispatch ...#inv` and nothing
else — no error, no ok:false — across 4 arg-shape variants. Propose
(no reference) always ok:true. Root cause via verify-state : no
governance.db existed ; .bluebook-FILE dispatch = memory-only, the
sibling governance.hecksagon only loads on DIRECTORY dispatch.

## Fix wanted
1. Runtime MUST emit a structured error when a command's
   reference_to() target is unresolved (validators-first ; a
   swallowed failure is ungovernable by definition).
2. Either auto-discover a sibling .hecksagon for single-file
   dispatch, OR emit a one-line notice on boot stating which
   adapter (memory vs sqlite) and store path are in effect.

## Also (model, not runtime)
Governance commands emit events (the log = the point) but declare
no `mutations`, so Policy.permitted / .status don't accumulate.
Acceptable for an event-audit reading ; needs mutations for a
queryable live allow-list. Named, not hidden.
