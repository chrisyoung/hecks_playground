# i642 — pre-commit harness was worktree-blind ($REPO anchored to main checkout)

## Symptom (how it surfaced)

Closing i637 (a 2-line inert inbox-doc edit) in a worktree off
`origin/main` was blocked by `statusline_regression_smoke.sh`. The
worktree's `origin/main` source is provably green; the main checkout
was mid-i630-statusline-refactor with a matching in-flight binary.

Isolated conclusively : same clean `origin/main` binary, run from the
worktree → `OK`; run from the main checkout (i630 catalog) → `FAIL`.
`HECKS_BIN` could not rescue it because the failing input was the
catalog the test reads via `REPO_ROOT`, which the harness pinned to
the main checkout.

## Root cause

`tooling/git-hooks/pre-commit` :

```
REPO="$(cd "$(dirname "$0")/../.." && pwd)"
```

`core.hooksPath` = the main repo's `.git/hooks` (shared by every
worktree). So `$0` is always the main-repo hook ; `$REPO` and every
derived path (`STOREHOUSE`, `CONCEPTION_DIR`, the parity tests) point
at the main checkout no matter which worktree git is committing.
Gates therefore validate the wrong tree + binary.

## Fix applied (this session)

Derive `$REPO` from the working tree git is actually committing —
git runs hooks with cwd = that worktree's root :

```
REPO="$(git rev-parse --show-toplevel 2>/dev/null)"
[ -n "$REPO" ] || REPO="$(cd "$(dirname "$0")/../.." && pwd)"
```

Fallback preserves old behaviour if rev-parse is unavailable.
Verified : from the worktree → worktree root ; from the main repo →
main repo (unchanged, no regression). Mirrors the i565
worktree-awareness already in the smoke script.

## Deeper fix

The minimal shell anchor is a surface (Nirmanakaya) patch. The
structural fix — kernel hooks declared and registered from bluebook
rather than hand-anchored shell — is tracked by **i594**
(bluebook-driven kernel hook registration). When i594 lands, the
pre-commit harness anchor becomes a bluebook concern and this class
of `$0`-vs-worktree bug cannot recur.

## Closes when

Worktree commits gate against their own tree (done — applied +
verified this session). Deeper structural fix deferred to i594.
