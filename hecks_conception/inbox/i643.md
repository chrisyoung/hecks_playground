# i643 — restart-card pattern needs a freshness-check step

## What happened (2026-05-17 session)

The i2 restart card handed off "do i637 + i638". Both were filed
2026-05-16 against the local i630 branch, NOT yet pushed. By the
next session origin/main had moved (PRs #671/#672/#673 merged) :

- **i637** — the contaminated commit `38189ad9` it wanted to split
  was now *published on origin/main*. The card's recipe
  (`git rebase -i` + replay) would have required a force-push to
  main. The premise ("local-only, pre-PR") was dead. Closed obsolete
  per the card's own fallback.
- **i638** — the aggregate it wanted to graft VOs onto
  (`SubcommandRegistry::Subcommand`) had been *deliberately stripped*
  from origin/main by `6ca50098` ("registry belongs in main.rs as
  kernel-floor") — an explicit architectural decision *against* the
  carded mechanism. Required a fresh architectural decision from
  Chris (→ HeartbeatScheduler host).

Both were caught only because the i2 card itself carried the
instruction *"FIRST: verify real state, do not trust this card's
SHAs blindly."* That single line saved two dead-premise executions.
It should not be optional prose buried mid-card — it should be the
pattern.

## The fix

Make a freshness-check the **mandatory first step** of every
restart-card execution, and bake the prompt for it into the card
template the WakeReview / restart-card writer emits :

1. **SHA liveness** — for every SHA the card references :
   `git merge-base --is-ancestor <sha> origin/main` →
   if YES, any "rewrite/split/rebase this" instruction is now a
   force-push to main : STOP, treat as obsolete, use the fallback.
2. **Structural-premise liveness** — for every "the EXISTING X"
   the card asserts, grep origin/main for X. If absent, the
   mechanism is dead : STOP, surface to Chris before executing.
3. **Only after both pass** — execute the card body.

Mechanise where possible : a `storehouse restart-card verify <card>`
that extracts referenced SHAs + asserted aggregate/file names and
runs the two checks, exiting non-zero with the dead premises listed.
Then the freshness-check is a dispatch, not a discipline reminder —
consistent with the bluebook-first standard (the check is a domain
concern, not a shell habit).

## Closes when
The restart-card writer emits the freshness-check as step 0 of every
card body, AND `storehouse restart-card verify` (or equivalent
bluebook-dispatched check) exists so the verification is mechanical,
not a remembered instruction.
