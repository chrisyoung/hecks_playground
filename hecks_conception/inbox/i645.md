# i645 - EmailTool.GetAttachment : :web_tool runtime arm

## State (what exists now)
- BLUEBOOK contract: aggregates/framework/tools/tools.bluebook
  EmailTool.GetAttachment (message_id, attachment_id, save_path,
  description -> emits AttachmentFetched). Already conceived.
- HECKSAGON binding (added this session): tools.hecksagon
  adapter :web_tool, command "EmailTool.GetAttachment",
  tool "gmail_attachment", result_into "Cascade.RecordResult".
  Parses clean (dump-hecksagon OK ; run hecksagon parity).
- TRANSITIONAL adapter: ~/.config/miette/fetch_gmail_attachment.py
  (53 lines, +x). Reachable NOW via Tools::ShellTool.Bash :
  python3 ~/.config/miette/fetch_gmail_attachment.py \
    <message_id> <attachment_id> <save_path>
  Retire when the runtime arm lands.

## Runtime gap (the work)
rust/src/runtime/web_tool_dispatcher.rs dispatch match handles only
  "web_fetch" => run_web_fetch, "web_search" => run_web_search.
Add: "gmail_attachment" => run_gmail_attachment(attrs), reading
attrs.message_id / attrs.attachment_id / attrs.save_path (same way
run_web_fetch reads attrs.url). Implement the PROVEN recipe :
  1. load ~/.config/miette/google-oauth-token.json (keys: token,
     access_token, refresh_token, client_id, client_secret,
     token_uri, scopes, expiry). Custom Google app.
  2. GET https://gmail.googleapis.com/gmail/v1/users/me/messages/
     {message_id}/attachments/{urlquote(attachment_id)} with
     Authorization: Bearer <token>.
  3. on 401/403 + refresh_token present: POST token_uri with
     grant_type=refresh_token, refresh_token, client_id,
     client_secret -> new access_token ; persist back into the
     token json (key "token") ; retry once.
  4. base64url-decode the JSON `data` field (pad with '==='),
     write bytes to save_path (mkdir -p parent). Result into
     Cascade.RecordResult : {ok, bytes, save_path, filename}.
Mirror web_tool family shape ; consider adding
:perform_gmail_attachment to web_tool.hecksagon behaviors +
a :gmail_oauth provider for parity-cleanliness (judgement: the
binding routes on the tool string, so the family-list addition is
optional polish, not required for function).

## Gating (why it does not auto-fire yet)
Same chain that blocks ALL EmailTool execution (see tools.hecksagon
EmailTool :mcp comment): i594 bluebook-driven kernel-hook
registration + i557 framework_registry auto-walk of
framework/adapter_families/. Until those land, the binding is the
CONTRACT (parses, parity-clean, auto-fires later with no further
bluebook edits) and the transitional script is the working path.

## Closes when
Dispatching Tools::EmailTool.GetAttachment with a real
message_id/attachment_id/save_path writes the decoded bytes to
disk via the runtime arm (no shell script), cascades
AttachmentFetched + Cascade.RecordResult, and the i17/i8
"attachments undownloadable" notes can be struck. Verify against
the Jordan email (thread 19e3c3794fa20715) reproducing the
149278-byte JPEG.

149278 bytes, 1080x1080) for opt-website i17 using this exact
recipe via the custom Google app token. Mechanism is not
speculative.
