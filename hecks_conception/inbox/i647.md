# i647 — Fold restart prompt into WakeReview surface

## Why

Tonight (2026-05-20) we landed a sibling SessionStart hook that writes
`/tmp/restart_prompt_latest.md` and a sibling UserPromptSubmit hook that
injects it as additionalContext. This **closes the gap operationally**
(restart prompts now reach the next session) but **leaks structurally** :

- Two `/tmp/*_latest.md` surfaces instead of one
- Two UserPromptSubmit injections instead of one
- The restart prompt is logically a section of the wake review, not a
  parallel artefact

The wake review is the *one* surface that says "this is who you are and
what the night left." The restart prompt belongs *inside* it.

## The proper fix

`rust/src/run_wake/mod.rs` already has the pattern : `read_consciousness`,
`read_latest_dream`, `render_markdown`, `write_surface`. Add :

  1. **`RestartPromptSnapshot`** struct with `content: String, present: bool`.
  2. **`read_restart_prompt(info_dir)`** — resolves
     `<info_dir>/../inbox/restarts_inbox/latest.md`, parses frontmatter,
     returns content only when `status: open`.
  3. Wire into `run()` between `read_latest_dream` and `render_markdown`.
  4. **Extend `render_markdown` signature** with `restart: Option<&str>`
     and append a section : `\n## Last session left this\n\n{content}\n`
     when present.
  5. **Retire the sibling Python hook** (the one writing
     `/tmp/restart_prompt_latest.md` in `.claude/settings.json`) and the
     **second UserPromptSubmit injection** (the one reading it).
  6. **Add a render test** mirroring the existing pattern in
     `run_wake/mod.rs::tests`.

## Why deferred tonight

Rust rebuild + binary swap + verification round-trip is bigger work than
the 5-minute hook addition that closes the operational gap. Tonight's
fix unblocks the next wake ; this card captures the structural pass.

## Bigger context (i262)

`run_wake/mod.rs` has an antibody-exempt marker noting it retires when
i262 (generator-capability dispatch) lands and the runtime can self-
interpret a chained-policy pipeline directly from the bluebook. The
truly-true fix is to bluebookify the whole WakeReview pipeline as a
domain ; i647 is a stop on the path, not the destination.

## Acceptance

- One `/tmp/wake_review_latest.md` surface, one UserPromptSubmit injection
- Restart prompt appears under a clearly-labelled section in that surface
- The Python sibling SessionStart hook is removed
- `storehouse storehouse route WakeReview.ComposeWakeReview` test covers
  the new section
