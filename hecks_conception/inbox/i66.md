# i66 — runtime-kernel-minimization-via-futamura

runtime-kernel-minimization-via-futamura — Chris's conjecture: most of the Rust runtime can be re-expressed as bluebook, kernel should be VERY small, use Futamura projections. Third-Futamura territory (paper §9.11) applied to runtime, not just specializer. Concrete shape: identify the minimum kernel (argv parsing, file I/O primitives, process spawn, maybe the interpreter for givens/mutations) and push everything else through bluebook-self-interpretation. Every subsystem NOT in minimum set (repository, event_bus, policy_engine, lifecycle, middleware, command_dispatch — F-7 Dispatch family ; server, query, conceiver — everything Phase F declared) becomes bluebook-driven. Rust that remains specializes out via Futamura ; rest is residue. Pairs with i62 delete-dead-rust (deletion is the close of the loop). Load-bearing blocker for: honest closure of i62, i65, i66. Related decision from 2026-04-24: Ruby gems can carry adapter layer (i61 ruby-gems-as-rust-adapters) — honest middle path rather than pure bluebook for I/O.
