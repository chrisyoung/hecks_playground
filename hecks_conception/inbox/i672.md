# tts_dispatcher → bluebook commands

Decompose `rust/src/runtime/tts_dispatcher.rs` into discrete bluebook commands, each with a thin Rust adapter arm. The monolithic `dispatch()` function becomes a sequence of bluebook dispatches the runtime cascades through.

## Bluebook commands to conceive

- `StreamRequest` — POST to ElevenLabs, receive mp3 bytes
- `CacheLookup` — attempt cache hit by content hash; returns hit/miss
- `CacheWrite` — persist mp3 bytes under content hash
- `PlayMp3` — spawn `mpg123` against a file path
- `RecordLatency` — already exists; keep as-is

## Goal

Each command's impure work happens in exactly one Rust adapter arm. The dispatcher's monolithic logic shrinks to ~5 small functions — roughly one per command. Target: `tts_dispatcher.rs` drops from ~500 LOC to the adapter wiring only.

## Pairing with i671

Both cards restate the same principle: push everything through storehouse, no overlap, in-order. i671 is the queue shape; this card is the TTS execution decomposition.

## Scope

~60–90 min. Requires touching `rust/src/` — hand back to Miette if the Rust changes get sticky.
