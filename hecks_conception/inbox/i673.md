# voice.hecksagon thin-wrapper refactor

Migrate voice configuration from `voice.hecksagon` into the `Voice` aggregate in `voice.bluebook`. The hecksagon becomes a thin declaration of adapter kind, name, provider, and trigger — nothing more.

## What moves

Lift these fields from `voice.hecksagon` INTO `Voice` aggregate attributes seeded via `voice.fixtures`:

- `voice_id`
- `model`
- `speed`
- `stability`
- `similarity_boost`
- `style`
- `cache_dir`
- `auto_play`

## What stays in hecksagon

- adapter kind
- adapter name
- provider
- trigger_on

## Runtime change

Update the runtime resolver to read config from Voice aggregate state when the hecksagon options are absent. The hecksagon becomes a literal wrapper: "the `:tts` adapter for Voice reads its config from the Voice aggregate."

## Scope

~45 min. Bluebook + fixture edits. No Rust changes expected unless resolver logic is non-trivial.
