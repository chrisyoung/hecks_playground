# (more coming) marker parser

Teach `speech_stream_advance.py` to recognize the `(more coming)` literal in assistant text as a continuation signal, keeping the current SpeechUnit open until the marker is absent.

## Behavior

1. `discover_transcript()` yields assistant text chunks as they arrive.
2. If a chunk ends with `(more coming)`: strip the marker before dispatch, emit `SpeechQueue.AppendStatement` with `is_continuation: true`, leave the unit open.
3. If a chunk arrives **without** the marker after the next sentence boundary: emit `AppendStatement`, then emit `SpeechQueue.CloseUnit` — drain fires.

## Marker contract

The marker is the assistant's explicit signal: "I have more to say before you should play." Its absence is the close signal. This is a cooperative protocol between the assistant's text generation and the drain policy.

## Dependency

Pairs with i671 (SpeechQueue bluebook). The `AppendStatement` and `CloseUnit` commands must exist before this parser can dispatch them.

## Scope

~20–30 min. Python-only change in `bin/speech_stream_advance.py`. No Rust or bluebook changes.
