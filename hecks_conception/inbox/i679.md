# Voice.Play own adapter family

Split `Voice.Play` (play a pre-rendered mp3 file) from `Voice.Speak` (render + play) by giving each its own adapter family. Today `tts_dispatcher.rs` branches on `attrs["audio_path"]` presence to skip render — a leaky coupling.

## Target architecture

| Command | Adapter family | Runtime arm |
|---|---|---|
| `Voice.Speak` | `:tts` | render via ElevenLabs, then play |
| `Voice.Play` | `:audio_play` | spawn `mpg123` against `audio_path` only |

## Implementation

1. Declare `:audio_play` as a new hecksagon adapter family.
2. Add a runtime arm in Rust that handles `Voice.Play` dispatches by reading `audio_path` from attrs and spawning `mpg123`.
3. Remove the `audio_path` branch from `tts_dispatcher.rs` — it belongs in the new arm.

## Purity goal

Closes the simpler half of i672's decomposition objective: the two execution paths (render vs. play) are no longer entangled in a single monolithic dispatcher.

## Scope

~45 min. Requires touching `rust/src/` — surface to Miette if the Rust arm wiring gets non-trivial.
