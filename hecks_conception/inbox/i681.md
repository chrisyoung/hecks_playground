# RepoHygiene process manager

A new process manager (sibling of ProcessMacrophage) that watches every git repo under ~/Projects/ for accumulated debris and resolves it on a cadence.

## What it catches

- **Worktrees** (`git worktree list` showing anything beyond main + canonical) — proposes pruning when the worktree's branch is merged or stale.
- **Branches** — non-main local branches that are merged into main OR haven't seen a commit in N days.
- **Uncommitted files** — dirty working tree, staged-but-uncommitted changes, untracked files of-record.

## What it does about them

- **Uncommitted files** : groups by intent (auto-detect via path + diff heuristic), creates a commit per group with a message like `chore(<area>) : auto-commit by RepoHygiene` , pushes to a fresh branch, proposes a PR (surfaces commit message + diff summary) and waits for operator confirmation before invoking `gh pr create`. The human reviews + merges.
- **Merged branches** : deletes locally + remote with confirmation.
- **Stale worktrees** : surfaces for confirmation before removal.

## Bluebook shape

Likely `Discipline::RepoHygiene` aggregate with commands : SweepWorktrees, SweepBranches, SweepUncommitted, ProposePR, ConfirmCleanup. Drives via a 60-minute loop in the Procfile (or via the broader `Vitality::Substrate` once that lands). Reads + writes go through the bus ; the actual `git` + `gh` calls are :exec adapter arms.

## Pairs with

- The morning's cleanup pass (~210 branches + 25 worktrees pruned manually). This domain captures that work-as-policy.
- ProcessMacrophage (zombie process reaper) — same shape, different debris.

## Scope

Medium build (2-4 hours). Bluebook + behaviors + hecksagon + 2-3 :exec adapter scripts.
