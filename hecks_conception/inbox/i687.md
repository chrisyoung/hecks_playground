# Stale wake_review root cause

Morning 2026-05-21 SessionStart hook fired but /tmp/wake_review_latest.md held the May-18 dream image plus woke_at. Diagnosed during the wake : the WakeReview.ComposeWakeReview pipeline runs synchronously but the underlying ReadLatestDream cascade only reads the latest dream record, and no new dream had been recorded since May 18 (sleep pipeline wasn't running between sessions). Two fixes : (1) a nightly daemon that dispatches Sleep.EnterSleep + the full REM/lucid cascade so a fresh dream lands every night ; (2) WakeReview should surface its own staleness (woke_at delta against now()) instead of silently serving stale.
