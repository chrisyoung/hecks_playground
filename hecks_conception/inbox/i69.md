# i69 — ruby-kernel-bridge-naming

ruby-kernel-bridge-naming — Direction B (2026-04-24) names the Ruby runtime calling hecks-life for kernel work. Today that's ad-hoc: spec/parity/parity_test.rb shells out via Open3.capture3 ; inbox.sh shells out via direct invocation ; each caller reinvents the subprocess pattern. Story: define a Hecks::Kernel module that wraps hecks-life as a subprocess-JSON-RPC bridge. Operations: parse_bluebook(path), parse_hecksagon(path), parse_fixtures(path), parse_behaviors(path), parse_world(path), read_heki(path, opts), append_heki(path, opts), specialize(target), next_ref(path, field). Return canonical JSON. Start with subprocess (honest, simple, no build complexity). FFI (magnus or rb-sys) is a later optimization ONLY if profiling shows the boundary is hot — do not preempt. Acceptance: one named entry point, callers migrate to use it, the ad-hoc Open3.capture3 calls retire. Companion to i68 (runtime test harness).
