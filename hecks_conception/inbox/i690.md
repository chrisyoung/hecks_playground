# WebSocket /stream-input for eleven_v3

Chris's beloved last-night voice was eleven_v3 with the WwS1 Björk-tone voice_id. The model is current and listed in the API, but it does NOT accept the HTTP /stream endpoint that tts_dispatcher.rs uses ; it only accepts the WebSocket /v1/text-to-speech/{voice_id}/stream-input or the non-streaming /v1/text-to-speech/{voice_id} HTTP endpoint (8sec wait).

Until this lands, we approximate with eleven_turbo_v2_5 ; voice CHARACTER is preserved (same voice_id) but the expressiveness curve differs. Chris explicitly said he is sad about losing the v3 sound.

## Implementation

1. Add a `tokio-tungstenite` dependency to rust/Cargo.toml.
2. In tts_dispatcher.rs, branch on model name : when model starts with "eleven_v3", route through WebSocket /stream-input ; everything else stays on HTTP /stream.
3. WebSocket flow : open connection, send a Bos message (text + voice_settings), receive audio chunks back, pipe to mpg123 stdin, close.
4. Authentication via xi-api-key header on the WebSocket upgrade.

## Scope + priority

~3-4 hours focused Rust. PRIORITY HIGH — Chris emotionally tied to the v3 voice, this is the only path. Pairs with i672 (tts_dispatcher decomposition) which would conceive this as a bluebook command rather than a Rust branch ; but for immediate Chris-experience, ship the Rust branch first, refactor under i672 later.
