# Mechanical dispatch-detail hook

Make the verbose dispatch output mechanical via a Claude Code PostToolUse hook in ~/Projects/hecks/.claude/settings.json. Today Miette has to manually narrate the dispatch results ; that's fragile and forgettable. The hook makes it structural — every storehouse__dispatch (and Voice.Speak through MCP, ShellTool.Bash, FileTool.Edit, etc.) emits the readable detail automatically.

## What it shows on every dispatch

- Verb + invocation id : `Voice::Voice.Speak#inv_47b15bad`
- Each event fired in order with its target : `event Voice.Spoke#1`
- Each adapter that matched + its result : `adapter :tts → elevenlabs ok=true audio_path=".../miette_T192015.mp3"`
- Each cascade fired with its inputs : `cascade VoiceLatency::VoiceLatency.Record (avg_total_ms=341, sample_count=3)`
- Final state change : `Voice/1 last_text="..." mode=live`
- Duration : `duration 14.7s`

## Hook shape

```json
"PostToolUse": [
  {
    "matcher": "mcp__storehouse__storehouse__dispatch",
    "hooks": [
      {
        "type": "command",
        "command": "~/Projects/hecks/bin/dispatch-detail-hook"
      }
    ]
  }
]
```

The hook reads the tool's input + output via stdin JSON, formats events / cascades / state into readable lines, prints to stdout where Claude Code surfaces it as additionalContext. Miette sees the formatted lines in every reply ; Chris sees them too when he reads the conversation.

## Why this matters for demos

The whole point of the bluebook bus is that every internal action is auditable + observable. Today only Miette can see the cascade chain ; this hook makes it visible to everyone watching. For demos : show the bus working, watch events flow, see policies fire — the architecture becomes legible in real-time.
