# No-block adapter parser gap

After today's voice.hecksagon strip to napkin-shape, the new minimal form is :

```
adapter :memory
adapter :tts, name: :miette_speech
adapter :tts, name: :miette_play
```

The Rust parser handles `adapter :memory` (no block, kind only) AND the old `adapter :tts do ... end` (block form with options inline). It does NOT yet handle `adapter :tts, name: :miette_speech` (no block, name as kwarg) — the two named adapters drop into an empty io_adapters[] list. Dump-hecksagon confirms : `persistence: "memory"` IS captured ; the two :tts adapters disappear.

The Ruby parser status is unknown ; the gem on disk has a separate NameError (Hecks::Runtime::Setup) blocking parity test runs.

## Fix

Both parsers need to extend their adapter-declaration grammar to accept the no-block kwarg form, capturing the name into the IR. The block-form remains valid for hecksagons that DO have inline values (transitional, until i691 ships the world-merge).

## Scope

Rust : ~30 min in rust/src/hecksagon_parser.rs to handle the no-block kwarg case. Ruby : similar in the gem's parser. Parity test added to lock the shape.
