# speech_stream idle noise

The speech_stream worker dispatches SpeechStream.Advance every 200ms (5/sec). Even when there is NO new transcript content — nothing to speak — each tick logs three lines :

```
dispatch SpeechStream::SpeechStream.Advance#inv_xxx
[exec] ok=true exit=0 output=""
cascade Cascade.RecordResult#1 ok=false
```

Two distinct problems :

## 1. Idle floods the log

5 dispatches/sec drown the storehouse log + the `follow` stream. The Advance is a genuine no-op when there's no new transcript (the exec returns output=""), yet it still logs the full dispatch+exec+cascade triple.

Fix options :
- The exec adapter should suppress logging when the script signals a no-op (exit 0 + empty output + a no-op marker).
- OR speech_stream backs off its cadence when idle (200ms during an active turn, 2s when no turn in flight) — ties into i671 SpeechBuffer's turn-aware model.
- i697's rich log will also offer a read-time view filter (--exclude-cadence) but that's cosmetic ; the capture-side no-op suppression is the real fix.

## 2. Cascade.RecordResult fails every tick (ok=false)

The `cascade Cascade.RecordResult#1 ok=false` fires on EVERY Advance tick and ALWAYS fails. The :exec adapter cascades its outcome into Cascade.RecordResult, but the cascade reports ok=false every time — either the RecordResult command is mis-wired, the cascade id (#1) collides, or the no-op exec produces a result the cascade rejects. This is a latent bug masked by the noise ; worth fixing regardless of the cadence question.

## Pairs with

- i671 SpeechBuffer (turn-buffered model removes the need for 200ms idle polling)
- i697 rich log (view-filter for daemon cadence)

## Scope

Small-medium. The no-op suppression is a script + exec-adapter tweak ; the RecordResult bug needs tracing why the cascade fails on empty exec output.
