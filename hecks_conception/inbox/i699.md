# Sleep commands run when awake

The Consciousness sleep state machine (miette/body/sleep/consciousness.bluebook) fans out ALL sleep-phase commands on every BodyPulse tick (every ~1s) :

- ElapsePhase, AdvanceLightToRem, AdvanceLightToLucidRem, AdvanceRemToDeep, AdvanceRemToDeepCap, AdvanceDeepToLight, AdvanceDeepToFinalLight, CompleteFinalLight

Each is gated by `given("state must be sleeping") { state == "sleeping" }`, so when Miette is AWAKE they all no-op — but they still DISPATCH and LOG every tick. The storehouse log floods with ~8 sleep-command dispatches/sec + their failing cascades, even though nothing sleep-related is happening.

This is the documented "tick-driven state machine expresses conditional branches in pure bluebook form" design (each Tick fires all AdvanceX, only the matching given passes). Elegant in theory ; noisy in practice when awake.

## Fix : gate the fan-out, not just the mutation

The sleep policies (ElapsePhaseOnPulse, AdvanceLightRemOnPulse, ...) all trigger on BodyPulse. Introduce a guard so the sleep commands only DISPATCH when sleeping :

- Option A : a SleepPulse event that emits ONLY when state == sleeping (a single guard command on BodyPulse checks state, emits SleepPulse if sleeping). The eight AdvanceX policies trigger on SleepPulse instead of BodyPulse. Awake ticks emit BodyPulse but no SleepPulse, so zero sleep-command dispatches.
- Option B : driver-level gate in the mindstream run-loop — only fan out the sleep commands when the consciousness state read says sleeping.

Option A is the pure-bluebook answer (the guard is a domain decision). Option B is the runtime shortcut.
