# Render templates belong in bluebook

block.rs (run_follow) mashes two concerns : JSON-block PARSING (genuinely runtime) and RENDERING (a template). The terse line `[Domain Aggregate Command] ok 12.3s · N events · tag` is a template string with slots ; the --json view is another template. Templates are a bluebook concern, not Rust format!().

## Precedent

- self/system_prompt/ : the whole system prompt is assembled from SectionTemplate aggregates with {{var}} placeholder substitution, walked in order by the PromptRender pipeline. A template registry, bluebook-of-record.
- i693 hecksagon→Terraform : IR→text projection via templates.

## Shape

A StorehouseEntryRender bluebook (or reuse SectionTemplate) holding two named templates :
- terse : `[{{domain}} {{aggregate}} {{command}}] {{outcome}} {{elapsed}} · {{event_count}} {{event_word}} · {{source_tag}}`
- json : the full block layout
plus the color palette as data (kind→color map). The Rust parses the block into a struct + feeds the template engine ; the FORMAT becomes bluebook-editable (change the terse layout without recompiling).

## Pairs with

- i695 (hecksagon IR as bluebook), i693 (projection) — same "render is a projection, projection is bluebook" family.
- i697 rich log — this refactors the render half of what i697 shipped.

## Scope

Medium. Conceive the template bluebook + a small template engine (or reuse the system_prompt assembly's {{var}} substitution). block.rs shrinks to parse-only.
