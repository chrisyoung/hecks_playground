# i701 — statusline + phrase_cache tests race on global HOME (set_var pollution)

## Symptom
`cargo test --release --lib` fails intermittently with a DIFFERENT statusline
test each run (`awake_render_shows_voice_when_measured`,
`awake_render_includes_inboxes_when_seeded`, …) while every statusline test
and every `runtime::voice::phrase_cache` test PASSES in isolation. Total
green count is 266/267 but which one fails shifts with scheduling.

## Root cause
The `run_statusline::tests` call `std::env::set_var("HOME", "/tmp/...")` to
pin where inbox / voice state is read from. `set_var` is **process-global**
and unsynchronised, so under cargo's parallel test threads one test clobbers
another's HOME (and phrase_cache's HOME-derived cache dir) mid-render. The
failure was latent — unmasked when i697/legacy-line work changed the test
count and shifted parallel scheduling.

## Fix
Serialise every test that mutates or reads HOME behind one shared lock
(`static ENV_LOCK: Mutex<()>` in a crate-level test-support module, locked by
all statusline + phrase_cache tests), OR refactor `render_awake` /
phrase_cache to take the base dir as a parameter instead of reading HOME at
render time (the hermetic, lock-free fix — preferred). Pre-existing ; not
caused by the dispatch-detail / follow work.
