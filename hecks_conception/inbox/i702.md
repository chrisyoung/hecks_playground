# i702 — retire stdout breadcrumbs once the MCP wrapper reads events from the rich block

## Context
i697 added the rich i697 dispatch block (storehouse_log::emit_dual) carrying
the full event timeline. The legacy per-event breadcrumbs
(`[ts] dispatch X#id`, `[ts] event …`, `[ts] cascade …`) are now redundant
with the block. As of the legacy-line cleanup they no longer reach the FILE
(storehouse_log::emit_stdout keeps them on stdout only) so `storehouse follow`
is a clean block-only stream.

## What still depends on the stdout breadcrumbs
The MCP wrapper (tooling/storehouse-mcp/src/defs/cli/dispatch.mjs) calls
`parseEvents(stdout)` to build its events[] array — it parses the breadcrumb
lines off stdout. The status_golden smoke also asserts the stdout breadcrumb
format. So the breadcrumbs cannot leave stdout yet.

## The move
Have the MCP wrapper read the events[] from the rich block (or from the
result JSON's events field) instead of parsing stdout breadcrumbs. Once no
consumer parses stdout breadcrumbs, drop the `emit_stdout` calls in the five
storehouse_log surfaces entirely — stdout becomes just the result JSON line,
and the rich block (file) is the single event-timeline source of record.
Then retire `emit_stdout`.
