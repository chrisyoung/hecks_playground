slug: filetool-read-ignores-offset-and-limit
value: 'Tools::FileTool.Read (the `claude_tool:read` adapter behind the storehouse FileTool door) IGNORES both `offset` and `limit` — every call returns from line 1 with a fixed default cap. Repro on rust/src/behaviors_conceiver/generator.rs (1579 lines) : `Read file_path=... offset=1000 limit=3` returns line 1 (`//! Generator for behavioral test suites`) onward, ~200 lines — neither the 1000 skip nor the 3-line cap applied. Verified 2026-06-13. Severity : SILENT — it returns exit=0 with plausible content, so a reader who paginates a large file with offset believes they are seeing later sections when they are re-reading the top. This fooled a conception session into modeling 1200 lines of generator.rs from its doc-comment header until the discrepancy was caught (identical output from two different offsets). Workaround in use : sed -n RANGE via Tools::ShellTool.Bash. Fix : honour offset/limit in the read adapter (the native Claude Code Read tool honours them ; the storehouse FileTool projection drops them), OR if intentionally capped, return a truncation marker + the actual line range read so the caller knows pagination is unavailable. Found while conceiving behaviors_conception.bluebook (conceiver-as-bluebook restart arc).'
