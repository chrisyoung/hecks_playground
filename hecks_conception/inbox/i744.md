# i744 — RelationshipDiscipline macrophage : wire live `::` detection (GATED on upsert-on-identity merge)

**Status:** blocked-on-merge. Conception landed ; live detection deliberately NOT wired.

## What's done (conception)

`RelationshipDiscipline` is conceived as the 18th per-rule macrophage in
`aggregates/discipline/immune_system/macrophage/macrophage.bluebook`
(+ 6 behaviors in `macrophage.behaviors`, all green). It is the spec for the
relationship-grammar surface discipline — the verb carries the boundary, in
English, no `::`. Three checks modeled :

- `codey_double_colon` — `::` in a cross-reference target in `.bluebook` /
  `.hecksagon`. NET-NEW, textually detectable, NOT covered by any validator.
  **This is the only check that needs new live detection.**
- `cross_verb_at_value_object` — already covered by the validator's
  `unknown_aggregate_errors` (caught the driving.bluebook `has_many Dispatch`
  bug). Do NOT duplicate live detection.
- `inside_verb_at_root` — genuine validator gap, but needs a corpus pass
  (is the target a root?) the textual PostToolUse hook can't do. Separate.

## Why detection is GATED (the hard blocker)

A live `::` flag on the current branch would **contradict the
AmbiguousCrossReferenceErrors validator** (shipped this session, commit
`70bb086ec`). That validator's error literally tells authors to qualify with
`Context::Target` *until the from-parser lands* — because on this branch the
English ` from <Context>` form is silently dropped by the parser (verified ;
the `from` parser lives unmerged on the `upsert-on-identity` branch, commit
`52e1ce747`, which sets `reference.domain` via `parse_from_context`). So
flagging `::` now would punish authors for following the validator's own
advice, with no valid path between the two gates.

## The unblock + the work

When `upsert-on-identity` merges into the mainline (so ` from <Context>`
parses and `::` is genuinely retired) :

1. Wire `codey_double_colon` detection into `run_macrophage` in
   `rust/src/main.rs` — when the edited file is `.bluebook` / `.hecksagon`,
   scan relationship-declaration lines for a `::` in the cross-reference
   target ; dispatch `RelationshipDiscipline.Check` -> `RecordViolation` ->
   `Complain`, mirroring the existing per-file lint blocks. (Note : the
   sibling rules like `BidirectionalAssociation` are themselves
   conception-only — `CheckRun` is not dispatched anywhere yet — so wiring
   THIS one live also sets the pattern for wiring the others.)
2. Drop the "(or legacy `<Context>::{}` until the from-parser lands)" clause
   from the AmbiguousCrossReferenceErrors message (`codegen/
   validator_corpus_shape/snippets/ambiguous_cross_reference_errors.rs.frag`)
   — once `from` works, `::` is the thing being flagged, not suggested.
3. (Optional, separate) `inside_verb_at_root` corpus-pass detection.

Until then : the conception stands as the documented end-state ; no live
detection ships.
