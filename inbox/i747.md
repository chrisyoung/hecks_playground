# i747 — DrivingAdapterBuilder has no `driven`, silently swallows a whole block

Found alongside i746 while mapping the effect-port gap for the parser-removal
plan (`~/.claude/plans/fully-plan-the-removal-velvety-chipmunk.md`).

## Where it breaks

`vendor/hecksagain/lib/hecksagain/bluebook/dsl/driving_adapter_builder.rb`
defines `driving` (line 37) but **not `driven`**. Found live in
`examples/pizzas/bluebook/pizzas.hecksagon:101-102,116-124`:

    adapter "Deposit" do
      driven on "Pizzas::Order.OrderPlaced" do |sale|
        dispatch "..."
        success "..."
        failure "..."
      end
    end

The whole `driven on ... do ... end` call — `dispatch` included — falls into
`method_missing` (driving_adapter_builder.rb:63-64) and is silently
swallowed. Same shape as `success`/`failure` no-opping in i746, but a
different code path (`DrivingAdapterBuilder`, not `HecksagonBuilder`), so a
separate fix, not a duplicate of that card.

## Blast radius

Only found in `examples/pizzas/bluebook/pizzas.hecksagon` — Pizzas is not
part of the production `hecks_playground_conception` corpus (confirmed via
`hecksagain-cli catalog hecks_playground_conception` — `Pizzas` is not in its bluebook
list). Not urgent on its own. Likely worth doing alongside i746 since it's
the same conceptual gap (driving-side effect wiring) in a sibling builder —
note the connection there rather than scoping this card independently.
