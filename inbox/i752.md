# i752 -- bin/project_rust silently drops multi-file domain content

## What's wrong

`vendor/hecksagain/bin/project_rust`'s domain-loading step :

    Kernel.load(File.join(domain, "bluebook", "#{File.basename(domain)}.bluebook"))

loads EXACTLY ONE file, named after the directory's own basename. A
domain split across several files (`hecks_playground_conception/aggregates/
framework/agent/bluebook/{agent,auth_identity,role}.bluebook`, all
`HecksPlayground.bluebook "Agent"`) only has its basename-matching file loaded --
the rest are silently never read. No error, no warning, no incomplete-
generation notice. Confirmed directly this session :

    $ ruby bin/project_rust hecks_playground_conception/aggregates/framework/agent
    # generates agent/agent.rs etc. successfully -- but auth_identity.bluebook
    # and role.bluebook's aggregates never existed as far as the generator
    # is concerned.

When the basename doesn't match ANY file at all (conductor/ has claim,
worker, lease, merge_queue, sweeper -- none named conductor.bluebook),
it's at least loud :

    $ ruby bin/project_rust hecks_playground_conception/aggregates/conductor
    bin/project_rust:25:in `load': cannot load such file --
    .../conductor/bluebook/conductor.bluebook (LoadError)

## Why this is the highest priority of the three rust/ gaps

Silent partial generation is worse than a crash -- a crash tells you
something's wrong ; silently generating from 1/3 of a domain's files
looks like success. Anyone running `project_rust` against a real
hecks_playground_conception multi-file domain today gets a confidently-wrong
result with no signal.

## The fix, likely shape

Runtime's own `HecksPlayground.boot` (via `Loader#boot` -> `Ports::Loading.load_
domain`) already handles multi-file domains correctly -- it globs every
`.bluebook` file under the root, not just a basename match (confirmed :
this session's `fix(hecksagain): defer MetaValidator.call...` commit
depends on this glob already working, only the WHEN of validation was
broken, never the WHICH files). `bin/project_rust` should load domains
the SAME way `HecksPlayground.boot` does, rather than reimplementing a narrower,
basename-only convention. Worth checking whether `project_rust` can just
call through the real boot path (`Hecksagain.boot(domain, install_
facade: false)`) instead of its own hand-rolled `Kernel.load` + two
extra port/adapter loads.

## Verification once fixed

Re-run against framework/agent and conductor -- framework/agent's
generated IR should include Role and AuthIdentity aggregates (it
currently doesn't, silently) ; conductor should generate all 5
aggregates (Claim/Worker/Lease/MergeQueue/Sweeper) instead of erroring.
