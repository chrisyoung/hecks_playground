# i754 -- generated Rust: enum-typed field's reflection accessor assumes String

## What's wrong

    error[E0308]
      --> src/generated/agent/agent.rs:176:54
    176 |             "status" => Some(Field::Value(Value::Str(self.status.clone()))),
       |                                           ---------- ^^^^^^^^^^^^^^^^^^^ expected `String`, found `Option<Status>`

Also surfaces earlier in the same build as a second error at the struct
definition site (line 166, `pub status: Option<Status>` -- "expected
&String, found &Option<Status>").

`Agent`'s `status` attribute is `Status`, a value_object using the
one_of LONG form (this session's own migration target, i745/i750) :

    value_object "Status" do
      attribute :value, String
      one_of do
        member value: "active"
        member value: "retired"
      end
    end

This correctly generates a real Rust enum (`pub enum Status { Active,
Retired }`, confirmed working for the SIBLING `Kind` value object in the
same file -- i753's card notes the enum generation itself is CORRECT).
But the generic field-reflection accessor every generated struct also
emits (`fn field(&self, name: &str) -> Option<Field>`, used for
generic/dynamic field access -- JSON serialization, diffing, whatever
consumes it) unconditionally wraps every field's value as `Value::Str`,
assuming every field is (or converts trivially to) a `String`. An
`Option<Status>` enum field doesn't.

## Where to look

`vendor/hecksagain/rust/project/` -- wherever the `field(&self, name)`
match-arm generation lives (likely `domain_generator.rb` or
`fielded.rb`, same neighborhood as i753). The fix needs the reflection
codegen to branch on attribute TYPE the same way the struct-field-type
codegen already correctly does (real enum for a one_of long-form VO) --
probably a `Value::Str(...)` for String-backed fields vs. something
enum-aware (a `Value::Str(self.status.as_ref().map(|s| s.as_str()).
unwrap_or_default())`-shaped fix, or a distinct `Value` variant for
enums entirely — worth checking what `Value`'s own variants already
support before picking an approach).
