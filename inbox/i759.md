# i759 -- TestAutomation domain complete ; lifecycle bug root-caused and fixed

See the original card body below (unchanged) for the discovery narrative.
Resolution: the inline-attribute-block lifecycle form is dead syntax --
never wired to anything. Real keyword is `lifecycle :field, default: "x"
do transition "Cmd" => "y", from: "x" end`, declared once per aggregate,
no separate `value_object` wrapper needed (the field renders as a bare
string, e.g. `"status": "healed"`, not `{"value": "healed"}`).

## Original discovery narrative (unchanged, kept for the record)

New TestAutomation domain conceived (Locator self-healing + MutationRun
fuzzing, sibling aggregates, same domain -- discussed live with Chris).
Found live during verification: `status` never advanced through Heal/Stop
despite matching declared transitions. Investigation traced through
`command_interpreter.rb`'s real `advance_lifecycle` step (gated on
`admissible_transition` finding a match in `aggregate.lifecycle`) to the
DSL layer, where the actual bug was found: `AggregateBuilder#attribute`
never accepts or forwards a block.
