# i760 -- examples/pizzas had 3 chained bugs masking each other, never actually booted live

## Why this was invisible until now

`storehouse__validate` stops at the FIRST error per root. Each of these
three bugs, fixed in isolation, would have looked like "the fix worked"
while the NEXT bug was still sitting there, unexercised, because boot
never got far enough to reach it. This is the exact shape
`hecksagain_runtime/lib/validate_sweep.rb`'s own header comment already
warns about for a DIFFERENT case (combined-corpus boot hiding per-root
defects) -- same failure mode, one level down: a single root's OWN boot
can hide N of its own bugs behind each other just as easily.

## The three, in the order they were found

### 1. Order / Deposit : lifecycle declared as a dead `attribute` block

    attribute :status, OrderStatus, default: "pending" do
      transition "Authorize"    => "authorized"
      ...
    end

`AggregateBuilder#attribute` (aggregate_builder.rb:58) takes no `&block`
parameter -- Ruby silently accepts and discards a block passed to a
method that doesn't declare one. The transitions inside never got
captured into any IR at all. `lifecycle` is a completely separate,
top-level keyword (aggregate_builder.rb:228, `def lifecycle(field,
default:, &block)`), confirmed live via hecksagain's own self-hosted
`grammar/translation.bluebook`. Also: the bare `default: "pending"`
form is wrong for a VO-typed attribute regardless (a VO default fills
its fields) -- but `lifecycle`'s own default is a bare string, so
switching to the real keyword fixes both problems at once and DROPS
the now-unneeded `OrderStatus`/`DepositStatus` value objects entirely
-- the lifecycle field is a plain string, never VO-wrapped.

Fixed: both `attribute ... do transition ... end` blocks replaced with
`lifecycle :status, default: "..." do transition "X" => "y", from:
"..." end` (explicit `from:` added, matching the only confirmed-live
usage pattern).

### 2. Kitchen : `identified_by :name` + two bare VO defaults

`identified_by` (aggregate_builder.rb:187) takes ZERO positional
arguments, only a block -- `identified_by :name` is `ArgumentError:
wrong number of arguments (given 1, expected 0)`. Real form,
confirmed against `drafting`/`conductor`/`Locator`
(all live, validated domains): `identified_by { name.value }`.

Same VO-bare-default bug as #1, on `last_swept_at`/`stale_after_seconds`:
`default: "—"` / `default: 1800` -> `default: { value: "—" }` /
`default: { value: 1800 }`.

### 3. A stale local `heki.adapter` shadowing the vendored complete one

`examples/pizzas/bluebook/heki.adapter` declared only `port
"persistence"` -- missing `field :dir`, which the vendored
`vendor/hecksagain/lib/hecksagain/adapters/driven/heki.adapter` DOES
declare. `Adapters::Folder#load_domain` walks `*.adapter` inside every
domain root via `Kernel.load` IN ADDITION to the globally-loaded
library copy (`load_library`) -- so the local, incomplete redeclaration
of `HecksPlayground.adapter "Heki"` overwrote the correct one. Heki is a generic,
already-global adapter; a per-domain copy was never needed. Deleted the
local file outright rather than patching it to match -- one adapter
declaration, not two that can drift.

## Verified

    storehouse__validate examples/pizzas          -> valid: true
    Pizzas::Pizza.CreatePizza  -> real record, id "Margherita"
    Pizzas::Order.PlaceOrder   -> OrderPlaced, status: "pending"
    Pizzas::Order.Authorize    -> OrderAuthorized, status: "authorized"  (the actual bit-flip -- confirmed real, not just accepted)
