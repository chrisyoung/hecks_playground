   were vestigial, never actually resolved by anything live. Fixed with
   a real `executed_by` bind to a real Ruby adapter
   (`Hecksagain::Adapters::Email`) speaking the Gmail REST API directly

   already used. Needed a second, non-obvious piece : a separate

2. **i755/i758** -- two real bugs in the rust/ projector (a separate,
   independently-compiled per-domain export target, see architectural
   note below), found and fixed via REAL dispatch through the compiled
   binary, not just a clean `cargo build` (which only proves
   type-checking, not semantic correctness -- the actual lesson of this
   part of the session).
3. **i759** -- built a new `TestAutomation` domain live with Chris
   (`Locator` self-healing + `MutationRun` fuzzing, sibling aggregates,
   same domain, never merged). While verifying it end-to-end, found the
   inline `attribute :status, VO, default: {...} do transition ... end`
   lifecycle form is DEAD syntax -- `attribute` never accepts a block,
   Ruby silently drops it. Real form : a separate top-level `lifecycle
   :status, default: "x" do transition "Cmd" => "y", from: "x" end`.
4. **i760** -- the same dead-lifecycle bug turned out to be live in the
   SHIPPED canonical Pizzas example (`examples/pizzas`) -- which had
   NEVER actually booted against the live hecksagain Ruby runtime.
   Fixing it unmasked two more chained bugs behind it (`identified_by
   :name` bare-arg form, a stale local `heki.adapter` shadowing the
   vendored complete one). All three fixed ; verified with a real
   `CreatePizza -> PlaceOrder -> Authorize` dispatch chain, status
   genuinely flips `pending -> authorized`.
5. **i751** -- committing i760's fix hit the pre-commit gate's
   corpus-wide validate, which blocked on an unrelated, pre-existing,
   already-tracked issue (`catalog/Explorer.ByKind`). Chris chose "fix
   it now" over a bypass. Removed the dead query (no real caller
   anywhere, and the field it needed was never populated by any command
   either) -- which unmasked SIX more independent, previously-invisible
   bugs in the same `catalog/` corpus, one validate-cycle at a time :

   literal defaults on named VO-typed attributes across 7 files, a
   typo'd `defaults tab: "editor"` policy verb (real verb is `map`),
   and 2x bare-symbol `identified_by`. `hecks_conception` now validates
   **64/64** -- first time ever, clean.

## Architectural note, locked this session

Chris confirmed explicitly : the live door (`storehouse__dispatch` /
`storehouse__validate` / everything MCP calls) runs on `hecksagain-cli`
-- the **Ruby** hecksagain runtime -- ONLY. The `rust/` projector (the
i750-758 work) is real and independently verified (a bluebook compiles
to a standalone Rust binary with correct dispatch/lifecycle semantics),
but it is a SEPARATE per-domain export target, not wired as the door's
backend, and grepped-confirmed `hecksagain_runtime` has zero shell-outs
to it. "we need to rely just on hecksagain vendoring" -- so don't drift
toward treating the rust/ projector as the live path in future work
unless that decision changes explicitly.
