## Dropped as superseded — the other half of what Chris asked for

- **Ruby-idiom expression methods, Query policy where/for_each, mutation
  ops (remove/multiply/clamp)** — upstream restructured these areas
  independently; re-applying the fork's versions would have been a
  regression, not a fix.
- **`identified_by :field` bare-symbol form** — upstream's current grammar
  requires the explicit form; the fork's block-form / implicit-first-
  attribute fallback is gone by design (ADR 0025).
- **VO `from_json` unknown-key allowlist guard** — the identical fix
  already exists upstream (confirmed byte-for-byte against fork commit
  `8354351`).
- **`Policy with_literals`/`wheres`/`for_each`** (`db253cd`'s third part)
  — upstream's `Bluebook::Policy` is now GENERATED from the language's own
  self-hosted Policy aggregate, and already carries `where`/`for_each`/
  `with_spec` in a materially more mature shape than the fork's hand-rolled
  struct ever had. Nothing to re-apply; re-applying would have replaced a
  better mechanism with a worse one.
- **Query aggregation (count/median/group_by)** — the original recon
  called this "PARTIAL." Re-verified this session: all three already exist
  in current `ReadModelBuilder` (`def count`, `def median(field)`, `def
  group_by(*fields)`). Fully superseded; the recon finding was stale.
- **VO-nesting-in-VO `one_of` refusal** — the original recon called this
  "PARTIAL, a gap." Re-verified this session with a live repro: upstream's
  `AggregateBuilder#value_object` (line ~160) flattens a nested value
  object's own `closed_sets` into the aggregate's `@value_objects` —
  `agg.value_object("Size")` resolves to a real class, not nil. **This is
  better than the fork's own fix**, which only *refused* the nesting with
  a `Malformed` error; upstream actually makes it work. Re-applying the
  fork's version here would have been a straight regression — the
  strongest single piece of evidence this session that squash-and-reapply-
  with-verification, not a blind port, was the right call.

## Real bugs found and fixed en route, not on the original recon list

Boot-testing before committing (a discipline this session had to relearn
once — see below) surfaced six real, live bugs:

1. **`World#for_binding` cross-adapter settings leak** (`1e38638`) —
   generic settings fell back across unrelated adapters bound under the
   same verb.
2. **`Rendering.describe` object-pointer leak** (`d361df5`) — a
   `Runtime::Value` reaching a refusal message printed a raw Ruby object
   pointer instead of its value.
3. **Spurious `success`/`failure` Bind-minting** — `success "..."`/
   `failure "..."` inside a `charged_by(...) do ... end` block landed on
   `HecksagonBuilder#method_missing` and minted TWO garbage binds (verb
   "success"/"failure") instead of writing onto the bind the block opened.
   Verified live before the fix (three binds in the array) and after (one
   correct bind, `on`/`success`/`failure` all populated).
4. **`Ports::Execution.unwrap` raw-kwargs gap** — the fork's own version
   assumed `perform_execution` always receives coerced `Runtime::Value`
   objects; in the current dispatcher it receives the DISPATCH's own raw
   kwargs, so a single-field VO attribute arrived as a plain
   `{ value: "..." }` Hash and got stringified into garbage
   (`"{:value=>\"echo hi\"}"`) instead of unwrapped. Caught immediately by
   the FIRST real boot-test of the newly-wired execution port.
5. **The execution port existed with nothing calling it** — landed as its
   own commit specifically so this gap would be visible and closeable in
   one clean follow-up, rather than shipping a port that silently did
   nothing (the exact class of bug the port was built to kill in the
   first place).
6. **Four DSL-syntax breakages in earlier-copied files** —
   `cloudflare_artifacts.bluebook`, `cloudflare_deploy.bluebook`,
   `miette_phone.bluebook`, `r2_adapter.bluebook` were copied verbatim from
   the fork in units 3/4 without boot-testing, and only surfaced as broken
   once actually exercised during unit 6's work. Fixed in `8c2a0cc`. **This
   was a real process gap this session** — the lesson ("boot-test before
   committing, not after") was internalized and held for every subsequent
   unit (execution port, driven-handler dispatch, behaviors DSL all got
   real boot tests against real fixtures before their commits landed).
