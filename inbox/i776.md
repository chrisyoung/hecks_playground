## What happened this session

1. **Bumped the pin**: `48d2210` -> `933d1dd` (the fork's tip when this
   session started) -> `fe39d44` (one more fork-only fix found
   immediately after bumping -- `AdapterBuilder` never exposed the
   `handler` DSL word despite the Stripe example in the fork's own docs
   using it; `.adapter` files with `handler "..."` raised NoMethodError
   at parse time). Fixed on the fork with a real spec, full fork suite
   still 1602/1602 (`fe39d44` is `hecks-hecksagain`'s current main tip,
   pushed).
2. **`bundle update hecksagain`** -- clean. `storehouse__validate` against
   `hecks_playground_conception` immediately went from 64/64 valid to **1/64** (only
   `spikes/`). The corpus was last written against 48d2210-era DSL and had
   drifted off everything ADR 0025 retired.
3. **Migrated the whole corpus mechanically.** For each retired form:
   wrote a small Ruby script (never sed/perl, per project convention),
   ran it dry-run first, spot-checked the diff, applied, re-ran
   `storehouse__validate`, moved to the next error class surfaced. Forms
   migrated (occurrence counts from the actual sweeps):
   - `aggregate "X", "desc" do` (two-arg) -> `aggregate "X" do` +
     `description "desc"` in-block (225 / 133 files)
   - command-level `description` -> `goal` (830 / 135 files)
   - `identified_by { field.value }` -> `identified_by :field`
     (270 / 124 files)
   - `then_set` -> `sets` (1169 / 123 files)
   - `sets :field, to: :field` (redundant) -> `sets :field` (729 / 111 files)
   - `one_of do member ... end` wrapper -> inline
     `attribute :f, T, one_of: %w[...]` (32 blocks / 18 files) -- plus two
     multi-attribute VOs (Lifespan, EventTrace) that needed the OTHER
     retirement path (bare `member k: v, ...` lines), since the inline
     `one_of:` keyword only works when the VO has exactly one attribute
   - quoted `trigger "X.Y"` -> bare `trigger X::Y` (101 / 41 files) --
     including 13 that carried a stale leading `HecksPlayground::` prefix baked
     into the original string, which had to be stripped (bare constants
     resolve for real, unlike strings, and there is no real `HecksPlayground::`
     namespace to walk)
   - `belongs_to`/`has_many`/`has_one` -> `reference_to` (all three
     collapsed to one relationship primitive)
   - bare-constant `attribute ConstName` and reversed
     `attribute ConstName, as: :name` -> explicit
     `attribute :name, ConstName` (27 + 38)
   - `validation :field, presence: true` (retired AND redundant --
     `optional: false` is already the attribute default) -- removed
   - `role Role, as: Agent` (dynamic role ref, retired) -- unset on the
     2 call sites, matching their own "any Agent kind" intent
   - `value_object`-scoped `description` (never supported there) -> `#`
     comment (29 occurrences, one file)
   - retired policy `with "key", value` calls -> `trigger X, with: {
     key: value }` (127 lines / 4 files)
   - `gate`/`allow`/`adapter :memory` (bare) in two aggregates
     (world/spend's Budget/Call) -> `uses_framework "Governance"` +
     explicit `persisted_by("Memory")` binds, since the domain-side
     `role` already said the same thing and is now real access control
4. **Wired `uses_framework "Governance"` onto ~85 hecksagons.** Chris's
   explicit choice, given via AskUserQuestion (recommended option). Before
   doing this broadly, read `CommandRules::Authorization#refuse_role_
   mismatch` in the fork directly: `governance_attached?` only changes
   behavior for a caller that ALSO binds `actor_id`
   (`Hecksagain.as_caller(role:, actor_id:)`); a caller with no
   actor_id, or a command with no `role` declared, is completely
   unaffected. Confirmed this was a safe, additive change before wiring
   it corpus-wide, not just following the recommendation blind.
5. **Caught and fixed a bug I introduced.** My first has_many/has_one
   retirement pass blindly followed the runtime's own raise message
   ("reference_to Sprint mints the same bare name now") and turned real
   membership lists into scalar `reference_to` -- Board's queued_sprints/
   active_sprints/cards, Epic's sprints/stories, Project's epics, Story's
   dependencies. `storehouse__validate` caught it: "Epic.AddSprint sets
   sprints, which Epic never declares." Root cause: `reference_to` always
   mints a scalar (`AggregateBuilder#reference_to`, confirmed by reading
   the actual method); it's only the correct replacement for
   `has_one`/`belongs_to`, never for `has_many`'s plural case. Fixed all
   sites to `attribute :name, list_of(VO)` + added the local identity-
   string VOs each aggregate needed (a `value_object` is scoped to its
   own aggregate -- confirmed live that cross-aggregate VO reuse does
   NOT resolve, unlike command-scoped bare constants).
6. **Found ~10 more pre-existing, unrelated latent bugs** while migrating
   (not caused by this session, just newly surfaced once validate got
   past earlier blockers):
   - `sets :list_field, append: :bare_symbol` -- `Mutation#appended_fields`
     now unconditionally calls `source.transform_values` (requires a
     Hash); several real call sites across plan.bluebook, gestation.bluebook,
     domain_cell.bluebook, sentence.bluebook, composition.bluebook,
     acl.bluebook, merge_queue.bluebook, applications.bluebook still
     passed a bare `:symbol`. Fixed to `append: { value: :symbol }`
     (one even needed `list_of(String)` promoted to a real
     `list_of(AppType)` VO, since appending a raw scalar has no
     supported spelling anymore).
   - Query block params shadowing their own name in `where()`
     (`query "X" do |agent_id| where(agent_id: agent_id, ...) end`) --
     the RHS `agent_id` was a bare local var evaluating to whatever the
     block got (often nil, since these blocks are `instance_eval`'d with
     no args passed), not a symbol reference into the query's own
     resolved arguments. These were SILENTLY FILTERING ON NIL the whole
     time, not raising -- only surfaced now because a couple of variant
     spellings (mismatched key/value names, or block-param names with no
     matching owner attribute) hit `Literal.render`'s "no pinned literal
     spelling" refusal. Fixed 8 occurrences across agent_inbox.bluebook,
     event_sourcing.bluebook, pizzas.bluebook to `where(field: :param)`;
     two needed an explicit `attribute :param, Type` inside the query
     since `derive_from_owner!` can only infer from a matching-named
     owner attribute.
   - Two real event-shape collisions where multiple commands emit the
     same bare event name with different fields ("an event is one fact"):
     7-way in hecksagon_ir.bluebook (`Conceived`, renamed per-aggregate
     to `HecksagonConceived`/`IoAdapterConceived`/etc.), 2-way in
     extraction.bluebook (`Declared` -> `BlockRuleDeclared`/
     `FieldRuleDeclared`), 4-way in hexagon.bluebook (`Declared` ->
     per-aggregate), 2-way in appeal.bluebook (`CommandExecuted` ->
     `FormSubmitted` on Console.SubmitForm). All checked for consumers
     first (`grep on "EventName"`) -- zero subscribers on every one,
     zero-blast-radius renames.
   - Two `attribute :x, default: "y"` with no TYPE at all (pizzas.bluebook
     `currency`, appeal.bluebook `status_label`) -- added the missing
     type.
   - `.world` file using a dotted `Domain::Aggregate.verb(...)` binding
     form (`web_debug.world`) that `WorldBuilder` genuinely doesn't
     support (confirmed by reading `world_builder.rb`: no `ConstShim.with`

## Governance-wiring risk check (why it was safe to do broadly)

Before wiring `uses_framework "Governance"` onto ~85 hecksagons in one
sweep, read `lib/hecksagain/runtime/command_rules/authorization.rb`
directly (not just trusted the recommendation):

    def refuse_role_mismatch(command, domain)
      caller = Caller.current
      return unless caller
      return if command.role.to_s.empty?
      authorized =
        if caller.actor_id && governance_attached?(domain)
          Ports::Authorization.holds_role?(...)   # <- only this path is new
        else
          caller.role == command.role              # <- everyone else, unchanged
        end
      ...
    end

No caller bound: unchecked (same as always). No role declared: unchecked
(same as always). Caller bound WITHOUT `actor_id`: falls to the string
check (same as always). Only a caller that explicitly opts into identity
(`Hecksagain.as_caller(role:, actor_id:)`) reaches the real
`Governance::RoleAssignment` lookup -- and nothing in this corpus's
current runtime callers passes `actor_id:` yet, confirmed by grep. So
this was a genuinely additive, zero-regression change for every existing
caller.
