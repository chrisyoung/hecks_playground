# i784 — miette pre-push gate: 22 → 2 of 169 failing, CLOSED

*Surfaced while pushing two small miette commits (a body_pulse Procfile
fix + a pre-push hook binary-path fix, both pushed to miette main).
The pre-push gate blocked on 22/169 `.behaviors` files unrelated to
either commit. What started as "investigate before deciding whether to
push past it" became a full root-cause-and-fix arc. This card is the
complete record.*

## Fixed + shipped — 7 PRs, all merged to hecks-hecksagain main

**[#2](https://github.com/chrisyoung/hecks-hecksagain/pull/2) — VO `one_of` validation stringified the whole hash instead of its discriminant.**
`payload_gate.rs` compared the vocabulary against a VO-typed attribute's
whole `Value::Map` rendered via `Display` (`"{N fields}"`) instead of
its discriminant field. Fixed by resolving the VO's first declared
attribute and reading that field out of the map.

**[#3](https://github.com/chrisyoung/hecks-hecksagain/pull/3) — cross-domain policy cascades never fired.**
`behaviors_aggregates_root()` walked up to a sibling
`hecks/hecks_conception/aggregates` — an i117-era heuristic predating
miette's own repo (2026-08-14 cutover). A STALE pre-migration duplicate
of `domain_cell.bluebook`, never deleted from `hecks_conception`,
organ-won over miette's live copy ; the isolation gate deciding whether
to merge `HECKS_ADDITIONAL_CORPUS_ROOTS` checked only "textually inside
hecks". Fixed by recognizing a `*.world`-marked ancestor as a being's
own combined-domain root, and widening the isolation gate.

**[#4](https://github.com/chrisyoung/hecks-hecksagain/pull/4) — `identified_by { name.value }` (274 uses in miette) wasn't recognized as a block.**
Ruby's inline curly-brace block syntax has neither a trailing `" do"`
nor a bare `"do"`, so it fell through to bare-symbol extraction, found
no `':'`, and left `identified_by` unset — every dispatch counter-minted
a fresh record regardless of the name attribute's value. Fixed by
recognizing the single-line curly form and stripping the `.value`
accessor to the actual attrs key.

**[#5](https://github.com/chrisyoung/hecks-hecksagain/pull/5) — sibling of #2 for `list_of(VO)` attributes.**
A `list_of(VO)` attribute arrives as a whole `Value::List` with no
single "sent" value — fixed by judging each element's own discriminant.

**[#6](https://github.com/chrisyoung/hecks-hecksagain/pull/6) — VO-typed defaults written as a hash literal (207 uses) were triple-broken.**
(1) extraction truncated `{ value: "x" }` to its opening `{` ; (2)
`parse_default` had no hash-literal branch, so the field held the
literal string instead of a real Map ; (3) three separate consumers
(lifecycle guard/transition, `given`/`invariant` `==`, the behaviors
runner's field-equality assertion) compared the resulting Map against a
bare scalar via lossy `Display` instead of unwrapping. Fixed all three,
consolidated into one canonical `Value::unwrap_scalar()`.

**[#7](https://github.com/chrisyoung/hecks-hecksagain/pull/7) — #3's `.world`-file check was too broad.**
`*.world` is NOT a repo-root-only marker — the corpus scatters ~126 of
them, one per domain/bluebook (adapter/persistence wiring, same
`Hecks.world "X" do ... end` shape as the real repo-root one). Checking
for ANY `.world` file matched the FIRST one the walk met — often the
`.behaviors` file's own immediate directory — resolving a combined-domain
root scoped to just that one bluebook. Fixed by additionally requiring
a co-located `.git` entry, which only a true repo root has.

**[hecksagain#330](https://github.com/chrisyoung/hecksagain/pull/330) — same-shaped bug as #3, found independently in the Ruby parity gem.**
Doesn't touch the actual gate (that runtime is the Rust
`hecks-hecksagain/storehouse` crate) — fixed on its own merits.

**miette `14c3e1b` — two event-name collisions #7 unmasked, fixed as bluebook qualifier changes** (not a runtime bug — this is what `across`/qualified `on "Aggregate.Event"` exists for):
- `Proprioception.DetectDrift` and catalog's `Mirror.DetectDrift` both
  emitted a bare `"DriftDetected"` (organ-sensing drift vs domain-sync
  drift — unrelated concepts). Qualified both reacting policies.
- `development.bluebook`'s `Development.DevelopDomain` and catalog's
  `Entry.DevelopDomain` both emitted a bare `"DomainDeveloped"` (a whole
  domain finishing development vs a catalog entry bumping its version).
  Qualified all three reacting policies. Also updated
  `conception.behaviors`'s expected-emits list to include
  `CatalogSynced` — a genuine, previously-unreachable part of the
  cascade (`development.bluebook`'s own `SyncOnDevelopment` policy,
  `across "Catalog"`), not a new bug.

All 7 hecks-hecksagain PRs merged with red CI via `--admin` — every
failure checked individually, confirmed pre-existing on `main` (a
Postgres auth misconfig, a pre-existing broken generated-code build)
before merging, never touching the files any of these PRs changed.
`cargo test --release --no-fail-fast` (the `--no-fail-fast` matters —
plain `cargo test` stops at the first failing binary alphabetically and
hides ~20 *other* pre-existing failures past it, confirmed via a
`git stash` control baseline in #6) stayed at an **identical** failure
set across every one of these PRs — zero regressions introduced by any
of them.

**Build/deploy gotchas hit along the way** (folklore now, not bugs):
`cargo build --release` from `hecks-hecksagain/storehouse/` silently
rebuilds only the lib, not the `storehouse-cli` binary — needs
`cargo build --release --workspace`. Installing a fresh binary to
`~/.local/bin/storehouse` via `cp -f` while daemons have the old one
memory-mapped produces `SIGKILL(137)` on every subsequent exec (macOS
invalidates code-signing validation for a vnode overwritten in place) —
fixed by writing to a temp path and `mv`-ing atomically over the
destination.

## Still open — 2 files, both test-authoring issues, not runtime bugs

**`world/infrastructure/bluebook/change_tracker.behaviors`.**
References a `RunBatch` command that has never existed anywhere in the
corpus or git history — created whole-cloth, aspirational, in the
migration commit `c54fba4`. Either implement `RunBatch` or delete/skip
this test.

**`self/memory/bluebook/memory.behaviors`.**
The `StoreMemory` test was accidentally passing against an unrelated,
same-named `Store` aggregate that only ever existed in
`hecks_conception/aggregates/library/stores` — a genuinely foreign
concept. Miette's own `Store` (`body/sleep/consolidation/`) only has
`PromoteSignal`. Now correctly unreachable (a side effect of #3
correctly stopping cross-contamination). Needs retargeting to whatever
miette command it actually meant.
