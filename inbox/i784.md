# i784 — miette pre-push gate: 22 → 4 of 169 failing, 5 clusters fixed across 6 merged PRs

*Surfaced while pushing two small miette commits (a body_pulse Procfile
fix + a pre-push hook binary-path fix, both pushed to miette main as
`e29746b`). The pre-push gate blocked on 22/169 `.behaviors` files
unrelated to either commit. What started as "investigate before
deciding whether to push past it" turned into fixing nearly all of it.
This card is the full record — what shipped, what's left, and why.*

## Fixed + shipped (6 PRs, all merged to hecks-hecksagain main)

**[#2](https://github.com/chrisyoung/hecks-hecksagain/pull/2) — VO `one_of` validation stringified the whole hash instead of its discriminant.**
`payload_gate.rs` compared the vocabulary against `raw.to_string()` for
a VO-typed attribute's whole incoming `Value::Map` — `Value`'s `Display`
renders any map as `"{N fields}"`, never equal to a vocabulary string.
Fixed by resolving the VO's discriminant (first declared attribute) and
reading that field out of the map first.

**[#3](https://github.com/chrisyoung/hecks-hecksagain/pull/3) — the big one: cross-domain policy cascades never fired.**
`behaviors_aggregates_root()` resolved a `.behaviors` file's
combined-domain root by walking up to a sibling
`hecks/hecks_conception/aggregates` — an i117-era heuristic from before
miette became her own repo (2026-08-14 cutover). Two consequences: (a) a
STALE pre-migration duplicate of `world/conception/bluebook/domain_cell.bluebook`,
never deleted from `hecks_conception` (old `sets`/`goal` DSL dialect),
organ-won over miette's own live copy, so the correct cross-domain
policy never got a chance to fire ; (b) the isolation gate deciding
whether to merge in `HECKS_ADDITIONAL_CORPUS_ROOTS` + the framework's
own buckets checked only "is this path textually inside the hecks
repo" — stopped being the only shape of "a being dispatching against
her own conception" once her corpus moved out. Fixed by recognizing
any ancestor directory with a `*.world` file as its own combined-domain
root (checked before the stale fallback), and widening the isolation
gate to also admit a root that IS one of `additional_corpus_roots()`.
Fixed 6 of 7 "cascades through policy chain" failures outright.

**[#4](https://github.com/chrisyoung/hecks-hecksagain/pull/4) — `identified_by { name.value }` (274 uses in miette) wasn't recognized as a block at all.**
Ruby's inline curly-brace block syntax has neither a trailing `" do"`
nor a bare `"do"`, so `ends_with_do_block` never matched it — it fell
through to the bare-symbol `identified_by :name` extraction, found no
`':'`, and silently left `identified_by`/`identity` both unset. With no
`identified_by`, `Repository::id_for_command` counter-minted a fresh
record on *every* dispatch regardless of the name attribute's value —
breaking idempotent-declare, mutex-refusal, and fold/accumulate for
every aggregate using this (very common) form. Fixed by recognizing the
single-line curly form alongside `do...end`, plus stripping a trailing
`.value` accessor so the extracted field name matches what
`id_for_command` actually looks up. Fixed `claim.behaviors`,
`storehouse.behaviors`, `event_sourcing.behaviors`,
`capabilities.behaviors`'s identity-shaped failures outright.

**[#5](https://github.com/chrisyoung/hecks-hecksagain/pull/5) — sibling of #2 for `list_of(VO)` attributes.**
`events: list_of(EventTrace)` arrives as a whole `Value::List`, which
has no single "sent" value of its own to judge — `Value::List`'s
`Display` (`"[N items]"`) can never equal a vocabulary string either.
Fixed by judging each element's own discriminant instead of the list
itself. Fixed both remaining `storehouse_log.behaviors` failures.

**[#6](https://github.com/chrisyoung/hecks-hecksagain/pull/6) — VO-typed defaults written as a hash literal (207 uses) were triple-broken.**
`attribute :state, State, default: { value: "untasked" }` : (1) the
default's own extraction truncated the hash literal to its opening `{`
(a plain whitespace split on `{ value: "x" }` finds `"{"` as the first
token) ; (2) even once captured, `parse_default` had no hash-literal
branch, so the field held the literal STRING
`"{ value: \"untasked\" }"` rather than a real `Value::Map` ; (3) once
the field genuinely held a Map, three separate consumers (a lifecycle
guard/transition, a `given`/`invariant`'s `==`/`!=`, the behaviors
runner's field-equality assertion) compared it against a bare scalar
via `Value`'s own lossy `Display` instead of unwrapping. Fixed all
three, consolidated into one canonical `Value::unwrap_scalar()`.
Fixed `process_health.behaviors` (21/21) and `plan.behaviors` outright
— both were blocked on this exact chain.

**[hecksagain#330](https://github.com/chrisyoung/hecksagain/pull/330) — same-shaped bug as #3, found independently in the Ruby parity gem.**
`policies_for(event, domain)` only looked inside the emitting command's
own bluebook. Doesn't touch the actual gate (that runtime is the Rust
`hecks-hecksagain/storehouse` crate, not this gem) — fixed on its own
merits for whatever consumes the gem as the parity reference.

All 6 hecks-hecksagain PRs merged with red CI via `--admin` — every
failure checked individually and confirmed pre-existing on `main`
before merging (a Postgres auth misconfig, a pre-existing broken
generated-code build, a known-flaky Postgres tenant-isolation test —
none touching the files any of these PRs changed). **Correction/note**:
`cargo test --release` without `--no-fail-fast` stops at the first
failing binary alphabetically (`board_activation_guard_test`), so the
"clean except one pre-existing failure" claim on #2–#5 was accurate for
that one binary but never actually exercised the ~20 *other*
pre-existing failures past it. #6's PR description names this — all
~20 confirmed pre-existing via a `git stash` + control-run baseline
before that PR, not introduced by any of these fixes.

**Build/deploy gotchas hit along the way** (both now folklore, not bugs):
`cargo build --release` from `hecks-hecksagain/storehouse/` silently
rebuilds only the lib, not the `storehouse-cli` binary — needs
`cargo build --release --workspace`. And: installing a fresh binary to
`~/.local/bin/storehouse` via `cp -f` while daemons have the old one
memory-mapped and running produces `SIGKILL(137)` on every subsequent
exec (macOS invalidates code-signing validation for a vnode overwritten
in place) — fixed by writing to a temp path and `mv`-ing atomically
over the destination instead.

## Still open — 4 files, all independently root-caused, none require a runtime fix

**`world/infrastructure/bluebook/change_tracker.behaviors` — stale test, no runtime bug.**
References a `RunBatch` command that has never existed anywhere in the
corpus or git history — created whole-cloth, aspirational, in the
migration commit `c54fba4`. Either implement `RunBatch` or delete/skip
this test.

**`self/memory/bluebook/memory.behaviors` — wrong-target test, not a runtime bug.**
The `StoreMemory` test was accidentally passing against an unrelated,
same-named `Store` aggregate that only ever existed in
`hecks_conception/aggregates/library/stores` — a genuinely foreign
concept. Miette's own `Store` (`body/sleep/consolidation/`) only has
`PromoteSignal`. Now correctly unreachable (a side effect of #3
correctly stopping cross-contamination from `hecks_conception`). The
test needs retargeting to whatever miette command it actually meant.

**`body/organs/bluebook/proprioception.behaviors` and `world/conception/bluebook/conception.behaviors` — the SAME event-name-collision bug, two sightings, genuinely needs a runtime fix.**
`proprioception.behaviors`'s `DetectDrift` cascade and
`conception.behaviors`'s `DevelopDomain` cascade both emit extra,
unexpected events (`DomainDeveloped`, `VersionSnapshotted`,
`IndexRebuilt`, `DomainIndexed`, `CatalogSynced`, …) leaking in from an
unrelated cascade. Only reachable/visible now that #3 stopped
`DomainCell` from being shadowed — not a regression from #3, a
pre-existing bug #3 unmasked. Not yet root-caused to file:line ; likely
an unqualified policy (`on "SomeEvent"` with no `event_qualifier`)
somewhere in the `DomainCell`/conception family reacting to more than
it should. `conception.behaviors` additionally still has ~9 unrelated
attribute-not-set failures, separate from this.
