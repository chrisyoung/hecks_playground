# i786 — category-2 exec->spawned_by pile committed: 60/64 valid, 2 known gaps remain

*Continuation of i776 -> i777 -> i778 -> i779 -> i780 -> i781 -> i782
(2026-08-17/18). Picked up a session that ended with real, verified work
(process_health/macrophage/fibroblast/session/plan/inbox all converted to
`spawned_by`, sweep already at 53->60/64 per i781) sitting uncommitted in
the working tree with no handoff card and no commit. This card closes that
gap.*

## What was found uncommitted, verified, and committed this session

- The `:exec` -> `spawned_by` re-expression (i780's design, i781's proven
  pattern) had been carried out across `macrophage`, `fibroblast`,
  `process_health`, `session`, `plan`, `inbox` -- all now use
  `AggregateName.spawned_by("HandlerName", on: "Event")` with
  `success`/`failure` blocks targeting `Cascade::Cascade.RecordResult`,
  matching the pattern proven E2E in i781.
- `uses_framework "Governance"` wired onto the remaining hecksagons that
  didn't already have it (single-line addition, ~85+ files, continuing
  i776's explicit-choice wiring).
- Retired DSL words (`redirects_native`, `logged:` kwarg) commented out in
  place rather than silently dropped, each with a one-line note on what the
  retired form meant and that there's no current replacement -- documentation
  of intent, not a functional change.
- `Gemfile` pin: `fe39d44` -> `74ea7da`, no longer provisional --
  `feat/spawn-effect-port` merged to the fork's `main` and the branch was
  deleted (matches i781's "PR not yet opened" now being resolved).
- `bin/adapter-host`: carries the 8 bugs i781 found and fixed (storehouse
  binary default, missing dispatch subcommand, `.rows` vs `.state`, Pending
  casing, VO field unwrapping, handler-as-shell-string, the two
  previously-undiscoverable Claim/OutboundEvent + Cascade-FQN bugs).
- New `.adapter` / `.port` files (34, untracked until now): the spawn port
  declarations + named adapters per binding, canonical copies plus the
  local per-aggregate copies the DSL expects.

## Verification before commit

- Full 64-root sweep via `HecksagainRuntime.validate("hecks_playground_conception")`:
  **60/64 valid, 4 invalid** -- all 4 confirmed pre-existing / already-scoped
  (not introduced by this diff):
  - `agent_inbox`, `event_sourcing`: `NoMethodError: undefined method
    'interval'` -- `driving on interval` is unbuilt in the vendored gem,
    confirmed by reading the gem source directly in i781. Cron/interval
    parity fixtures fail the same way.
  - `tools`, `storehouse`: `ArgumentError: wrong number of arguments`,
    traced to bare `adapter :memory` -- dead in the current gem (not a
    persistence shortcut), i782's own unscoped finding. Fixing `:web_tool`
    alone will not make `tools` boot; ~20 more missing binds surface right
    after, per i782.
- Deliberately did NOT touch either gap this session -- both are real
  infrastructure decisions (extend the gem's `DrivenCapture` DSL for
  `interval`; decide what replaces `:memory`), not mechanical migration
  work, and both were already flagged as needing Chris's call before i782.

## What's NOT done

- The two remaining invalid roots (`agent_inbox`/`event_sourcing` on
  `interval`, `tools`/`storehouse` on `:memory`) are unscoped design work,
  same as i782 left them. Not started this session.
- `for_each:` in `driven` blocks (8 sites, i781/i782 thread 1) -- design
  answer already on record (extend `DrivenCapture`, mirror
  `PolicyInterpreter#deliver_for_each`), cost is a fork PR. Not started.
- `run "shell cmd"` inside `driven` blocks (5 sites, i781/i782 thread 2) --

  call. Not started.
- 24 of 28 handler scripts for the spawn adapters are still unwritten (6 are

  `bin/fibroblast_sweep.sh` specifically confirmed missing on disk (i781).
