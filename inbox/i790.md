## 5. The validate/dispatch file-set discrepancy — carried forward whole to i791

`storehouse__validate` sweeps 64 "roots" and loads each independently.
`storehouse__dispatch`/`storehouse__query` (`HecksagainRuntime.dispatch` ->
`stage_flat_corpus`) flatten the WHOLE `aggregates_dir` into one staged
directory and boot it as a single registry. **These two paths load different
file sets.** Specifically, `hecksagons/` sibling folders (as opposed to each
domain's own `bluebook/` dir) appear to be invisible to per-root `validate`
but ARE staged and loaded by a full-corpus `dispatch`.

The files this surfaces share ONE bug shape, a pre-existing corpus authoring
mistake, unrelated to anything in sections 1-4: a `driven on
"Event" do |event| dispatch "Cmd", field: value end` block's `dispatch`
call passing bare kwargs instead of nesting them `with: { field: value }`
(`DrivenCapture#dispatch` takes `with: {}, for_each: nil`, no catch-all), and
in some files referencing `event.field` directly rather than a `"{field}"`
string template. Both are wrong for the same underlying reason: `driven`'s
block runs ONCE at PARSE TIME (`DrivenCapture#instance_eval`) to capture a
static dispatch template — `instance_eval` binds the block's own declared
parameter (`|event|`) to the RECEIVER (the capture object itself), not to
any real event, so `event.anything` is always a category error at that
point ; the real event's fields interpolate later, at actual dispatch time,
via `{field}` tokens (`Dispatcher#interpolate_args`).

The parallel session's `f5557d80b` fixed most of the known instances of
this (~12 sites). One more (`shell_adapter.hecksagon`) got fixed in this
session's reconciliation. What's confirmed STILL open, as of the
reconciled `main`: dispatching through the door surfaces a DIFFERENT,
unrelated `unknown adapter "MainUpToDateCheck"` WiringError — see i791.
