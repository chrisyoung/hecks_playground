# ── (Retired 2026-04-30 — implicit-args form rewritten as explicit) ──
# The drift came from antibody.hecksagon using the implicit-args
# convenience form (`command: "git rev-parse {{ref}}"` with no args).
# Rust silently auto-split ; Ruby's Structure::ShellAdapter validator
# rejected `{{` in the command. Bluebook-first fix : declare argv
# explicitly (`command: "git", args: ["rev-parse", "{{ref}}"]`). Both
# parsers handle the explicit form cleanly ; no Ruby code change ;
# no exemption needed. Pattern : when a parser convenience produces
# parity drift, prefer the bluebook write that needs no convenience.

# ── (Retired 2026-04-30 — block-form shell adapter) ──
# join_adapter_lines now flattens block-form `adapter :shell, ... do
# ... end` into kwargs by translating each indented `key value` line
# into `, key: value` appended to the joined invocation. parse_shell_adapter
# stays unchanged. shell_demo.hecksagon now parses byte-equal.

# ── (Retired 2026-04-30 — multi-line allow continuation) ──
# Rust gate parser now tracks an `in_allow` continuation flag :
# when an `allow :A, :B,` line ends with a comma, subsequent lines
# until `end` are parsed as continuation of the symbol list.
# parse_gate_body.rs.frag updated ; circuit_breaker.hecksagon now
# parses byte-equal between Ruby and Rust.

# ── (Retired 2026-04-28 — i80) ──
# Ruby's `def adapter(kind, name: nil, **opts)` extracted name as a

# IO adapter dump now carries `[name, :foo]` matching Rust. boot.hecksagon
# and shutdown.hecksagon (and capabilities/system_prompt_assembly's
